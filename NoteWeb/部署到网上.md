# 让网站在你关机后也能访问（免费方案）

## 先回答你的问题

**有，而且是免费、长期有效的。** 关键是换一个思路：

> 现在这套是"**你的电脑当服务器**"——电脑一关，服务就断了。
> 要关机也能访问，就得把网站**复制一份到别人的服务器上**。那些服务器 24 小时开着，你的电脑就自由了。

这个操作叫"**静态托管**"：把网站打包成普通网页文件，传到免费平台上。你的笔记站正好是纯静态的（没有数据库、不需要后台程序），**完全可以这么干**，一分钱不花。

**唯一的代价**：平台保存的是你上传那一刻的快照。以后改了笔记，网上不会自动跟着变，需要重新发布一次。

不过下面**方案一**会把这一步也自动化掉——你只要把改动 `push` 上去，剩下的平台自己做完。

---

## 三种方案对比

| 方案 | 费用 | 网址形式 | 改了笔记之后 | 适合 |
|---|---|---|---|---|
| **一、GitHub Pages**（推荐） | 免费 | `https://用户名.github.io/仓库名/` | **push 一下就自动更新**，不用手动上传 | 想长期用、愿意花 5 分钟学一次 |
| **二、Netlify Drop** | 免费 | `https://xxx.netlify.app` | 重新把文件夹拖一次（10 秒） | 想立刻看到效果、不想注册 |
| **三、Cloudflare Pages** | 免费 | `https://项目名.pages.dev` | 拖一次，或接 GitHub 自动更新 | 国内访问速度通常更好 |

三个都用得上，**可以同时用**。建议：先花 30 秒试**方案二**立刻拿到网址，再按**方案一**配好长期自动更新。

> 免费额度够用吗？够。笔记站总共不到 1 MB，22 篇全是文字。
> GitHub Pages 给 1 GB 存储 + 每月 100 GB 流量，Netlify 给每月 100 GB 流量，
> 一个班的人天天看也用不掉。

## 方案一：GitHub Pages + 自动更新（推荐）

我已经把自动发布流程写好了，放在 `.github/workflows/deploy.yml`。
你只需要做一次配置，以后**每次改完笔记 push 一下**，网站自己就更新了。

### 准备工作：装 Git 并登录 GitHub

**第 1 步**：装 Git（已经装过了就跳过）

检查一下：

```powershell
git --version
```

如果提示找不到命令，去 https://git-scm.com/download/win 下载安装，装完**重新打开** PowerShell。

**第 2 步**：注册 GitHub 账号

打开 https://github.com/signup ，用邮箱注册（免费）。记住你的**用户名**，网址里要用。

**第 3 步**：配置 Git 身份（只做一次，用户名邮箱随便填你注册的）

```powershell
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
```

### 第一次发布

**第 4 步**：在 GitHub 上新建仓库

1. 打开 https://github.com/new
2. **Repository name** 填 `my-notes`（必须用英文/数字，别用中文）
3. 选 **Public**（公开。免费账号的 Pages 只能用公开仓库）
4. **不要**勾选 "Add a README file" —— 保持完全空白
5. 点 **Create repository**

**第 5 步**：把项目传上去

打开 PowerShell，逐段复制执行（**把 `你的用户名` 换成你的 GitHub 用户名**）：

```powershell
cd D:\录音中转站\整理部署\NoteWeb

git init
git add -A
git commit -m "第一次发布：课堂笔记网站"
git branch -M main
git remote add origin https://github.com/你的用户名/my-notes.git
git push -u origin main
```

第一次 push 会弹出登录窗口，选择 **Sign in with your browser**，在浏览器里点授权即可。

> 如果弹出的是要用户名密码的框，密码处**要填 Personal Access Token**，不是账号密码。
> 遇到这种情况，改用浏览器授权最省事：先把上面最后一行换成
> `git remote set-url origin https://github.com/你的用户名/my-notes.git`，
> 再重新 `git push -u origin main`，让它弹出浏览器登录窗口。

**第 6 步**：打开 Pages 功能（**关键的一步，不做的话网址是 404**）

1. 进入你刚建好的仓库页面
2. 点 **Settings**（设置）→ 左侧栏找 **Pages**
3. **Build and deployment** 下的 **Source** 改成 **GitHub Actions**
4. 保存

**第 7 步**：等 1～2 分钟，看发布结果

1. 仓库页面顶部点 **Actions** 标签
2. 会看到一个叫「发布笔记网站」的任务在跑（黄色圆点在转）
3. 变成**绿色对勾**就成功了
4. 回到 **Settings → Pages**，顶部会显示你的网址：

```
https://你的用户名.github.io/my-notes/
```

这个网址**永久有效**，你的电脑关不关机都无所谓，手机流量也能打开。

### 以后改笔记怎么更新

改完「已总结稿.md」里的内容后：

```powershell
cd D:\录音中转站\整理部署\NoteWeb
git add -A
git commit -m "更新笔记"
git push
```

然后就**不用管了**。GitHub 会自己重新打包并发布，1 分钟左右网上就是最新的。

> 不想记这些命令也行 —— 在仓库页面点 **Add file → Upload files**，
> 把改好的 md 文件拖进去提交，同样会触发自动更新。

### 顺手存个备份

因为整套笔记现在也在 GitHub 上（`notes/` 目录），等于**免费多了一份云备份**。
哪天电脑坏了，`git clone` 一下就全回来了。

## 方案二：Netlify Drop（最快，30 秒）

完全不用注册、不用命令行，适合立刻想看效果。

**第 1 步**：先打包

> 最省事：双击 `D:\录音中转站\整理部署\NoteWeb\_打包网站.bat`（同步 + 打包 + 自检，跑完自动打开 `dist`）。
> 想自己敲命令就这样写（本工作区自带 Node，不用另装）：

```powershell
cd D:\录音中转站\整理部署\NoteWeb
& "D:\录音中转站\运行环境\nodejs\node.exe" "D:\录音中转站\运行环境\nodejs\node_modules\npm\bin\npm-cli.js" run build
```

**第 2 步**：本地先确认打包结果没问题

```powershell
npm run preview
```

浏览器打开 http://localhost:5174 ，每一页都点一遍确认正常，然后关掉预览窗口。

**第 3 步**：上传

1. 浏览器打开 https://app.netlify.com/drop
2. 打开文件资源管理器，进入 `D:\录音中转站\整理部署\NoteWeb`
3. 把 **`dist` 这个文件夹**直接**拖进网页中间**（拖文件夹本身，不是拖里面的文件）
4. 等十几秒，页面上出现网址，形如 `https://charming-panda-123456.netlify.app`

这就是永久网址了，可以直接发给别人。

**第 4 步（可选，建议做）**：注册账号，让网址好记、以后能改

1. 页面上点 **Claim your site**，用邮箱注册（免费）
2. 进入站点设置 → **Change site name**，改成比如 `my-notes-2026`
3. 网址就变成 `https://my-notes-2026.netlify.app`

**以后更新**：重新 `npm run build`，再把 `dist` 文件夹拖进 https://app.netlify.com/drop 覆盖一次。登录状态下会问你是不是要更新已有站点，选更新即可。

## 方案三：Cloudflare Pages（国内速度通常更好）

**第 1 步**：打包（同方案二）

```powershell
cd D:\录音中转站\整理部署\NoteWeb
npm run build
```

**第 2 步**：上传

1. 打开 https://dash.cloudflare.com/ 注册或登录
2. 左侧栏 **Workers & Pages** → **Create** → 选 **Pages** → **Upload assets**
3. 项目名填 `my-notes`（英文小写）
4. 把 `dist` 文件夹**里面的内容**拖进去上传
   （注意：这里拖的是 `dist` 里的**文件**，不是 `dist` 文件夹本身）
5. 点 **Deploy site**，等几十秒

网址是 `https://my-notes.pages.dev`，永久有效。

**以后更新**：进项目 → **Create new deployment** → 重新拖一次 `dist` 里的内容。

## 常见疑问

**Q：这三个能同时用吗？会冲突吗？**
能，互不影响。同一份 `dist` 可以发到三个平台，甚至只发到其中一个。

**Q：网址太长了，能换成自己的域名吗？**
可以，但要花钱买域名（.com 大约 ￥60～80/年）。免费用户只能用平台给的二级域名。对课堂笔记来说没必要。

**Q：能设置密码，只让同学看吗？**
免费方案一般不支持给静态站加密码。如果确实需要，只能：① 网址不公开、只发给特定的人（靠"猜不到网址"来保护）；② 自己算好哪些内容不适合公开，别放上去。

**Q：别人能通过 GitHub 搜索到我的笔记吗？**
能。**Public 仓库任何人都能看到源码**。发布前请确认笔记里没有：
- 你自己的真实姓名、学号、手机号、宿舍号
- 老师或同学的个人信息
- 任何账号密码
- 课件、试卷等有版权风险的材料

（你现在的 22 篇笔记我检查过：里面提到的"学号/姓名"都是操作指引里的字眼，没有真实个人信息；也没有手机号、邮箱、密码。所以现在是安全的。）

如果不希望别人搜到，用方案二或方案三（它们不需要公开源码，只上传打包好的网页文件）。

**Q：能只用 GitHub Pages，但仓库设为 Private 吗？**
不行，免费账号的 Pages 只能发布公开仓库的内容。要私有仓库 + Pages 得升级付费。

**Q：电脑关机、断网，网站还在吗？**
在。网站内容存在平台的服务器上，跟你电脑没关系了。

**Q：那我还需要 `npm start` 那个本地服务器吗？**
需要，但用途变了：**写笔记的时候本地预览用**（改完立刻看到效果，比上传快得多）。
发布到网上只是"把成果公开出去"这一步。

**Q：改了笔记忘了发布怎么办？**
网上不会变，但本地一切正常。下次 `npm run sync` + push（方案一）或重新拖 `dist`（方案二/三）就行。

## 出问题了？

| 现象 | 解决 |
|---|---|
| GitHub Actions 变红叉 | 进 Actions 看日志。最常见是第 6 步没做（Source 没选 GitHub Actions），去 Settings → Pages 补上 |
| `git push` 报认证失败 | 改用浏览器授权登录（见方案一第 5 步的提示） |
| 网址打开是 404 | ① Pages 的 Source 没设成 GitHub Actions；② 刚发布要等 1～2 分钟；③ 网址结尾的斜杠别漏 |
| 页面样式全没了 | 说明传错了目录。要传的是 `dist` 里的内容，里面应该有 `index.html`、`css/`、`js/`、`n/` 这些 |
| 改完笔记网上没变 | 方案一：确认 `git push` 成功了、Actions 跑绿了；方案二/三：重新打包上传了吗 |
| 想删掉重来 | GitHub：仓库 Settings → 最下面 Delete this repository；Netlify/Cloudflare：站点设置里 Delete site |
