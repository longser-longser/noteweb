## 二、从一个生活问题引入：程序关不掉怎么办

### 2.1 老师描述的场景

> **"我们经常遇到一些问题——我在用着用着我的计算机，某个程序关也关不掉。"**
> **"你（在任务栏里）点关闭也好，都没有反应，你也打不了（字）。"**
> **"那这个时候你咋办？"**

### 2.2 Windows 下：任务管理器

**打开方式**：任务管理器（`Ctrl + Alt + Del` 或右键任务栏）。

**在里面能看到什么**：

| 能看到 | 说明 |
|---|---|
| **后台运行的程序** | 一下子运行了很多，**有些东西我们根本没用过**（老师举例：某些输入法程序、远程登录的、百度网盘之类的） |
| **占用情况** | **CPU、内存、硬盘、GPU** 各占了多少，**"这里边占了不少"** |
| **启动项** | 里面**启动了很多**（开机自启项），老师说他**一个一个关掉**——"这些都是没用的" |
| **服务** | 服务也**开了几十个** |

**可以做两件事**：

1. **结束任务**——把正在跑的进程结束掉；
2. **（在"启动"里）禁用**——不让它开机自动起。

### 2.3 一句结论（老师反复强调）

> **"我们的机器为什么慢？原因就是它们运行了太多的没用的东西。"**
> **"你把它关了，那它就释放了我的内存，CPU 占用率就会变（低）。"**

### 2.4 Linux 桌面下：系统监视器

- 老师先试了**设置**、**工具**，**里面都没有进程相关的东西**（只有硬盘分析、使用情况）；
- 要找的地方叫 **【系统监视器】**——"系统监视器在这儿"；
- 打开后可以看到：**也是运行了很多很多的进程**，**"这是我们所有的进程，都是在运行的"**。

> ⚠️ 补充提醒（老师现场说的）：**"有些（进程）是不能结束的。"**

## 三、怎么查看进程（重点）

老师把"查看进程"总结为**两种途径**：

| 途径 | 位置 / 命令 |
|---|---|
| **途径一：图形界面** | 桌面里的**【系统监视器】** |
| **途径二：命令行** | **`ps`** 命令 |

### 3.1 `ps`：静态查看进程

**先看它有哪些参数**：

```bash
ps --help
```

> 老师原话：**"我们来看一下，后边可以跟很多（参数）……要详细啊，这里面它就会详细地显示出来。"**

**`ps` 输出里各列的含义**（老师带着逐列看）：

| 列 | 含义 | 老师现场看到的现象 |
|---|---|---|
| **PID** | **进程的编号**（进程的 ID 地址） | 也叫"进程号"；数字**很大**（如 3342），**不是从 1 开始连续排的** |
| **TTY** | 该进程**与哪个终端关联** | 显示为**问号 `?`** ——表示它**不与终端关联**（后台/系统进程） |
| **USER / UID** | 这个进程**属于哪个用户** | 这里边**一般都是系统**（system） |
| **时间** | 什么时间启动的 | |
| **CMD / COMMAND** | **命令的名称**——到底是哪个命令 | 比如你刚才敲的命令会在这里显示出来 |
| **（资源）** | **CPU 占用多少、内存占了多少** | 用 `ps` 的"详细"形式可以看到 |

**两种常用查法**：

| 写法 | 作用 |
|---|---|
| **`ps`（不带参数）** | 只显示**当前这个终端**里你自己启动的进程，**很少** |
| **`ps -u 用户名`** | 显示**某个用户**启动了哪些程序、使用了哪些命令（老师原话："杠 u 就是说我（这个）用户启动了哪些"） |
| **`ps`（加参数查看全部）** | 显示**所有**进程（系统进程 + 你自己的进程） |

> 老师原话：**"系统进程外，我的用户也执行了一些……启动我这个用户又调用了哪些程序、使用了哪些命令，在这里边也是显示得清清楚楚。"**

### 3.2 ⚠️ 同名进程有很多个，靠 PID 分辨

这是老师专门停下来强调的一点：

> **"你还会发现，里面同一个名称的（进程）有好多个。"**
> **"像谷歌（Chrome）这个进程，我打开，一共是十七个，它的名称都一样。"**

**那怎么分辨？**

| 方法 | 说明 |
|---|---|
| **看详细信息** | 在**详细信息**那一栏里，每一个同名进程后面都跟了一个**不同的 PID** |
| **结论** | **同样都是这一个名字，但是它的 PID 地址是不一样的** —— **靠 PID 分辨** |

> **记住这条**：**名字相同 ≠ 同一个进程；PID 相同才是同一个进程。**

### 3.3 `pstree`：查看进程的"父子/关联关系"

> 老师原话：**"我们有一个命令叫……（打开以后）往上拉，就会看到我们所有的（进程）。"**

**它和 `ps` 的区别**：

| 对比 | `ps` | **`pstree`（进程树）** |
|---|---|---|
| 显示形式 | **平铺**、**不分级**（"你刚才（看的）是不分级的"） | **分级（树状）**，一级、二级、三级展开 |
| 重点 | 进程各自的属性 | **进程之间的关联关系（谁是谁的父进程）** |

**老师讲的结构要点**：

- **所有进程都挂在一个"祖师爷"底下**——老师提到 **CentOS 7 以后改版**，系统启动时的第一个进程变了，这个 1 号进程就是 **`systemd`**；
- 在它下面再分：**系统进程、应用进程**，还有**硬件、软件各方面**的进程；
- 还能看到**二级、三级**的子进程——"在分级，你看它下边（还有）"。

**用途**：

> 老师原话：**"我们就会看到，我们就看到的所有的关联关系在这里边。"**

### 3.4 （实时）动态查看进程：`top`

除了"看一眼就结束"的 `ps`，还有一个**会自己动**的命令：

| 特征 | 说明 |
|---|---|
| **界面一直在刷新** | 老师原话："我们看（进程）它会在动，一直是动态的（在）跳" |
| **显示的内容** | **PID、用户、（命令）**，还有 **CPU 占用率**等，**有的（行）一直在变，有的不变** |
| **退出** | 在这个界面里**按 `q` 键退出** |

**为什么要用它**：

> 老师原话：**"那我们在使用过程当中……特别是因为服务器当中，你要时时监视我们服务器的动态，那你就可以从这个进程（界面）当中去监视。"**

## 四、怎么结束进程（重点）

### 4.1 前提：必须先知道 PID

> 老师原话：**"我们要结束进程，我们得知道这个进程的 ID 号。"**
> **"首先我们要知道怎么来知道（这个）PID。"**

**老师的例子（贯穿整段）**：结束 **`sshd`** 这个进程。

> **`sshd` 是干什么的**：老师原话——**"远程（连接）用的这个服务。你要是通过远程连接到这个服务，如果 `sshd` 这个服务不启动（就连接不上）。"**
> **"那比如说我现在就要把这个进程关掉，我让你远程的机器连不了我（的机器）。"**

### 4.2 `kill`：按 PID 结束进程

**用法**：

```bash
kill 进程的PID
```

**查它的用法**：

- **`kill -l`** —— **列出所有的信号**（老师原话："杠 l 是显示所有的"）；
- **`kill -s`** —— **指定用哪个信号**（后面跟信号名/信号编号）；
- **`kill -9 PID`** —— **直接强制杀掉**（老师演示的"第二种方式"）。

**⚠️ 一个特别容易被忽略的点：PID 会变！**

老师现场做了这个演示：

1. 查到 `sshd` 的 PID（**127**）；
2. 用 `kill` 把它结束掉；
3. 重新启动 `sshd`（或重新登录）后**再查**——**PID 变成了 3800**。

> **结论（老师原话）**：**"就是我们所有的进程，在重新启动之间，这个 PID 地址是会变的。"**
> **"并不是说一成不变——你只要（结束）再启动，这个 PID 是一直在变。"**

> **记住这条**：**每次启动进程，PID 都不一样**。所以**每次结束进程前，都要重新查一遍 PID**，不能记死。

### 4.3 ⚠️ 别把自己的"壳"杀掉

老师演示时**故意踩了这个坑**：

> 他执行了 `pid`、`bash` 一类的命令，**把当前正在和内核交互的 `bash` 进程给结束了**——
> 结果：**"我把（与内核）交互的（程序）直接关了——那你现在（这个会话就）没有了，我还要再重新登录。"**

**教训**：

- **你现在敲命令的这个 `bash`（shell），本身就是个进程**；
- **把它杀了，你和系统的交互就断了**，必须重新登录；
- 所以杀进程之前一定要**看清楚 PID 对应的是哪个进程**。

### 4.4 `killall`：一次结束所有同名进程

**为什么需要它**——老师举了网站的例子：

> **"比如说我们的（Web）服务，也就说我们的网站——你做好网站了，你要想启动网站，这个服务当中（会）启动很多个（进程）。"**
> **"这个程序……它必须要（启动）好几个，你要（结束）这种（进程），你（只）结束一个不行，结束不干净。"**

> **"我要想把它（全部）结束，把关联的进程（一起）结束——你看在 Windows 当中，你结束不了，（但）在（Linux）这（边）可以。"**

**解决办法**：

```bash
killall 进程名
```

> 老师原话：**"注意啊，这个命令就是你结束掉所有的关于（某个名字）的（进程）。"**
> 举例：**`killall sshd`** —— 把所有叫 `sshd` 的进程**全部**结束。

**效果**：结束以后，**和它相关联的（子）进程也全都关了**；再去看进程数——**"你会发现是不是少了很多呀？"**

### 4.5 ⚠️ 有些进程是绝对不能杀的

> 老师原话：**"有些进程是不能关的——系统进程好多都是系统进程，你关了以后，（系统）就不能继续运行了。"**

**所以**：

- **杀之前先看清楚这是什么进程**；
- **系统进程（尤其是那个"祖师爷"进程）不能动**。

### 4.6 顺便讲清楚：为什么服务器不装桌面

老师用**进程数**对比来说明：

> **"就是为什么我们的服务器不用（装）桌面（的原因）——因为你只要启动桌面，你要浪费了很多的（资源）。"**
> **"你看你这没有桌面、（只有）文本的情况下，进程（少）太多了，是不是？"**

**结论**：

| 环境 | 进程数量 |
|---|---|
| **带桌面的 Linux** | **非常多**（桌面本身要起一大堆进程） |
| **纯文本界面的服务器** | **少很多**（"你刚才那个显示（的进程数）就（少）很多"） |

> **所以**：**服务器为了节省资源，一般不装桌面**；也正因为没有桌面，**管理服务器只能靠命令**（呼应第一节）。

### 4.7 怎么判断某个进程到底在不在运行

**方法**：用 `ps` 去查有没有这个名字的进程（配合 `grep` 按进程名过滤）。

**老师的例子**：

> **"比如说我们要查看一下（有没有）一个叫 `httpd` 的——是（跑）网站的。而且我现在网站没有装，这里面是没有启动的。"**
> 结果：**查不到** —— 那就说明**这个进程没有运行**。

> 老师原话：**"你也可以通过这种方式来看你这个进程是否在运行。"**
> —— **查得到，就说明它正在运行；查不到，就说明它没运行。**

## 五、`echo`：把内容输出到屏幕上

> 老师先联系了程序设计课：**"在小程序当中，我们实际上学过……（就是）输出。"**

### 5.1 它是干什么的

> 老师原话：**"它的作用主要是把我们的内容输出到屏幕上。"**

### 5.2 为什么要有它：不想开编辑器

- 老师原话：**"（写文件用）我们需要用编辑器。"**
- **"但是（内容）还比较简单，我不想使用编辑器"** ——
- **"那我们这个（命令）还有这个功能：我这个命令（可以）向某个文件当中写东西，或者说增加（追加）东西，都行。"**

| 用途 | 说明 |
|---|---|
| **输出到屏幕** | 把内容**显示在终端上** |
| **写入文件** | **把内容写进某个文件** |
| **追加内容** | 在**已有文件后面增加**内容 |

> **⚠️ 老师明确说**：把内容**写入文件和追加内容**这两块**"在后面来讲，我（后面）遇到了再讲"**。本次只讲了**输出到屏幕**。

### 5.3 ⚠️ 重点：单引号、双引号、不加引号，效果不一样

老师用**好几个例子**对比，得出了**三种情况**：

| 情况 | 内容特点 | 引号怎么用 |
|---|---|---|
| **① 普通内容** | 就是一段普通文字 | **可以不加引号** |
| **② 含特殊符号** | 内容里有 `$` 这类**有特殊含义**的符号 | **加单引号、加双引号、不加引号，三种结果各不相同** |
| **③ 特殊内容** | 比如带空格等 | **必须用双引号**才行 |

**老师举的典型例子**：

> **"有些时候我们要想输出（原本的）值，比如说我就想（看到）那个（`$`）符号本身——那你就只能用单引号。"**
> **"你用双引号不行，你用不加引号也不行。"**
> **"它出来的不是你想要的东西，而是一个数值。"**

**怎么理解**：

- 不加引号 / 加双引号时，`$` 会被**当成变量**，先被"算"出来（老师原话：**"先计算的嘛"**），输出的是**它的值**；
- 只有**单引号**是"原样照抄"，`$` 才会**原样输出**。

> 老师小结原话：**"他有普通的，你可以不加（引号）；有特殊的，你加（的）引号——单引号、双引号、不加引号，效果出来不一样；还有（另一种）特殊的，你必须用双引号。"**

## 六、变量

### 6.1 定义变量

> 老师原话：**"我们可以直接定义一些变量……定义变量是什么呀？我们在程序当中就是**`什么什么 = 什么什么`**，对吧？"**

**写法**（和程序设计课一致）：

```bash
变量名=值
```

老师现场举例定义了一个 `a1` 之类的变量。

### 6.2 调用（显示）变量

- **调用变量的写法**：`$变量名`（在变量名前加 `$`）；
- 老师原话：**"怎么来调变量……你看显示出来的内容，在终端上显示的内容就是什么呀？——变量值。"**

**⚠️ 变量不存在的时候**：

> 老师现场演示：**"那我能找到吗？找不到，肯定找不到——那在这里边它就显示是空的。"**

> **记住**：**调用一个不存在的变量，什么也不显示（空），不会报错。**

### 6.3 ⚠️ 重点：Linux **严格区分大小写**

老师专门停下来强调：

> **"同学们一定要注意——大写字母、小写字母是两个完全不同的东西。"**

| 系统 | 是否区分大小写 |
|---|---|
| **Windows** | **不区分**（"基本上在 Windows 下，它不区分大小写"） |
| **Linux** | **严格区分**——"你大写就是大写，小写就是小写，它两个不是一个东西" |

> **所以**：定义变量叫 `v2`（大写）和 `v2`（小写）是**两个变量**；命令、文件名、用户名同理。**这一条是 Linux 和 Windows 最根本的区别之一。**

### 6.4 ⚠️ 重点：局部变量与全局变量

> 老师原话：**"我们这些变量也可以分为全局变量和局部变量。"**

**局部变量（默认）**：

> **"就是我们刚才用的这些，它都是属于局部变量——我只要一换位置，它就调不来了。"**

**全局变量**：**在哪个位置都能调到。**

#### 老师的"班级"类比（很好记，建议记住）

| 类比中的东西 | 对应到变量 |
|---|---|
| **班级（比如"二班"）** | 一个**局部区域**（一个 shell） |
| **只在二班的花名册上** | **局部变量**——"你在哪个区域定义的（变量），你这个变量就属于这个区域" |
| **人工智能学院的"大名单"** | **全局变量**——"我直接去人工智能学院找你能找到吗？诶，能找到，这个大名单当中肯定能找到" |

> 老师原话：**"但是我要去（另一个班）找你能找到吗？（找不到）"**
> **"但是我直接去人工智能学院找，能找到吗？诶，能找到。"**

**所以**：

- **在二班（局部）定义的名字，去（别的班）找不到**；
- **登记到学院大名单（全局）上的名字，在哪儿都能找到。**

#### 演示结果

| 变量状态 | 换一个位置（再开一个 shell / 换个目录）后调用 |
|---|---|
| **局部变量** | **调不到**——"它就显示是空的，找不到" |
| **（升级为）全局变量** | **没问题**——"不管它在哪个区域，它都能调过来" |

### 6.5 怎么把变量"升级"成全局变量

> 老师原话：**"比如说我要把 `v1` 升级成全局变量。"**
> **"把它定义成为全局变量，那你在哪个地方都能找到我。"**

**演示**：把 `v1`、`v2` **全部升级为全局变量**之后——

> **"你看，没问题——你就再换（位置）它还没问题，因为我把 `v1`、`v2` 全部都升级为了全局变量，这就不管它在哪个区域，它都能调过来。"**

**要点**：

- **默认定义的变量是局部的**，**只有"升级"之后才是全局的**；
- **升级后再换位置调用，就都能调到了**。

> 把变量升级为全局变量，用的是 **`export`** 命令。
