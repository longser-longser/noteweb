# Linux 操作系统 课堂笔记（第 21—24 节）——复制、移动与查看文件的三级台阶

> 本节接着上一节建好的「信息」「应用」两个目录往下做：先用 `cp` 把文件复制过去，一路被「路径」绊了一次、被「权限」拦了一次；于是讲清 `cp -p` 保留属性、目标已存在时复制改名、`cp -r` 复制目录、`-u` 只复制更新的。接着用 `mv` 一条命令完成「移动 + 改名」。最后解决「在命令行里怎么看见文件内容」：`cat` 一次倒完看不清 → `more` 能翻页但只能往后 → `less` 上下左右都能翻，再用 `head` / `tail` 只取头尾。

---

## 知识链：本节在整门课里的位置

### 来路

上一节在根目录下建了两个目录「信息」和「应用」，也建过普通文件，`mkdir` / `touch` / `rmdir` / `rm` 那一套已经能用了。本节拿这两个目录当现场——复制、移动、查看，操作的都已经是「存在的文件」。

### 本节主线

```text
建好的文件 → cp 复制（相对路径错 → 换绝对路径 → 成功）
           → 复制过来的是「新文件」（属性没跟过来）→ cp -p 补上
           → 目标同名会覆盖 → 复制时改名
           → 复制目录要 -r → -v 看过程 → * 复制一批
           → cp -u 只复制更新的
mv 移动 / 移动改名 / 原地改名（不加任何参数，属性时间原样跟过来）
cat 看不清 → more 只能往后 → less 上下左右
head / tail 只取头尾
普通用户复制失败 → 权限 → /etc/passwd 里存的是用户
```

### 去路

本节两次「复制不过去」都指向同一个东西：权限。`ls -l` 里那一列究竟是什么、怎么改，是后面单独一节的内容；`/etc/passwd` 里存着系统里所有用户，也是从用户与权限这条线接下去的。

## 一、开场：还是那两个目录，先把「路径」说清楚

### 1.1 现场是什么样

根目录下有两个目录：`/信息` 和 `/应用`。老师先 `ls -l` 看了一眼，两者的时间不一样：

```bash
ls -l /
drwxr-xr-x  ...  10月 12 15:53  信息
drwxr-xr-x  ...  10月 19 14:39  应用
```

一个是 10 月 12 日 15:53 建的，一个是 10 月 19 日 14:39 建的。本节要复制、移动、查看的东西就放在这两个目录里（比如「信息」下的 `a1`）。

### 1.2 相对路径这次为什么不行

人在根目录下，想把「信息」里的 `a1` 复制到「应用」：

```bash
cp 信息/a1 应用/
```

**执行不对。** 老师说得很直接：路径一定要弄清楚什么时候用相对路径、什么时候用绝对路径——「这个路径是非常重要的，你别弄错」。

原因在于「信息」和「应用」都挂在根下：你人虽然在根下，但命令里只写「应用」，指代是不牢靠的。把两边的绝对路径都写全，就成功了：

```bash
cp /信息/a1 /应用/
```

> 💡 `cp` 的两个参数是「源」和「目标」。源写相对还是绝对，取决于你人站在哪；只要目标位置写得含糊，就老老实实写绝对路径，别猜。

## 二、`cp`：复制文件

### 2.1 最基本的写法

```bash
cp 源文件 目标位置
```

命令和参数之间要敲空格——老师特意强调：敲一下就够了，不用连着敲很多下。

### 2.2 不加参数，复制过来的只是一个「新文件」

复制成功以后，文件确实出现在「应用」里了，但**属性没跟过来**。老师的原话是：「属性牵涉到这个文件的属性，我们没有复制，我相当于在这儿新建了一个文件。」

也就是说，不加参数的 `cp` 只搬走**内容**；权限、属主、最后修改时间这些，都按「新造一个文件」重新算——所以你看到的时间是当前时间，而不是源文件的时间。

### 2.3 `cp -p`：把权限、属性、时间一起搬过来

```bash
cp -p /信息/a1 /应用/
```

`-p` 的作用，老师讲了两遍，是同一个意思：把文件的内容、权限、最后一次修改时间**一块儿**复制过来；要连属性一起复制，就加 `-p`，「否则的话复制不过来」。

两种写法的差别：

| 写法 | 复制过来的时间 | 权限与属性 |
|---|---|---|
| `cp` | 变成当前时间（相当于新建） | 不保留 |
| `cp -p` | 与源文件一致 | 保留 |

> ⚠️ `-p` 不是「复制得更完整」，而是「连身份一起复制」。凡是要让复制前后「看起来还是同一个文件」，第一个想到的就是 `-p`。

### 2.4 `cp` 的常用参数一览

老师把 `cp --help` 的参数表从头过了一遍，并说参数虽然多，日常真正用得上的不多。归拢成一张表：

| 参数 | 作用 | 什么时候用 |
|---|---|---|
| `-p` | 保留权限、属主、时间戳 | 要求复制后属性不变 |
| `-r` / `-R` | 递归复制整个目录 | 复制目录（必须加） |
| `-v` | 显示复制过程 | 复制一批文件时看清进度 |
| `-u` | 源比目标新、或目标不存在时才复制 | 只更新改过的文件（见第五节） |
| `-f` | 强制：目标已存在或打不开时，先删掉再试 | 覆盖被挡住时 |
| `-i` / `-n` | 覆盖前先问一句 / 干脆不覆盖已存在的目标 | 怕误覆盖 |
| `-d` | 复制链接本身，不跟随链接指向的文件 | 处理符号链接 |
| `-l` / `-s` | 不复制内容，改为建立硬链接 / 符号链接 | 要「多一个入口」而不是多一份拷贝 |
| `-b` / `-S 后缀` | 覆盖前先备份目标 / 指定备份文件的后缀 | 覆盖之前留一手 |
| `-t 目录` | 先写目标目录，后面可跟多个源文件 | 一次把多个文件复制到同一处 |

## 三、目标已存在：覆盖，还是换个名字

### 3.1 默认会覆盖

目标位置已经有同名文件时，`cp` 会提示你要不要覆盖——「已经存在了……它会提示你给它覆盖掉」。

### 3.2 复制时改名

不想覆盖、又不想动源文件，最省事的办法是：**在目标位置直接写一个新名字**。

```bash
cp /信息/a1 /应用/a1_new
```

结果：`/应用` 下多了一个 `a1_new`，名字不一样，内容是一样的（要属性也一样，按 2.3 加 `-p`）。

> 💡 「复制 + 改名」不需要两条命令：`cp` 的目标参数本身就是一个路径，写到新名字上，就等于复制的时候改了名。

## 四、复制目录：`-r`、`-v` 与 `*`

### 4.1 目录必须加 `-r`

```bash
cp 信息 应用        # 不行，会报错
cp -r 信息 应用     # 可以，目录连着里面的东西一起复制
```

老师说：复制目录就得加 `-r`。

复制过来以后再核对：内容没变，但**目录的权限、属性、最后一次访问时间都变了**——因为这一条没加 `-p`。所以「复制目录并且保留属性」要两个参数一起上：

```bash
cp -rp 信息 应用
```

### 4.2 `-v`：看清楚到底复制了什么

`-v` 会把每一个被复制的文件打印出来。复制一批文件时，屏幕上刷过去的就是「复制了哪些东西」，比事后 `ls` 一个个数靠谱得多。

### 4.3 `*`：一次复制一批

要复制 `/etc` 下所有以 `a` 开头的文件：

```bash
cp -r /etc/a* /应用
```

`a*` 里的 `*` 代表「a 后面跟什么都算」，一次就能复制一批。老师强调这种写法很有用：平时要复制的往往不是单个文件，而是一类文件。

> ⚠️ `*` 是交给 shell 先展开成一串文件名、再交给 `cp` 的。所以 `a*` 圈进来的是什么，取决于目录里当时有哪些文件——动手前先 `ls /etc/a*` 看一眼最稳妥。

## 五、`cp -u`：只复制「更新过的」

### 5.1 规则

```bash
cp -u 源 目标
```

只有**源文件比目标文件新**，或者**目标文件根本不存在**时，才真正复制；否则跳过。

老师说这个参数「非常有用」：文件更新了，想把旧的覆盖掉——在 Windows 里往往是直接覆盖，而在 Linux 里用 `-u` 可以先比较一下再决定。

### 5.2 什么时候用

- 目标位置已经有一份，只想把「后来改过的」同步过去，没改的不动；
- 目标可能还不存在——`-u` 在这种情况下也会正常复制过去。

## 六、`mv`：移动与改名，一个命令三件事

### 6.1 三种用法

| 写法 | 效果 | 例子 |
|---|---|---|
| `mv 文件 目录` | 移动到该目录，名字不变 | `mv /信息/a1 /应用` |
| `mv 文件 目录/新名` | 移动过去并改名 | `mv /信息/a1 /应用/a1_new` |
| `mv 原名 新名` | 原地改名 | `mv a1.txt a2.txt` |

### 6.2 不用加任何参数

复制目录要 `-r`，**移动不用**：「移动当中我们不需要（加参数），目录也好、文件也好，不需要加任何参数，给它挪过去就行。」

`mv` 的本质是**剪切**：源位置没有了，东西到了目标位置。这一点和 `cp` 完全不同。

### 6.3 移动过来的还是原来那个文件

老师特意做过对比：复制过来的文件，时间会变成新的；**移动过来的文件，权限、内容、时间都还是原来的**——因为它不是新建的，是搬过来的。

### 6.4 改名：内容、大小、权限、时间一个都不动

在同一个目录里换个名字，就是「重命名」：

```bash
mv a1.txt a2.txt
```

改名前后核对：还是 55 个字节、还是原来那个时间、权限也没变——「他只是把文件名改了，权限什么的、保存的时间都没有动」，连「新建」的痕迹都看不出来。目录改名同理。

> 💡 Linux 命令行里没有单独的「重命名」命令。图形界面里右键有「重命名」，命令行里就用 `mv`：**移动到别处不改名 = 移动；移动到别处改名字 = 移动 + 改名；原地不动只换名字 = 改名。**

### 6.5 复制与移动对照

| 对比项 | `cp` 复制 | `mv` 移动 |
|---|---|---|
| 源文件 | 还在原处 | 原处没有了（剪切） |
| 目标位置 | 新造一份 | 原封不动搬过去 |
| 属性与时间 | 默认按新文件算，加 `-p` 才保留 | 原样保留，不用加参数 |
| 目录 | 必须加 `-r` | 直接移，不用加参数 |
| 改名 | 目标位置写新名字 | 目标位置写新名字，或者原地 `mv 原名 新名` |

## 七、看文件内容：`cat` → `more` → `less`

### 7.1 为什么非得用命令

Windows 里双击就打开了——记事本、Word、Office 套件都能直接看。Linux 命令行下没有「双击」这回事，要看文件里写了什么，只能让命令把内容打到屏幕上。

### 7.2 `cat`：一次全部倒出来

```bash
cat /etc/passwd
```

`cat` 把整个文件一次性输出。文件短的时候很痛快；文件一长，前面的内容就直接滚出屏幕了——**它不分页，你只能看到最后一部分**。

老师演示时打开的是 `/etc/ssh/sshd_config`（一百三十行左右），一屏根本装不下，屏幕最后只剩末尾那几行。

### 7.3 `cat -n` 与 `cat -b`

| 参数 | 行号怎么编 | 演示结果 |
|---|---|---|
| `cat -n` | 每一行都编号，**空行也占一个号** | 编到 130 |
| `cat -b` | 只给**有内容**的行编号，空行不编 | 编到 106 |

同一个文件，`-n` 编到 130，`-b` 编到 106，差的 24 个号就是空行。老师说 `cat` 的参数不多，常用的就 `-n` 和 `-b`，其他基本用不上。

> 💡 想知道一个文件「有多少行是有内容的」，用 `cat -b` 看最后一个编号即可——空行不算数。

### 7.4 `more`：能翻页，但只能往后翻

```bash
more /etc/ssh/sshd_config
```

- 一屏一屏地看，屏幕底部显示已经看到百分之多少（演示时出现过 18%）；
- **只能往后翻，不能往前翻**——这是 `more` 最大的毛病，前面的内容没看清就回不去了。

`more` 还能控制「一屏显示几行」和「从第几行开始」：

| 写法 | 作用 |
|---|---|
| `more -10 文件` | 一屏只显示 10 行 |
| `more +20 文件` | 从第 20 行开始显示 |
| `more -c 文件` | 显示之前先清屏 |

> ⚠️ 在字符文本界面（那种不进图形界面的全屏终端）里，屏幕是**不能往回滚**的，所以「只能往后翻」是真的回不去。这一点在 7.6 还要用到。

### 7.5 `less`：上下左右都能翻

```bash
less /etc/ssh/sshd_config
```

`less` 就是给 `more` 补上「往回翻」：

- 上下左右都能翻，方向键直接可用；
- 前面的内容没看清，按上键就回去了，往左往右也行；
- 打开时不清屏，前面的内容还留在上面（老师形容是「在新窗口里」看）；
- 看完按 `q` 退出。

`less -N` 可以在每行前面显示行号：

```bash
less -N /etc/ssh/sshd_config
```

### 7.6 三个命令怎么选

| 命令 | 能不能分页 | 能不能往回看 | 适用场景 |
|---|---|---|---|
| `cat` | 不能 | —— | 短文件，一次看完 |
| `more` | 能（只能往后） | 不能 | 长文件，顺着看一遍 |
| `less` | 能（上下左右） | 能 | 长文件，要来回找 |

> 💡 老师最后的结论：在**终端窗口**里（窗口本身能用鼠标往上滚），`cat` / `more` / `less` 用哪个都行，都能翻回去看；只有在**字符文本界面**里，三者的区别才真正显出来。所以「用哪一个」取决于你在哪儿用。

## 八、掐头去尾：`head` 与 `tail`

### 8.1 `head`：只看开头

```bash
head -n 6 /etc/ssh/sshd_config
head -6 /etc/ssh/sshd_config        # -n 可以省略，直接跟数字
```

显示前 6 行。`-n` 能省，写成 `-6` 效果一样。

### 8.2 `tail`：只看结尾

```bash
tail -n 6 /etc/ssh/sshd_config
tail -6 /etc/ssh/sshd_config
```

同一个文件，`head -6` 给开头 6 行，`tail -6` 给最后 6 行——一前一后，正好对上。

### 8.3 行数与字节数

`head` 和 `tail` 都能不按行、改按「字节」取：

```bash
head -c 100 文件      # 前 100 个字节
tail -c 100 文件      # 最后 100 个字节
```

> ⚠️ 还讲过一种「把末尾若干行排除掉」的写法：行数前面加负号，`head -n -20` 表示**除最后 20 行以外的全部内容**。注意它和 `tail -n 20`（只要最后 20 行）正好相反。

> 💡 文件很长时，先 `head` 看开头、`tail` 看结尾，比把整个文件刷一屏高效得多。

## 九、复制不过去的那两次：权限与 `/etc/passwd`

### 9.1 换成普通用户，同样的命令就失败了

前面一直用超级管理员在操作，所以「前面为什么一样」。换成另一个普通用户账号再做一次，同样一条命令就出问题了：把「信息」下的 `a1` 复制到「应用」，**复制不过去**。

### 9.2 老师说：这不是命令的问题

- 「你拷贝到其他地方拷不上，为什么拷不上？他没有权限。」
- 「我没有权限访问，所以我往那边写是写不动的。」
- 「我放到我自己的目录当中是可以的」——复制到自己的家目录就正常了。

所以能不能复制成功，不只看路径写没写对，还要看**你对目标目录有没有写的权限**。

> ⚠️ 同一个 `cp`，root 能成功、普通用户失败，八成不是命令写错了，而是目标目录不允许你写。看到「拷不上」，先别改命令，先看权限。

权限信息在 `ls -l` 的第一列就能看见（老师演示时一直在看这一列），但那一位一位到底表示什么、怎么改，是后面单独一节的内容。

### 9.3 `/etc/passwd`：所有用户都在这个文件里

用 `cat` 看的第一批文件里有一个 `/etc/passwd`。老师的说明很短：**这个文件里存着系统里所有的用户信息**。

```bash
cat /etc/passwd
```

所以「机器上到底有哪些用户」，在这个文件里能直接看到。它也是后面讲用户与权限时的入口。

## 十、小结

### 10.1 一条线串起来

```text
cp       → 复制（只有内容）
cp -p    → 复制（内容 + 权限 + 属性 + 时间）
cp 源 目标/新名 → 复制并改名
cp -r    → 复制目录          cp -rv  → 复制目录并显示过程
cp -u    → 只复制更新的
mv       → 移动 / 移动改名 / 原地改名（不加参数）
cat / -n / -b   → 短文件
more            → 能分页，只能往后翻
less / -N       → 上下左右都能翻，q 退出
head / tail / -c → 只取头尾
```

### 10.2 必须记住的几条

| 序号 | 要记住的 |
|---|---|
| 1 | `cp` 只搬内容；属性要跟着走，加 `-p` |
| 2 | 复制目录必须 `-r`；目录连属性一起复制，用 `-rp` |
| 3 | 目标位置写新名字 = 复制时改名；`mv` 原地换名字 = 重命名 |
| 4 | `mv` 不加任何参数，目录也能直接移 |
| 5 | `cat` 不分页，`more` 只往后，`less` 随便翻，`q` 退出 |
| 6 | `-u` 只在「源更新」或「目标不存在」时才复制 |
| 7 | 复制不过去，先查权限，别先改命令 |

> 💡 老师提醒过：建文件、建目录、复制、改名这几类操作是必考的，`cp` 的使用率几乎是百分之百——上面这几条要做到合上笔记能直接写出来。
