# Linux 操作系统 课堂笔记（第 29—32 节）——从"给机器建账号"到"管账号"：`useradd`、`/etc/passwd`、`/etc/shadow` 与 `passwd`、`userdel`

> 上一段把**编辑器**用熟了：`vi` / `vim` 三种模式来回切，内容能写进去、能改、能存。可这些内容**归谁**？→ 一台服务器从来不是一个人在用：企业里的邮件服务器、文件服务器、网站，都是**很多人同时登录** → Linux 是**多用户、多任务**系统，每个使用者都得有一个**账号**，没有账号连登录都登录不上（就像游戏没注册就进不了服务器）→ 账号怎么来？**一条命令**：`useradd 用户名` → 建完以后系统里**多了好几处东西**：`/etc/passwd` 多一行（**七个字段**）、`/etc/shadow` 多一行（**九个字段**，真正的密码在这儿）、家目录多一个文件夹、邮件目录多一个邮箱文件 → 可光有账号还是登不上：`/etc/passwd` 的密码位只是个 `x`，`/etc/shadow` 里是 `!!`，**没设密码的账号等于锁着** → 用 `passwd 用户名` 设密码，**输的时候屏幕上什么都不显示** → 想一次把账号的各属性定死：`useradd` 后面加 `-u`（UID）、`-d`（家目录）、`-s`（shell）、`-c`（说明信息）、`-p`（密码，⚠️ 明文）、`-r`（系统用户）、`-e`（账号失效日期，做临时账号）→ 账号要**停用 / 恢复 / 找回密码**：`passwd -l` 锁（shadow 里加 `!!`）、`passwd -u` 解、`passwd -d` 清空 → 人走了要**删账号**：`userdel` 只删两个文件里的登记，**家目录和邮箱还留在机器上**；`userdel -r` 才一起删；`userdel -f` 连正在登录的用户也照删。

## 知识链：本节在整门课里的位置

> 本节的知识不是孤立的。下面三张表说明"前面学过什么 → 本节主线 → 后面要用到哪里"。

### 🔗 来路：前面学过的，本节用上了

| 学过的地方 | 学的是什么 | 在本节哪里用上了 |
|---|---|---|
| **第 25—28 节 · `vi` / `vim` 三种模式** | 一般命令模式 / 编辑模式 / 末行模式，`Esc` 回退，`:wq` 存盘 | 本节开场先给编辑器收口：老师说这个编辑器"**后期用得非常多**"，要求**三种模式能来回快速切换**、清楚"哪个时候用哪一种模式"。本节打开 `/etc/passwd`、`/etc/shadow` 看内容，以及"**复制一份再改**"，还是这一套 |
| **第 21—24 节 · `/etc/passwd`** | 那时只说了一句：**这个文件里存着系统里所有的用户** | 本节把它真正打开，**七个字段一个一个数**——用户名、`x`、UID、GID、说明信息、家目录、shell |
| **第 21—24 节 · 普通用户 `cp` 失败** | 同一个 `cp`，root 能成、普通用户被拒，原因是**权限** | 本节又来一次，而且是更硬的拒绝：**普通用户执行 `useradd` 直接被顶回来** |
| **第 9—12 节 · `su` 切换用户** | 超级管理员 ↔ 普通用户来回切 | 老师现场就是 `su` 到普通用户去试 `useradd`，用"切过去就建不了"来证明**建账号是管理员的活** |
| **第 13—16 节 · `ps` 里的 USER / UID** | 那时只是"看见"每个进程属于哪个用户、UID 是多少 | 本节把 **UID 本身**讲清楚：每个用户一个号，**号段分三类用户** |
| **第 17—20 节 · 先 `cp` 一份再动** | 改重要文件之前先备份，不动原件 | 老师看 `/etc/passwd` 时说的是同一句话："**这个文件我修改过，但是我是复制的**……**原文件是不能动的**，一动这些就坏了" |
| **第 17—20 节 · `rm -r` / `rm -f`** | 递归删目录、强制不提示 | `userdel` 删不干净的家目录和邮箱，只能**手动 `rm`**，而且"因为这是一个目录，目录你必须也（带递归）删" |
| **第 5—8 节 · 装机时设 root 密码、建普通用户** | 安装时要设 **root 密码**，还要**建一个普通用户**才能登录桌面 | 本节 `passwd` 文件的第一行就是那个 **root**（**UID 和 GID 都是 0**）；本节现场 `useradd` 出来的 `u1`～`u8`，就是"装机时做的事，现在用命令再做一遍" |

### ⛓ 本节主线（一条因果链）

老师这节课是一条线走到底的：**为什么要账号 → 怎么建 → 建完系统里多了什么 → 怎么让它能用 → 怎么停、怎么改、怎么删**。

```text
编辑器会用以后，内容能写进去了 —— 可这台机器不止一个人用
        ↓
邮件服务器、文件服务器、网站（Apache）：很多人同时登录
        ↓
Linux 是多用户、多任务系统 —— 每个使用者都要有一个账号
        ↓ 没有账号会怎样？
连登录都登录不上；就像游戏里没注册，服务器不认你
        ↓
账号怎么建？一条命令：useradd 用户名
        ↓ 建完，系统里到底多了什么？
/etc/passwd    多一行（7 个字段：用户名、x、UID、GID、说明信息、家目录、shell）
/etc/shadow    多一行（9 个字段：真正的密码、密码策略、账号有效期都在这儿）
家目录          多一个同名文件夹
邮件目录        多一个同名邮箱文件
        ↓ passwd 里密码位只是个 x，这个号能用吗？
不能 —— shadow 里是 !!，等于没密码、等于锁着，登不上
        ↓
passwd 用户名      设密码（输的时候屏幕上什么都不显示）
        ↓ 想一次把账号的属性全定下来？
useradd -u 1010 -d 家目录 -s /sbin/nologin -c 说明 -e 2026-11-09 ...
        ↓ ⚠️ -p 直接把密码写在命令行上 —— 进了 shadow 是明文
        ↓ 账号要临时停用 / 恢复 / 找回密码？
passwd -l 锁定（shadow 里前面加 !!）   passwd -u 解锁   passwd -d 清空
        ↓ 人走了，账号怎么删？
userdel 用户名      只删 passwd 和 shadow 里的登记，家目录、邮箱还在
userdel -r 用户名   连家目录和邮箱一起删
userdel -f 用户名   正在登录也照删（强制）
```

### 🔗 去路：本节内容后面用在哪里

| 本节内容 | 后面 / 实际运维时用在哪里 |
|---|---|
| **UID 的号段（0 / 1—999 / 1000 起）** | 后面讲**文件权限**时要看"这个文件属于谁"，`ls -l` 里那一列显示的就是用户和 UID——**分不清号段，就分不清这是人还是系统** |
| **GID 与"同名主组"** | 本节老师**故意只点了一下**："（GID）一般在这儿用不上，我们后面讲（用户）组的时候再说。" 下一块就是**用户组** |
| **`/etc/passwd` 的七个字段** | 排查"这个账号为什么登不上"时的第一站：家目录对不对、shell 对不对，全在这一行里 |
| **`/etc/shadow` 的九个字段** | 密码策略就落在这几列上：多久必须改、什么时候过期、账号什么时候作废。**临时账号、外包账号**全靠第 8 列 |
| **`useradd` 的参数** | 批量建账号、写脚本建账号时，靠的就是这些参数；`-e` 是**临时账号**的标准做法 |
| **`passwd -l` / `-u` / `-d`** | 员工离职先**锁**不删、忘密码**清掉重设**——这是运维里天天做的事 |
| **`userdel` 与 `userdel -r` 的区别** | ⚠️ 删账号最典型的坑：以为人删了就干净了，**家目录和邮箱还占着盘、还留着数据** |
| **"多用户"这个前提** | 后面所有服务（Apache、邮件、文件共享）**都要按用户授权**，账号是权限的载体 |

## 一、开场：编辑器收个尾，转到"这台机器是谁在用"

### 1.1 上一节的内容先收口

老师开场只用了两三句话回顾上一节：

> 老师原话（大意）：**"我们上一节课讲的内容比较少，（就是）熟悉使用了一下我们的编辑器。"**

他对编辑器的态度很明确：

| 老师说的 | 意思是 |
|---|---|
| **"后期我们要用这个编辑器，用得非常多、非常频繁"** | 这不是学完就丢的内容，**后面一直要用** |
| **三种模式要能"来回"切换** | 不是记住三个名字，而是**手上要快** |
| **"哪个时候用哪一种模式"** | 关键是**判断**：现在该写字，还是该下命令 |

> 📌 所以编辑器的要求是**熟练**，不是"知道"。本节开始，话题从"**怎么把内容写进去**"转到"**这些东西归谁**"。

### 1.2 一个新问题浮出来：这台机器不止一个人用

前面所有的操作——建目录、建文件、写内容、复制、删除——都是**一个人在一台机器上**做的。可服务器不是这么用的。

> 老师原话（大意）：**"（Linux）也是一个多用户、多任务（的操作系统）。"**

一句话：**接下来要管的不是文件，是"人"。**

## 二、Linux 是多用户系统：为什么一台机器要有很多账号

### 2.1 先拿游戏账号打比方

老师这一段讲得很生活化，用的全是"游戏"这个比方：

| 游戏里 | Linux 里 |
|---|---|
| 每个人有自己的**游戏名**，而且**游戏名和登录用的用户名不是一回事** | 每个使用者有自己的**用户名**，登录用它 |
| 相当于在**服务器上注册了一个用户**、建了一个角色 | 相当于在系统里**建了一个账号** |
| 你的东西**存在服务器上**（数据库里），下次登录直接调出来 | 账号的信息**存在系统文件里**，登录时读出来 |
| **没注册就进不去** | **没有账号就登录不上** |
| 一个服务器上可以有很多人、很多角色 | 一台机器上可以有很多账号 |

> 老师原话（大意）：**"你自己登录不上……你没办法使用，你没办法登录。必须是（注册）了以后才能登录。"**

### 2.2 企业里到底是谁在用

老师举的都是他实际见过的场景：

| 场景 | 为什么一定是多用户 |
|---|---|
| **邮件服务器** | 每个人一个邮箱、一个账号，各看各的信 |
| **文件服务器** | 不同的人能看的文件不一样，得按账号分 |
| **网站服务器** | 老师原话里点到了 **Apache**——"我们这里边用的 Apache"，网站服务同样是按用户跑起来的 |
| **大促、抢购那种场面** | 老师拿购物节打的比方：**一下子涌进来很多人**，服务器扛不扛得住，是硬件和账号数一起决定的 |

### 2.3 一台机器能建多少用户

> 老师原话（大意）：**"（能同时允许多少人用）跟硬件有关，根据它的（配置）来……具体建多少，根据你服务器实际的硬件配置来决定。"**

所以：**没有固定数字**，看机器。企业里"都会建很多用户"，但建多少是**按硬件说话**的。

> 💡 注意这个说法的落点：**账号数量不是随手拍的，是硬件撑得住的量。**

## 三、建一个用户：`useradd`

### 3.1 就一条命令

```bash
useradd 用户名
```

> 老师原话：**"这个命令非常简单，叫 `useradd`。"**

### 3.2 现场：建出第一个用户

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 用超级管理员登录 | —— | 提示符是 `#` |
| 2 | 建一个用户 | `useradd u1` | **屏幕上没有任何输出**，直接回到提示符——**没消息就是建成了** |
| 3 | 看用户总账 | `cat /etc/passwd` | 文件末尾**多出一行**，最后一段是 `u1` 的信息 |
| 4 | 看密码文件 | `cat /etc/shadow` | 也**多出一行**，密码那一列是两个感叹号 `!!` |

这一行的样子**就是七列**，老师是**一列一列念下来**的：

```text
u1:x:1001:1001::/home/u1:/bin/bash
```

| 念到第几列 | 内容 | 老师说的话（大意） |
|---|---|---|
| 1 | `u1` | 用户名 |
| 2 | `x` | 密码位，"这里面不用管它，它在另一个密码文件当中" |
| 3 | `1001` | UID，"我新建的用户是从一千开始" |
| 4 | `1001` | GID，"GID 就是 1001" |
| 5 | 空 | 说明信息，"我是没有说明信息的" |
| 6 | `/home/u1` | 家目录 |
| 7 | `/bin/bash` | "和内核进行交互（的时候），用的就是这个 `/bin/bash`" |

### 3.3 换成普通用户，就建不了

老师现场演示了"没有权限"是什么样子：

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 切到普通用户 | `su u1` | 提示符变了 |
| 2 | 照样建一个用户 | `useradd u9` | **被顶回来**，提示没有权限 |
| 3 | 回到管理员 | `exit` | 提示符变回 `#` |

> 老师原话（大意）：**"就是因为我们是没有权限的。"**

> 📌 **建账号是管理员的活。** 这也是本节第一次把"**超级管理员 / 普通用户**"的区别直接摆到台面上——后面讲 `/etc/passwd` 能不能改，还是这一条。

## 四、`/etc/passwd`：所有用户都在这一个文件里

### 4.1 用户的"总账本"

```bash
cat /etc/passwd
```

老师先给这个文件定了性：

> 老师原话（大意）：**"（这里）有一个配置文件，所有的用户，你只要建（了），他这里边就会有一个（记录）。"**

### 4.2 ⚠️ 这个文件不能随便动

老师在打开它之前，专门交待了一句：

> 老师原话（大意）：**"这个文件我修改过，但是我是复制（了以后）修改（的）……原文件是不能动的，一动这些（账号）就（全乱）了。我都是复制了以后才进行（修改）的。"**
> **"在这个地方不能（乱动），你是不能随随便便地动的。"**

还有一句是拿身份说的：

> 老师原话（大意）：**"我现在用的是超级管理员用户，所以说我可以动；但是我们普通用户是不能动（的）。"**

> ⚠️ **易错点**：`/etc/passwd` 是**系统的用户总账**，不是普通文本。要看、要试，先 `cp` 一份出来改副本——这正是第 17—20 节那条老规矩。

### 4.3 一行七个字段

每一行是一个用户，字段之间用**冒号**隔开，**一共七列**：

| 第几列 | 字段 | 里面是什么 | 现场看到的 |
|---|---|---|---|
| 1 | **用户名** | 登录时用的名字 | `u1` |
| 2 | **密码位** | 只放一个 `x`，**真正的密码不在这儿** | `x` |
| 3 | **UID** | 用户 ID 号，**每个用户一个，各不相同** | `1001` |
| 4 | **GID** | 主组的 ID | `1001` |
| 5 | **说明信息** | 这个账号给谁用，**可以是空的** | 老师建的这几个都是空的 |
| 6 | **家目录** | 登录以后默认待的地方 | `/home/u1` |
| 7 | **shell** | 登录后**跟内核打交道**的程序 | `/bin/bash` |

> 老师原话（第 2 列）：**"（密码位）就是 `x`，这里面不用管它——它在另一个密码文件当中。"**
> 老师原话（第 7 列）：**"和内核进行交互（的时候），用的就是这个 `/bin/bash`。"**

> 💡 七列里最容易被忽略的是**第 2 列和第 5 列**：一个是"密码根本不在这"，一个是"空着也正常"。

### 4.4 这七列全都可以改

> 老师原话（大意）：**"我们这里面的所有的（项）都可以修改——这些所有项都可以修改。"**

本节后面 `useradd` 讲的那一堆参数，**改的就是这七列里的某几列**：

| 参数 | 改的是第几列 |
|---|---|
| `-u` | 第 3 列 UID |
| `-c` | 第 5 列 说明信息 |
| `-d` | 第 6 列 家目录 |
| `-s` | 第 7 列 shell |

## 五、UID：一眼看出这是"哪一类用户"

### 5.1 每个用户都有一个号

> 老师原话（大意）：**"用户 ID……我们每个用户都有一个 ID 号，这个 ID 号（各）不一样。"**

### 5.2 号是从 0 开始数的

> 老师原话（大意）：**"我们都知道在计算机当中，零代表的是第一个……我们基本上都是从零开始的。"**

这个"从 0 开始"不是随口一说，它直接决定了下面三类用户怎么分：

### 5.3 三类用户，三个号段

| 用户类型 | UID | 干什么的 | 现场看到的 |
|---|---|---|---|
| **超级管理员**（root） | **0** | 权限最大，什么都能动 | `passwd` 第一行，**UID 和 GID 都是 0** |
| **系统用户** | **1—999** | **系统自己用的**，给服务和程序使 | `shadow` 里密码位是 `*`，**不能直接登录** |
| **普通用户** | **1000 起** | **给人用的** | 老师新建的第一个就是 **1001**，往后 1002、1003…… |

> 老师原话（大意）：**"1 到 999 就是系统用户，0 是超级管理员用户，1000 以后那就是普通用户。"**
> 老师原话：**"我新建的用户是从一千开始。"**

> 📌 **拿 UID 判身份，比看名字可靠**：名字可以随便起，号段是系统定死的。

### 5.4 GID 先放着，但"为什么要组"讲清楚了

GID 那一列是**组**的编号。老师明说这块**先不动**：

> 老师原话（大意）：**"（GID）一般在这儿用不上，我们后面讲（用户）组的时候再说。"**

但他把**为什么要有组**讲透了，这段是本节最像"运维现场"的一段：

> 老师原话（大意）：**"在企业当中，我们会把一个部门的用户放在一起——人事部、财务部、采购部、销售部……不同的部门，我会把这些用户放到不同的（组）里。因为我们在企业当中用不同的用户，他的权限是不一样，（我们）会设置这个组的权限，来限制这个用户的权限。"**

还有一句要紧的——**建用户的时候，系统会自动建一个同名的组**：

> 老师原话（大意）：**"我们所有的用户（建的时候）他都会建一个（同名的组）……（这个）讲组的时候再说，我现在还没有讲。"**

所以现场看到的 `1001:1001`（UID 和 GID 是同一个数），原因就在这儿。

## 六、`/etc/shadow`：真正的密码在这个文件里

### 6.1 为什么 `passwd` 里只有一个 `x`

```bash
cat /etc/shadow
```

> 老师原话（大意）：**"（密码）在另一个密码文件当中"**——就是 `/etc/shadow`。

### 6.2 密码那一列，能看出好几种状态

| 在 `shadow` 里看到什么 | 什么意思 | 能不能登录 |
|---|---|---|
| **`!!`**（两个感叹号） | **没有设密码**，或者**密码被锁** | ❌ **登不上** |
| **`*`**（星号） | 系统用户的密码位 | ❌ **不能直接登录** |
| **一串看不懂的密文** | 设过密码，存的是**加密后**的结果（SHA-512） | ✅ 能登 |
| **一眼能看懂的明文** | ⚠️ 用 `useradd -p` 直接写上去的，**等于没加密** | 见 7.6 |

> 老师原话（大意）：**"（从这里）我们就可以看到，那星号就属于系统用户，不能直接登录；还有一些是什么呀？双感叹号，双感叹号也是不能直接用的。"**
> 老师原话（大意）：**"系统里面（建）的用户，没有密码不能登录。"**

> ⚠️ **易错点**：**"建了用户"和"这个用户能用"是两件事。** 刚 `useradd` 出来的账号，密码位是 `!!`，**必须 `passwd` 设过密码才算开通**。

### 6.3 九个字段：一个账号的"一生"都记在这儿

| 第几列 | 字段 | 管什么 | 默认 / 现场 |
|---|---|---|---|
| 1 | **用户名** | 谁的 | `u1` |
| 2 | **密码** | 加密后的密码（`!!` / `*` / 密文） | `!!` |
| 3 | **最后一次改密码的日期** | 从 **1970 年 1 月 1 日** 起算的**天数** | 现场是两万多天 |
| 4 | **密码最短使用天数** | 设了以后**多久才能再改** | `0` → **随时能改** |
| 5 | **密码最长有效期** | 从最后一次改密码算，**过了就过期** | `99999` 天（老师算：约 **273 年**） |
| 6 | **到期前警告天数** | 提前几天提醒"该改密码了" | `7` 天 |
| 7 | **过期后的宽限天数** | 密码过期后**还能用几天** | 默认**没设** → 过期立刻不能用 |
| 8 | **账号失效日期** | 到这天**整个账号作废** | 空；**临时账号**靠它 |
| 9 | **保留字段** | 现在没用 | —— |

> 老师原话（第 3 列）：**"从 1970 年 1 月 1 日开始算，从 1970 年到今天，一共是两万多天。"**
> 老师原话（第 4 列）：**"你密码设置了以后，什么时间、多长时间能改密码？……（默认）你可以立即修改的。"**（要限制的话，可以设成"三天以后才能改"）
> 老师原话（第 5 列）：**"（默认）是多少啊？99999，大概 273 年左右。"**
> 老师原话（第 7 列）：**"（默认）没有（设）……（密码）过期后，你这个账号就不能用了。"**
> 老师原话（第 8 列）：**"（这个字段）规定（日期）之后，将无法再使用这个账号。"**
> 老师原话（第 9 列）：**"这个字段作为保留字段，没有用。"**

> 💡 **九个字段分成三组记**：① 谁、密码；② **密码的三个时间**（最短、最长、提前几天提醒）；③ **账号的两个期限**（过期宽限、账号失效）。第 8 列和第 5 列最容易混：**第 5 列管"密码"，第 8 列管"账号"。**

### 6.4 现场：建一个"只用到某天"的临时账号

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 建账号，同时定**失效日期** | `useradd -e 2026-11-09 u2` | 没有任何输出 |
| 2 | 看用户总账 | `cat /etc/passwd` | 多一行 `u2`，UID 接着往下排 |
| 3 | 看密码文件 | `cat /etc/shadow` | `u2` 那一行的**第 8 列**多了一个数：**20766** |

> 老师原话（大意）：**"从 1970 年 1 月 1 日到（这一天），一共是 20766 天。"**

**这个功能是给谁用的**——老师讲得很具体：

> 老师原话（大意）：**"企业当中，比如说外地来了一个工程师，或者说外地（的人）来我们企业学习的，我临时给他分配一个账号——他在学习的这几年能用，他走了以后，过了这几天就不能再用了。"**

> 老师还专门强调了一遍边界：**"11 月 9 号可以用，但是 11 月 10 号就不能用了。"**

> ⚠️ **易错点**：**`-e` 写进去的是日期，`shadow` 里存的是天数**。看到第 8 列一个五位数别慌——那是"从 1970 年数过来的第几天"，不是乱码。

## 七、`useradd` 的参数：现场一个一个试

### 7.1 参数总表（本节讲到的）

| 参数 | 作用 | 现场 | 改的是 `passwd` 第几列 |
|---|---|---|---|
| **`-u 1010`** | 指定 **UID** | 把新用户的 UID 从顺序号改成 `1010` | 第 3 列 |
| **`-d 目录`** | 指定**家目录** | 默认在 `/home/用户名`，老师把它指到别处 | 第 6 列 |
| **`-s /sbin/nologin`** | 指定 **shell** | 现场把 shell 指到了 `/sbin/nologin` | 第 7 列 |
| **`-c "说明"`** | 写**说明信息** | 写一句"这个账号给谁用" | 第 5 列 |
| **`-p 密码`** | 建号时**直接给密码** | ⚠️ 存进去是**明文**，见 7.6 | 第 2 列 |
| **`-r`** | 建**系统用户** | UID 落在 1000 以下 | 第 3 列 |
| **`-e 日期`** | **账号失效日期** | 见 6.4 | `shadow` 第 8 列 |

> 老师原话（大意）：**"（`useradd`）有 `-e`、`-u`、`-d`、`-s`、`-p`、`-r`、`-c` 等等这些，我们可以通过不同的参数来设置不同的内容。"**

### 7.2 现场：`-u` 改 UID

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 建号时指定 UID | `useradd -u 1010 u3` | 没有输出 |
| 2 | 看用户总账 | `cat /etc/passwd` | `u3` 那一行**第 3 列是 1010**，而**第 4 列（GID）也变成了 1010** |

> 老师原话（大意）：**"（UID）正常情况下是按顺序下来的（1001、1002）……但是我现在把它变了。……因为我没有给它强制设置（GID），所以它也（跟着）变。"**

> 💡 这说明一件事：**UID 变了，GID 会跟着走**，除非另外强制指定。这也是"同名主组"在起作用。

### 7.3 现场：`-d` 改家目录

> 老师原话（大意）：**"默认情况下，它就在（`/home`）这儿；但是我的家目录，我不想让它放到这儿，我想变一下位置。"**

```bash
useradd -d 指定目录 u4
```

结果：`/etc/passwd` 里 `u4` 那一行的**第 6 列**，不再是 `/home/u4`，而是老师指定的那个位置。

> 💡 现场老师指的不是 `/home` 底下的路径——他要演示的就是"**这个位置能改**"。

> 📌 家目录是"这个用户自己的地方"，**建号的时候就把位置定下来了**——`passwd` 第 6 列写的就是它。

### 7.4 现场：`-s` 改 shell

```bash
useradd -s /sbin/nologin u5
```

结果：`passwd` 第 7 列不再是 `/bin/bash`，而是 `/sbin/nologin`。

> 老师原话（大意）：**"你可以改变——这些都可以改变。"**

### 7.5 现场：`-c` 加说明信息

```bash
useradd -c "说明信息" u6
```

> 老师原话（大意）：**"我想加上用户说明信息，那你就是 `useradd -c`。"** 现场填的就是**"这个账号给谁用"**的一句话。

结果：`passwd` 第 5 列**不再是空的**，填进去的就是那句话。

### 7.6 ⚠️ 现场：`-p` 直接把密码写上去——这是明文

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 建号时把密码一起写上 | `useradd -p 密码 u7` | 没有输出 |
| 2 | 看密码文件 | `cat /etc/shadow` | `u7` 密码那一列**是一眼能看懂的明文**，不是密文 |
| 3 | 看密码状态 | `passwd -S u7` | 显示的算法是 **DES**——和正常设密码的 **SHA-512** 不一样 |

> 老师原话（大意）：**"我们通过 `-p` 建的（密码），它是明文显示的。……那上边的（密码）都是密文显示，用的（是）加密算法。但是你看你通过 `-p` 建的密码，这个（根本）没有加密。那么我只要能看得到你的 `shadow` 文件，我就能知道你的密码。"**

> ⚠️ **易错点**：`-p` 后面跟的**不是"设密码"这个动作**，而是**直接把一串字符塞进密码位**——它不会帮你加密。**要给人设密码，用 `passwd`**（见第八节）。

### 7.7 现场：`-r` 建系统用户

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 建一个系统用户 | `useradd -r u8` | 没有输出 |
| 2 | 看用户总账 | `cat /etc/passwd` | `u8` 的 UID **落在 1000 以下**（现场是 977 一带），**和普通用户明显不在一个号段** |

> 老师原话（大意）：**"（这些）都是系统用户，我们是不能用（的）。"**

> 📌 **系统用户不要动。** 它们是给系统自己和服务用的，跟着系统一起装出来的；删掉，依赖它的东西就没了。

## 八、`passwd`：设密码、看状态、锁定、解锁、清空

### 8.1 设密码：一条命令，三次输入

```bash
passwd u1
```

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 给 `u1` 设密码 | `passwd u1` | **"更改用户 u1 的密码。"** |
| 2 | 输新密码 | 密码 | ⚠️ **屏幕上什么都不显示**（连星号都没有） |
| 3 | 再输一遍 | 同一个密码 | 还是不显示 |
| 4 | 完成 | —— | **"passwd：所有的身份验证令牌已经成功更新。"** |

> 老师原话（大意）：**"在这里面设置密码，没有任何显示。你只管输就行了。……有的同学说，我输了多少、输的是什么，也看不见呐——它就是看不见。"**
> 又补了一句：**"我输了多少位，不知道——我自己知道，（别）人不知道，你也看不到。"**

> 💡 **不是键盘坏了，是故意不回显**。这是密码输入的标准做法；看不见，才不会被旁边的人瞄走。

### 8.2 密码有规则，不是随便设

> 老师原话（大意）：**"（提示你要更改密码）……这些简易的密码就不行了。密码要符合密码规则——（大小写）字母加数字，或者说加一些（特殊符号）。"**

太简单的密码会被系统**顶回来**，让你重新设。

### 8.3 拿新账号登一次：能登、能进家目录

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 注销当前用户 | 注销 | 回到登录界面 |
| 2 | 看登录界面 | —— | 新建的 `u1`～`u7` **都在列表里** |
| 3 | 用新账号登录 | 选 `u1`，输密码 | 进到桌面 |
| 4 | 回到家目录 | `cd ~`（或直接 `cd`） | 位置变成 `/home/u1` |
| 5 | 看里面有什么 | `ls` | **空的**——刚建的账号，家目录里什么都没有 |
| 6 | 用桌面系统登录过之后再 `ls` | `ls` | 家目录里**多出了东西** |

> 老师原话（大意）：**"因为这里呀是我们的桌面（系统），你只要用桌面系统登录过就（有），不登录不显示。"**

> 📌 家目录里的东西是**用户自己用出来的**：一登录，桌面环境就把自己的配置写进去；不登录，它就是空的。

### 8.4 看一个账号的密码状态：`passwd -S`

```bash
passwd -S u1
```

> 老师原话（大意）：**"你想看一个用户的密码信息，也可以用 `passwd -S`。"**

| 输出里看到什么 | 意思 |
|---|---|
| **`PS`** + 一个日期 | 密码**已设置**；后面那个日期是最后一次改密码的日子（老师读成"这个用户是什么时候建的"） |
| **`LK`** | 密码**被锁定**，这个账号现在用不了 |
| 密码位是空的 | **没有密码** |
| **`SHA-512`** | 正常设的密码，用的是 SHA-512 加密 |
| 末尾的 **`-1`** | 老师：**"负一这个地方我们没有涉及到，不用管它。"** |

> 老师现场读到的是：**"密码已设置，使用的 SHA-512 算法。"**
> 也读到过：**"密码已锁定。"**——锁定的账号，**密码再对也进不去**。
> 读到系统用户那一行时，日期是 **1969 年 12 月 31 日**，老师解释：**那些账号是随系统一起建出来的**。

> ⚠️ **易错点**：`passwd -S` 和 `cat /etc/shadow` 看到的**不是一回事**：`-S` 是"**结论**"（已设置 / 锁定 / 无密码），`shadow` 里是"**原始数据**"（九列）。老师专门说过一句：**"它显示的密码信息（里）不显示（有效期），你只能在密码文件当中看。"**

### 8.5 锁定：`passwd -l`

```bash
passwd -l u1
```

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 锁定 `u1` 的密码 | `passwd -l u1` | **"锁定 u1 的密码。"** → **"操作成功"** |
| 2 | 看密码文件 | `cat /etc/shadow` | `u1` 密码那一列**前面多了两个感叹号** |
| 3 | 看状态 | `passwd -S u1` | **"密码已被锁定"** |

> 老师打的比方（大意）：**"（这）就相当于（游戏里）封号——你用外挂，我给你封号。"**

> 📌 **锁的是"登录"，不是"删除"**：账号还在，家目录、邮件、里面的东西**一样没动**，解开就能接着用。

### 8.6 解锁：`passwd -u`

```bash
passwd -u u1
```

> 现场：**"会提示你解锁成功"**，`shadow` 里那两个感叹号**去掉了**（"那又去掉了，就正常了"），账号恢复正常。

> 老师的比方接着上面：封了号还能申诉，申诉完了**"我再把这个用户给你解封"**。

### 8.7 清空密码：`passwd -d`——"找回密码"的真相

```bash
passwd -d u7
```

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 清掉 `u7` 的密码 | `passwd -d u7` | 提示密码已清除 |
| 2 | 看密码文件 | `cat /etc/shadow` | `u7` 密码那一列**空了**，**也没有锁定标记** |
| 3 | 看状态 | `passwd -S u7` | 显示**没有密码** |
| 4 | 重新设一个 | `passwd u7` | 又是"成功更新"，账号能正常用 |

> 老师原话（大意）：**"实际上就是删除——我把 u7 的（密码）给删掉。……现在你的密码是空密码，你可以再重新设置。"**

**这一节最值钱的一段，是老师顺手把"找回密码"讲穿了：**

> 老师原话（大意）：**"你选择找回密码，实际上后台会把你的原密码给你清掉，让你再重新设置一下。"**
> **"但是实际上作为后台的人，他也看不到你的密码——（密码）都是加密的。"**
> **"我只是把密码清了，你账户信息的内容啥都没有动。"**

| "找回密码"你以为的 | 实际发生的 |
|---|---|
| 后台把我的密码读出来告诉我 | ❌ **谁也读不出来**，存的只是加密结果 |
| —— | ✅ 后台把旧密码**清掉**，让你**重设一个新的** |
| 账号里的东西会不会没了 | **一样不动**：家目录、邮件、（游戏里的）东西都还在 |

> 📌 **所以"找回"这个词是错的，实际是"重置"。** 这也解释了为什么各大网站的"找回密码"都是让你**设新密码**，而不是"把旧密码发给你"。

## 九、`userdel`：删用户，删干净了没有

### 9.1 建一个用户，系统里不止一处留了记录

| 位置 | 建号时多了什么 | `userdel`（**不加参数**）删不删 |
|---|---|---|
| **`/etc/passwd`** | 一行（七个字段） | ✅ **删** |
| **`/etc/shadow`** | 一行（九个字段） | ✅ **删** |
| **家目录**（默认 `/home/用户名`） | 一个文件夹 | ❌ **留着** |
| **邮件目录里的邮箱文件** | 一个同名文件 | ❌ **留着** |

> 老师原话（大意）：**"（建用户的时候）这两个文件（里都）建了一个信息。实际上还有一个在哪儿？在邮件当中还牵涉到邮件——（`mail` 目录里）也有一个。"**
> 老师现场是**翻箱倒柜把它找出来的**："我记得就在这里面有一个 `mail`……就在这里边，这里边不是有一个（邮箱）吗？我们新建（的用户）就在这个里面。"

### 9.2 ⚠️ 现场：不加参数删 `u6`

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 删用户 | `userdel u6` | 没有输出 |
| 2 | 看用户总账 | `cat /etc/passwd` | `u6` 那一行**没了** |
| 3 | 看密码文件 | `cat /etc/shadow` | `u6` 那一行**也没了** |
| 4 | 看家目录 | `ls /home` | ⚠️ **`u6` 的文件夹还在** |
| 5 | 看邮件目录 | `ls /var/mail` | ⚠️ **邮箱文件也还在** |

> 老师原话（大意）：**"不加任何参数的情况下，他只是把（`/etc/passwd`）和（`/etc/shadow`）这两个文件的关联信息给删了；而在我们的家目录当中和我们的邮件信息当中，这一关联的（东西）他并没有删掉。"**

**想删干净，只能手动删**——而且老师特意点了"这是目录，得带递归"：

> 老师原话（大意）：**"想把它删掉，那这个时候你（再）删 u6 啊，你只能手动地把这两个（东西）给删掉。"**
> **"因为这是一个目录啊，目录你必须也（带递归）删他。"**

> ⚠️ **易错点**：`userdel` 删的是**"账号登记"**，不是**"账号的家当"**。删完一定要 `ls /home`、`ls /var/mail` 看一眼。

### 9.3 `-r`：连家当一起删

```bash
userdel -r u7
```

| 步骤 | 做什么 | 输入什么 | 看到什么 |
|---|---|---|---|
| 1 | 删用户，带 `-r` | `userdel -r u7` | 没有输出 |
| 2 | 看两个文件 | `cat /etc/passwd`、`cat /etc/shadow` | `u7` **都没了** |
| 3 | 看家目录、邮件 | `ls /home`、`ls /var/mail` | **也没有了** |

> 老师原话（大意）：**"通过这种方式，他会把关联的（地方）——用户文件、密码文件，还有（家目录）和邮件文件，这四个（地方）通通都会（删掉）。"**

> 💡 **一条命令记住区别**：**`-r` 的 `r` 是"连根拔"**——账号连着它的家目录、邮箱一起走。

### 9.4 `-f`：正在登录也照删

> 老师原话（大意）：**"即使你正在用，我后台也可以给你直接删掉——（就是）加个 `-f`，就是强制删除。"**
> **"你即使在用（着），我也可以给你直接删掉。"**

现场：先让一个账号登录着，管理员这边 `userdel -f 用户名` ——**照样删掉**。

> ⚠️ **易错点**：`-f` 是**强制的意思**，它不问、也不管这个人在不在线。`-r` 和 `-f` **不是一回事**：一个管"连不连家当"，一个管"要不要硬来"。

### 9.5 系统用户不要动

> 老师的态度很明确（大意）：**"（这些）系统用户，我们是不能用（的）"**、**"系统用户不动（它）算了。"**

它们和普通用户**不在一个号段**（1000 以下），是**跟着系统一起装出来的**，删了会牵连到用它的服务。

### 9.6 `userdel` 用到的就这几个

> 老师原话（大意）：**"我们常用的就是（`-r`、`-f`）这两个……其他的那些基本上（都）用不上。"**

## 十、小结

### 10.1 一条线串起来

```text
为什么要有账号：Linux 是多用户、多任务系统，没账号登不上
        ↓
useradd 用户名                 建账号（只有管理员能建）
        ↓ 建完系统里多了四处
/etc/passwd    7 列：用户名 : x : UID : GID : 说明 : 家目录 : shell
/etc/shadow    9 列：密码 + 密码的三种时间 + 账号的两种期限
家目录           /home/用户名
邮件目录         一个同名邮箱文件
        ↓
UID 定身份：0 = 超级管理员   1—999 = 系统用户   1000 起 = 普通用户
        ↓
passwd 用户名                 设密码（输的时候不显示）
        ↓ 建号时就想定死？
-u 指定 UID    -d 家目录    -s shell    -c 说明    -p 密码(⚠️明文)
-r 系统用户    -e 失效日期（临时账号）
        ↓
passwd -S  看状态（PS / LK / 无密码 / SHA-512）
passwd -l  锁（shadow 里加 !!）   passwd -u  解   passwd -d  清空（= 重置密码）
        ↓
userdel 用户名       只删两个文件里的登记，家目录、邮箱还在
userdel -r 用户名    连家目录、邮箱一起删（四个地方）
userdel -f 用户名    正在登录也照删
```

### 10.2 必须记住的几条

| 序号 | 要记住的 |
|---|---|
| 1 | Linux 是**多用户、多任务**系统，**一台机器很多账号**，没账号登不上 |
| 2 | 建账号一条命令：**`useradd 用户名`**；**只有管理员能建**，普通用户执行被拒 |
| 3 | `/etc/passwd` **七列**：用户名、`x`、**UID**、**GID**、说明、**家目录**、**shell**——**这个文件不能乱动，要动先复制** |
| 4 | **UID 定身份**：`0` 超级管理员、`1—999` 系统用户、`1000 起` 普通用户 |
| 5 | `/etc/shadow` **九列**：真正的密码在这儿；`!!` = 没密码/被锁，`*` = 系统用户，都**登不上** |
| 6 | **没设密码的账号等于没开通**——`useradd` 完必须 `passwd` |
| 7 | **`-p` 写进去的是明文**；要设密码，用 `passwd` |
| 8 | `-e` 做**临时账号**：写的是日期，`shadow` 里存的是**天数** |
| 9 | `passwd -S` 看状态、`-l` 锁、`-u` 解、`-d` 清空；**"找回密码"的真相是清掉重设，谁也读不出来** |
| 10 | `userdel` **只删登记**；要连家目录、邮箱一起删，用 **`userdel -r`**；**`-f`** 是连在线用户也删 |
| 11 | **系统用户（1000 以下）不要动** |

### 10.3 老师对"讲到什么程度"的交待

> 老师原话（大意）：**"（今天）就是把用户的信息、怎么建用户（讲一下）……（参数）牵涉了很多，你看你加不同的参数，作用不一样。"**

本节覆盖的就是：**多用户的概念 → `useradd` 建账号 → `/etc/passwd` 七列 → UID 号段 → `/etc/shadow` 九列 → `useradd` 的七个参数 → `passwd` 设密码 / 看状态 / 锁 / 解 / 清空 → `userdel` 删账号**。

老师还留下一句**明摆着的下一站**：

> 老师原话（大意）：**"（GID）一般在这儿用不上，我们后面（再）讲……（用户）组（的）时候再说。"**
