## 一、三个阶段：先看清骨架

### 1.1 三个阶段各管什么

| 阶段 | 要解决的问题 | 包含环节 |
| :--- | :--- | :--- |
| **① 输入文本理解阶段** | 把用户输入的那句话，变成机器能算的东西 | 文本预处理 → 向量化表示 → 编码与特征提取（**3 个**） |
| **② 内容决策阶段** | 决定"**写什么**" | 外部资源检索 → 逻辑推理 → 内容选择／策略生成（**3 个**） |
| **③ 输出生成文本阶段** | 决定"**怎么写出来**" | 解码器初始化 → 自回归生成 → 采样策略与多样化生成 → 生成文本优化与完善（**4 个**） |

> 💡 记忆点：**3 — 3 — 4**。前两个阶段都是三个环节，只有最后"落笔"那段是四个。

> 📌 一句话记：三个阶段里，**前两个阶段的功夫都花在"想清楚"，最后一步才真的产出文本**——理解在前、决策在中、生成在后，顺序不能倒。

### 1.2 三个阶段对应到"谁在读、谁在写"

```text
编码器 Encoder：读
  把输入的文本压成富含语义的中间表示
        │
        ▼
内容决策：想
  补外部资源、做推理、定策略
        │
        ▼
解码器 Decoder：写
  一个词一个词往外生成
```

- **编码**这一步，靠的是 **Transformer 模型里的编码器**：把向量化之后的数据送进编码器，让它提取特征。
- **解码**这一步，靠的同样是 **Transformer 模型里的解码器**。
- 一头一尾都是 Transformer 的部件，中间夹着"内容决策"——**编码器负责理解，解码器负责生成**。

## 二、阶段一：从一段文字到一组向量

### 2.1 文本预处理：清洗与分词（接上一节）

- 阶段一的第一个环节就是**文本预处理**，课上点了两件事：**清洗**和**分词**。
- **分词**是把一句话切成一个个小单位（token）；怎么切，前面已经举过例子。

> 💡 记忆点：预处理的产物是**一串 token**。后面的向量化、编码，全都是在这串 token 上做的——切错了，后面全歪。

### 2.2 向量化表示：把词放进一个有远近的空间

分完词，下一步是**把切好的词映射（嵌入）到低维空间里**，也就是给每个词配一个向量。这件事靠**词嵌入技术**实现。

```text
分词结果：  [词1]  [词2]  [词3]  …
                │  词嵌入
                ▼
向量表示：  [0.21, −0.04, …]  [ … ]  [ … ]
```

**词嵌入有两种形态**，课上明确分成两支：

| 形态 | 代表做法 | 长什么样 | 关键差别 |
| :--- | :--- | :--- | :--- |
| **离散表示** | **独热编码**（one-hot） | 一个长向量，只有一位是 1，其余全是 0 | 词与词之间**看不出远近**，向量本身不带语义 |
| **连续表示** | 词嵌入得到的**稠密向量** | 每个词是一个低维向量，几乎每一位都有值 | **语义相近的词，向量距离就接近** |

**"距离"这件事怎么看**——这是词嵌入最要紧的性质：

| 词对 | 在向量空间中的距离 | 说明 |
| :--- | :--- | :--- |
| 小汽车 ↔ 苹果 | **远** | 语义不相关 |
| 语义相近的两个词（如"国王"与"皇帝"） | **近** | 意思接近的词被放到了一起 |

> ⚠️ 易错点：**向量化不是靠"归一化"实现的**。归一化属于文本预处理（统一大小写、还原词形），向量化靠的是**词嵌入**——这两件事经常被混在一道题里考。

> 💡 记忆点：**离散靠"编号"，连续靠"位置"**。独热编码只是给每个词发了个编号，编号之间没有远近；词嵌入才把词真正摆进一个有距离的空间里。

> 📖 **教材 P35—P36 · 单元 2「2.1」阶段一（2）向量化表示**
> 把文本中的每个词映射为**低维空间中的向量**，让计算机能理解，通常通过**词嵌入（word embedding）技术**实现。目标是捕捉词语之间的语义关系，使**语义相近的词在向量空间中距离更近**——"国王"与"皇帝"的向量距离较近，"苹果"与"汽车"的向量距离较远。用向量表示数据既能**降低数据维度**，又能有效**保留词语之间的语义信息**，为分类、翻译等后续任务提供高质量输入特征。

### 2.3 编码与特征提取：把向量送进编码器

- 向量化之后，数据进入 **Transformer 的编码器**，由编码器做特征提取。
- 课上特别强调了一点：**编码器可以是一层，也可以是多层**——层数不是固定的。

| | 编码器（Encoder） | 解码器（Decoder） |
| :--- | :--- | :--- |
| **在哪一步** | 阶段一（3）编码与特征提取 | 阶段三（1）解码器初始化 |
| **干什么** | 读输入，提取特征，产出中间表示 | 依据理解结果和已生成的内容，逐个产出词 |
| **层数** | **可以一层，也可以多层** | — |

> 📖 **教材 P36 · 单元 2「2.1」阶段一（3）编码与特征提取**
> 编码器由**多个相同的层堆叠**而成，每个层都包含**多头自注意力层**和**前馈神经网络层**。多头自注意力层从多个角度捕捉文本中不同位置的语义信息——例如输入"鸟儿在天空中飞翔"，模型能确定"鸟儿"与"飞翔""天空"等词的**关联程度**，为每个词**分配不同的注意力权重**；随后前馈神经网络对多头注意力层的输出做特征提取与变换，将文本编码为富含语义信息的**中间表示向量**。

## 三、阶段二：内容决策

阶段二解决的是"**写什么**"，课上按三步讲：

### 3.1 三个环节

| 环节 | 做什么 | 课上举的例子 |
| :--- | :--- | :--- |
| **（1）外部资源检索** | 系统按照自己**理解出来的需求**，去外部取回**与需求一致的信息** | 从外部的**接口、数据库**这类来源取 |
| **（2）逻辑推理** | 把**模型内部已有的知识**和**检索回来的外部资源**结合起来，生成一个**逻辑推理的结果** | 内部知识 + 外部资源，两股并成一股 |
| **（3）内容选择／策略生成** | 在推理结果之上，选定要写的内容或定下生成策略 | — |

```text
用户的真实需求
      │
      ├──► 外部资源检索 ──► 外部信息（接口／数据库）
      │                            │
      └──► 内部已有知识 ────────────┤
                                   ▼
                            逻辑推理结果
                                   ▼
                        内容选择／策略生成
```

> 📌 一句话记：阶段二是**两个来源、一次合并**——模型脑子里的知识，加上外面查回来的资源，合起来推理，再定策略。

> 📖 **教材 P36—P37 · 单元 2「2.1」阶段二 内容决策**
> ① **外部资源检索**：根据理解的需求，从**数据库、知识图谱以及其他 API** 获取对应信息——回答特定问题时查询知识图谱获取事实或数据；处理动态内容时调用 API 获取**实时更新**的信息。② **逻辑推理**：将模型内部已有的知识与检索到的外部资源结合起来，生成**联合逻辑推理结果**。③ **内容选择或策略生成**：根据逻辑推理的结果选择最合适的内容或生成策略，例如从训练数据中抽取相关信息，或根据**预先设定的规则**选择最佳响应。

> ⚠️ 易错点：三个阶段里，**只有阶段二会去"外面拿东西"**。阶段一（预处理、向量化、编码）和阶段三（解码生成）都在模型内部完成，别把"检索"记到阶段一或阶段三头上。

## 四、阶段三：解码、采样与幻觉

### 4.1 四个环节

| 环节 | 干什么 |
| :--- | :--- |
| **（1）解码器初始化** | 由 Transformer 的**解码器**接手，准备开始生成 |
| **（2）自回归生成** | 一个词一个词地往下写 |
| **（3）采样策略与多样化生成** | 不只是挑概率最高的词，还要让输出有变化 |
| **（4）生成文本优化与完善** | 对生成结果做评估与修补 |

### 4.2 自回归生成

课上只讲到了这个环节的名字；它的机制在教材里写得更细：解码器**从左到右依次生成每个词**，每生成一个新词，都要同时看**编码器的输出**和**已经生成的内容**，最后得到一个"所有可能词的概率分布"，再从中选出下一个词。

```text
编码器的输出 ──┐
                ├──► 注意力权重 ──► 概率分布 ──► 选出下一个词
已生成的文字 ──┘                                    │
        ▲                                          │
        └────────── 接回已有内容，继续生成 ◄────────┘
```

> 📖 **教材 P36—P37 · 单元 2「2.1」阶段三 输出生成文本**
> ① **解码器初始化**：解码器的输入包括**对原文的理解结果**以及**此前已经生成的内容**；生成第一个词时，使用一个特殊的**起始标记向量**作为输入。② **自回归生成**：从左到右依次生成每个词，多头自注意力层同时关注**编码器的输出**和**已生成的信息**，再由前馈神经网络生成一个表示**所有可能单词的概率分布向量**——例如"花朵在［生成位置］绽放"，若"花园"的概率最高，模型便选择"花园"。

### 4.3 采样策略：为什么每次结果不一样

- 模型除了会选**概率最高**的那个词之外，还会采用一些**采样策略**。
- 采样策略的作用是**让生成结果更多样**——同一个提示词，不一定每次都给同一段文字。

> 📖 **教材 P36—P37 · 阶段三（3）采样策略与多样化生成**
> 为增强生成文本的多样性，模型除选择**概率最高的单词**外，还会采用一些采样策略，例如**温度采样（temperature sampling）**：通过调整概率分布的"**尖锐度**"，使模型有一定可能选择概率较低的单词，从而生成**更具创意性**的文本。

### 4.4 生成文本的优化与完善

- 生成的文本**质量一般非常高**，但仍然要做**优化与完善**这一道。
- 这道环节要检查的是**流畅性、连贯性、语义合理性**这类东西；结果不达标，就重新生成或局部修改。

> 📖 **教材 P36—P37 · 阶段三（4）生成文本优化与完善**
> 使用大语言模型对生成文本进行评估，检查其**流畅性、连贯性和语义合理性**；若评估结果**低于预设阈值**，系统可能重新生成文本或对现有文本进行调整，如**语法修正、敏感性检查、重复内容过滤**等操作。

### 4.5 文本幻觉：写得顺，不等于写得对

- 课上明确点出：生成质量再高，**仍会出现"人工智能幻觉"**。
- 幻觉的表现是两类：**内容上的错误**，以及**语义模糊**。

> ⚠️ 易错点：**"通顺"和"正确"是两件事**。文本读起来很顺、很像人写的，不代表里面的信息都对——幻觉恰恰最容易藏在很流畅的段落里。所以生成结果必须人来核。

> 📌 一句话记：**质量高 ≠ 零错误**；AIGC 的输出要过一遍人的眼睛，这一条在两个实践任务里都要用。

## 五、文本生成工具：写作工具与智能对话工具

### 5.1 写作工具：任务导向型

写作工具是**以任务导向为主**的——先得有一个明确目标，它才知道往哪儿写：

| 场景 | 首先要说清的东西 |
| :--- | :--- |
| 写一篇文章 | 要写一篇**什么样**的文章 |
| 发一封邮件 | 要发一封**什么样**的邮件 |
| 写一篇新闻稿 | 这篇新闻稿的**主题**是什么 |

## 六、提示词设计：课本三步 + 几条硬技巧

### 6.1 课本上的三步，课上各点了重点

| 步骤 | 课上强调的地方 |
| :--- | :--- |
| **① 明确生成目标** | **越具体越好**。写一首诗和写一篇文章，"风格"的要求完全不是一回事；写新闻、写报告这类场景，要明确要求**正式** |
| **② 细化需求要点** | 最常用的是**字数**——"不超过多少字"；还要给**受众**（面向谁必须说清）、**语言、背景**，以及**限制条件**（比如不许使用专业术语） |
| **③ 测试和迭代优化** | 一次写不完美，要一轮一轮改；典型情况是**关键信息缺失**，那就针对缺的那块补要求 |

> 💡 记忆点：三步的关键词——**具体 → 细化 → 迭代**。少一步，提示词就停在"半成品"。

> 📌 一句话记：提示词的核心不在"一次写对"，而在**写完还要审、还要改**——课上把这一点称作提示词的本质。

> 📖 **教材 P46—P47 · 单元 2「2.3」提示词设计 3 步**
> ① **明确生成目标**：目标应具备**具体性**（越具体越有利于准确生成）与**独一性**（只设一个生成目标，避免多个目标导致内容杂乱）。② **细化需求要点**：7 个常见维度——**风格、字数、受众、目的、语言、背景、限制条件**。③ **测试和迭代优化**：常见偏差有 **3 类**——**内容缺失**（参数显性化、场景具象化）、**表达精确性差**（风格锚定、细化受众画像）、**逻辑失衡**（分步骤下达指令、优先级标注）。

### 6.2 三条能直接照着写的技巧

课上把书上的做法归纳成一组技巧，逐条讲透的是下面三条：

| 技巧 | 怎么做 | 反例 → 正例／说明 |
| :--- | :--- | :--- |
| **① 目标要具体** | 不要只说"写一段介绍"，把**受众、字数、格式**一起给进去 | ❌ 写一段介绍 → ✅ 面向某类读者、给一个字数范围、按某种体例来写 |
| **② 给模型一个身份** | 指定它的**角色**：老师、学生、程序员、文员…… | 不说身份，它只能写得很泛；说了身份，生成的内容才**更贴切** |
| **③ 加限定条件** | 明确**禁止它胡乱编造**，把边界写死 | 不写边界，它就敢编；写了边界，**AI 幻觉会明显减少** |

**"格式"这条要单独记**：写**通告**这类东西，就要按**公文的格式**来要求——格式说错，内容再好也不能用。

> ⚠️ 易错点：三条技巧不是"三选一"，而是**叠着用**。只给目标不给身份，写出来没人味；只给身份不给限定，它就敢编；只给限定不给目标，它又不知道写什么。

> 🔧 三条技巧合起来的样子（示意）：

```text
【身份】你是一名_____（老师／程序员／文员……）
【目标】写一篇关于_____的_____
【受众】面向_____（年龄、身份、专业背景）
【篇幅】不超过_____字
【格式】按_____（公文／公众号推文／报告）的体例
【限制】不要编造数据；不确定的地方标注"待核实"；不使用_____这类词
```

### 6.3 提示词是要迭代出来的

- 提示词不可能一稿到位，**要一轮一轮优化**。
- 判断标准很直接：看它生成的内容**符不符合要求**，不符合就改提示词再发一次。
- 迭代的两个常见抓手：**补上缺失的关键信息**、**把模糊的要求说死**（明确受众、明确篇幅、明确格式）。

### 7.1 课题报告是什么

### 7.2 任务情境的三要素

| 要素 | 本例的取值 |
| :--- | :--- |
| **写作者角色** | 一名优秀的**初中教师**，对中学生课后辅导模式做过**长期调研**，积累了丰富经验 |

### 7.3 提示词里必须写进去的四件事

| 必写项 | 为什么非写不可 |
| :--- | :--- |
| **课题报告的名称** | 不告诉它名字，它就没有明确方向，写出来是很泛的东西 |
| **课题报告的受众** | 受众决定用词和详略——这份是给**学校管理人员**看的 |
| **课题报告的核心结论** | 结论就是报告的"论点"，先给论点，它才知道各部分往哪儿靠 |
| **大纲标题的数量** | 直接指定数量，一般让它写**五个或六个** |

**核心结论要原样写进提示词**（这是本任务的固定内容）：

> 现有模式在**资源分配**和**个性化辅导**方面存在显著不足，建议通过**整合教育资源、引入智能化教育工具**，以及**强化家校社三方联动**，建立更加灵活和高效的辅导体系。

> ⚠️ 易错点：**核心结论不是让模型自己想出来的**，是你在提示词里给它的。顺序是"先有结论，再让它铺开成报告"，不是"让它写完再总结结论"。

> 📖 **教材 P50—P52 · 实践任务 2-2 步骤 1 的提示词原文**
> 假设你是一名优秀的**初中教师**，请你为一篇课题报告撰写一份大纲，要求如下。
> （1）课题报告的名称：中学生课后辅导模式优化。
> （2）课题报告的受众：学校的管理人员。
> （3）课题报告的核心结论：现有模式在**资源分配**和**个性化辅导**方面存在显著不足，建议通过**整合教育资源、引入智能化教学工具**，以及**强化家校社三方联动**，建立更加灵活和高效的辅导体系。
> （4）大纲标题数量：不少于 3 个大纲标题。

> 📌 数量这一项，教材原文写的是"**不少于 3 个**"，课上给的经验是"**一般指定五个或六个**"——两种写法都指向同一件事：**把数量明确写进提示词**，别让它自己定。

### 7.4 两条生成路径

```text
路径 A（教材写的：分阶段）
   写大纲提示词 ──► 生成大纲 ──► 人工核对／修改 ──► 写报告提示词 ──► 生成报告

路径 B（更省事的做法）
   一次把提示词写全 ──► 先拿回一份大纲 ──► 认可后让它照大纲出报告
                     （或直接让它出报告，再回头核大纲）
```

- **路径 A** 就是 2-1 用过的"分阶段设计提示词"：先大纲、再正文，两头都有人工复核。
- **路径 B** 的差别在于**步骤被压短**：提示词一次给全，让它先出大纲、再出报告，不必再单独写一遍"文章提示词"。
- 两条路径的共同点没有变：**每一步的结果都要人看一眼**，大纲不合意就改大纲或重生成，报告不合意就重生成。

> 💡 记忆点：**流程可以短，"复核"不能省**。路径 B 省的是写提示词的工夫，不是省核对。

### 7.5 大纲一般长什么样

课上给的经验是：课题报告的写法**和写论文差不多**，大纲一般按这个顺序铺开——

| 顺序 | 一级标题（大意） |
| :--- | :--- |
| 一 | **研究背景与意义** |
| 二 | **现有辅导模式的现状分析** |
| 三 | **现有问题的成因研究** |
| 四 | **优化方案**（对策） |
| 五、六 | 视需要再加（实施安排、预期成效之类），数量可指定 |

> 📖 **教材 P51—P52 · 实践任务 2-2 步骤 2：豆包生成的 6 个部分**
> 一、研究背景与意义；二、现有课后辅导模式现状分析；三、现有模式问题成因探究；四、课后辅导模式优化策略；五、优化方案实施计划；六、预期成效与评估方法。**注意**：若大纲的内容详略、板块设置与预期存在偏差，可将大纲**复制到文本文档中手动修改**，也可输入**修改意见重新生成**。

### 7.6 生成报告的那一句提示词

基于已经认可的大纲，直接在输入框里发一句就行：

> 请根据生成的大纲生成对应的课题报告，需要确保生成的课题报告内容正确、严谨。

- 还可以在这句后面**追加约束**，比如限定篇幅"**不超过一千字**"。
- 之所以能"顺着大纲写"，是因为**豆包会把当前对话的历史信息当作上下文参考**——前面写的大纲提示词、它生成的大纲，都在上下文里，所以它理解得更准。

> ⚠️ 易错点：**换一个新建对话，上下文就断了**。要让它接着大纲写，就得在**同一个对话**里往下说，别中途开新窗口。

> 📖 **教材 P52—P55 · 实践任务 2-2 步骤 3、步骤 4**
> 在输入框中输入提示词，例如"**请根据生成的大纲生成对应的课题报告，需要确保生成的课题报告内容正确、严谨**"，然后单击发送按钮；不满意可以单击**重新生成**。教材同时给出风险提示：AIGC 文本生成工具生成内容的**准确性和真实性无法百分之百保证**，用户需要具备相应的**鉴别能力**。

## 八、本节要记住的清单（复习用）

1. **文本生成三大阶段**：输入文本理解 → 内容决策 → 输出生成文本，环节数为 **3 — 3 — 4**。
2. **阶段一三环节**：文本预处理（清洗、分词）→ 向量化表示（词嵌入）→ 编码与特征提取（Transformer 编码器）。
3. **词嵌入两种形态**：**离散表示**（独热编码 one-hot）与**连续表示**（稠密向量）；前者看不出远近，后者**语义近则距离近**。
4. **向量化靠词嵌入，不是靠归一化**——归一化属于文本预处理。
5. **编码器可以一层，也可以多层**；编码器负责"读"，解码器负责"写"，两者都是 Transformer 的部件。
6. **阶段二三环节**：外部资源检索 → 逻辑推理（内部知识＋外部资源）→ 内容选择／策略生成。
7. **阶段三四环节**：解码器初始化 → 自回归生成 → 采样策略与多样化生成 → 生成文本优化与完善。
8. **采样策略**让输出多样化：不只挑概率最高的词，还会留出选低概率词的可能。
9. **人工智能幻觉**：生成质量高也可能出错，表现为**内容错误**与**语义模糊**；通顺不等于正确。
10. **写作工具是任务导向型**，支持**结构化写作**（模板／规则，公文、新闻稿）与**创作型写作**（开放自由，营销文案、故事）。
11. **新华妙笔**：公文平台，权威性高，面向党政机关／事业单位／国企央企；界面对不上教材截图，但不影响使用。
12. **DeepSeek 四大优势**：**长**（比同类开源模型长，多数开源模型 4~32K）、**省**（价格低约 30%）、**通**（标准格式兼容，省迁移成本）、**快**（推理更快）；V／R 系列**数字越大版本越新**。
13. **豆包四功能**：自然语言交互、文本创作、编程辅助、多模态处理（含文生图、语音转文字）。
14. **提示词三步**：明确目标（具体）→ 细化需求（字数、受众、语言、背景、限制条件）→ 测试迭代。
15. **提示词三条硬技巧**：目标具体、**给身份**、**加限定条件**（禁编造，压幻觉）；格式要说明（通告用公文格式）。
16. **课题报告提示词四要素**：名称、受众、**核心结论**、大纲标题数量；核心结论是**你给它的**，不是它总结的。
17. **课题报告流程**：先大纲、后正文，两头都要人核；豆包靠**同一对话的上下文**接着大纲写。
