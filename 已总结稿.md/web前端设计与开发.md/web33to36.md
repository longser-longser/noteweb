# 网页前端设计与开发 课堂笔记（第 33—36 节）——DOM 的节点树、节点关系与获取页面元素的方法

> 前面几节把**对象**讲完了——对象怎么造、成员怎么访问、方法怎么调。老师的原话是："学完了这个对象以后，我们就可以真正地进入网页交互效果的制作了。"这一节就是那扇门：**DOM（Document Object Model，文档对象模型）**。整节的因果链是：要让页面"动"起来（轮播、缩略图放大、点击变色）→ 程序得先**抓住**页面上的元素 → 要抓元素，先得知道页面是**一棵树**（`html` 是根节点，`head` 和 `body` 是它的两个亲儿子）→ 树上的每一个点叫**节点**，节点分**元素节点 / 文本节点 / 文档节点**→ 节点之间只有三种关系（**父子、兄弟、祖先与后代**），关系不清就找不准目标 → 于是有了四类取元素的方法：`getElementById`（按 id，拿**一个**）、`getElementsByTagName`（按标签名，拿**集合**）、`getElementsByClassName`（按类名，拿集合）、`querySelector` / `querySelectorAll`（按 **CSS 选择器**，拿一个 / 拿集合）→ 集合不是元素，必须**按下标 `[0]` 取**，而且它是"类数组对象"，数组的方法一概用不了 → 最后把镜头拉到整个文档：`document.documentElement`、`document.body`、`document.images`，以及 `document.title` 的读与写。
>
> 文中代码按浏览器里能直接运行的写法补全，只使用本节讲过的 API；示例页面统一用 2.1 的 `demo.html`。

### ⛓ 本节主线（一条因果链）

```text
落点：想让页面"动"起来（轮播、缩略图放大、点击变色……）
        ↓ 程序凭什么动得了页面？
DOM：把 HTML 文档变成一堆"对象"（文档对象模型），JS 通过它操作页面
        ↓ 它长成什么样？
一棵树：根是 html，它有两个亲儿子 head、body，然后一路往下分叉
        ↓ 树上的每一个点叫什么？
节点：元素节点（所有标签）／文本节点（标签里的字）／文档节点（<!DOCTYPE html>）
      查类型用 nodeType（数字），查名字用 nodeName
        ↓ 这些点之间是什么关系？
父子（直接上下）／兄弟（同一个爹）／祖先与后代（隔了好几层）
      关系不清 → 找不准目标；关系清楚 → 才能"先抓一个，再顺着往下找"
        ↓ 第一步：把元素"抓"到手里
① document.getElementById("id名")         → 一个元素（id 唯一）
② document.getElementsByTagName("标签名")  → 集合（有几个给几个）
③ document.getElementsByClassName("类名")  → 集合（类名可以共用）
        ↓ 集合不等于元素，怎么用？
按下标：[0]、[1]、[2]……；只能按下标，sort / reverse / slice 一概没有
      只有一个元素也是集合；没有元素就是空集合；页面加了元素，集合跟着变
        ↓ 还有更省事的办法吗？
④ document.querySelector("选择器")    → 第一个
   document.querySelectorAll("选择器") → 全部（集合）
   参数必须写成 CSS 选择器的样子：.类名、#id、标签名
        ↓ 想要整个页面，而不是某一个标签？
document.documentElement → html 元素
document.body            → body 元素
document.images          → 所有图片
document.title           → 读标题；document.title = "新标题" → 改标题
        ↓
落点：抓到元素之后，才谈得上"注册事件、改属性、改样式"
```

### 🔗 去路：本节内容后面用在哪里

| 本节内容 | 后面 / 实际做网页时用在哪里 |
|---|---|
| **DOM 树与节点关系** | 老师当堂说的用处：抓到一个元素之后，还要能"对它的子节点进行操作"；结构一复杂，就得靠关系一层层找 |
| **`nodeType` / `nodeName`** | 拿到一个节点、吃不准它是什么的时候，先打印出来确认，再决定怎么处理 |
| **四类取元素的方法** | 后面所有交互效果的第一步都是"选元素"——轮播、缩略图放大、点击变色、表单校验 |
| **按下标访问集合** | 一组列表项、一组复选框，凡是要处理"第几个"，全靠下标 |
| **`querySelector` / `querySelectorAll`** | 复杂条件（"某个盒子里的 `li`"）用一句选择器就能定位，比按标签名一层层找省事 |
| **`document.title` 的读写** | 页面标题跟着内容变——当前栏目名、未读消息数 |
| **下一段路：注册事件** | 老师说得很明确：取到元素之后要"给这个元素去注册事件"，在事件里改 `src`、改属性、改样式，才算真交互 |
| **再往后：BOM** | 老师说的第 5 件事："这个是操控浏览器的，可以让浏览器做出一系列的反应——放大呀、缩小呀、滚动呀等等" |

## 一、先给"操作页面"这件事定位：DOM 是干什么的

### 1.1 上一段路停在哪儿

> ★ 老师的话：**"上周主要是学习了那个对象的概念，及如何去处理对象这种特殊的数据形式……学完了这个对象以后，我们就可以真正地进入网页交互效果的制作了。"**

| | 前面（对象） | 本节（DOM） |
|---|---|---|
| 学的是 | 怎么造对象、成员怎么写、属性方法怎么访问 | 页面上的元素**本身**就是对象 |
| 练的动作 | `obj.name`、`obj.say()` | `document.title`、`document.getElementById(...)` |
| 落到哪儿 | 数据 | **页面本身**——摸得到、改得动 |

> 💡 **记忆点**：DOM 不是一套新语法，是**一批新对象**。语法还是"对象.成员"，只是这回对象的另一头连着真实的网页。

### 1.2 一句话说清 DOM 能干什么

> ★ 老师的话：**"使用 DOM 可以获取元素、操作元素的内容、属性以及修改元素的样式，从而实现网页交互效果。"**

| 能做的 | 具体指什么 | 老师当堂举的例子 |
|---|---|---|
| **获取元素** | 把页面上某个标签抓到程序里 | "轮播的话，我们需要先选中这个页面上的这张图片" |
| **操作内容与属性** | 改标签里的字、改标签上的属性 | "改变这张图片的 `src`，你就换一张"；表单元素改 `name`、`type` |
| **修改样式** | 颜色、宽度、高度…… | "这些都是属于元素的样式" |

> ★ 老师的定位：**"以后还会再学习一个 BOM，这个是操控浏览器的，可以让浏览器做出一系列的反应，比如说放大呀、缩小呀、滚动呀等等。"**——**DOM 管页面里的东西，BOM 管浏览器本身**，这一节只管前者。

### 1.3 "接口"这个词：DOM 也是一套接口

> ★ 老师的话：**"它是软件系统预先定义的接口，用于衔接……"**

老师拿手机打比方：手机上的人脸识别 App 要用前置摄像头，中间就得有一层**接口**，程序只管调，不用管摄像头怎么驱动。

> ★ 老师的话：**"在 JS 里面，所有的对象都是接口。这些接口都被封装成对象来实现了一些功能。那我们去用的时候，只需要……去使用它的属性和方法，调用就可以了。"**

所以本节所有动作，归根到底都是"**找到对象 → 访问属性 / 调用方法**"。拿最熟的 `console.log` 拆一下：

```js
console.log("在控制台输出一句话");
//  ↑     ↑
// 对象   方法（要加一对小括号）
```

> ★ 老师的话：**"它里面加了一个点……这个语法格式，就是在控制台调用的一个输出方法。"**

| 写法 | 谁是对象 | 谁是成员 | 成员是属性还是方法 |
|---|---|---|---|
| `console.log(...)` | `console` | `log` | 方法（加括号） |
| `document.title` | `document` | `title` | 属性（**不**加括号） |
| `document.getElementById(...)` | `document` | `getElementById` | 方法（加括号） |

> 💡 **记忆点**：本节从头到尾只有一个对象——**`document`**。`getElementById`、`body`、`title` 全是它身上的成员。

### 1.4 学 DOM 的路线图（老师当堂列的）

> ★ 老师的话：**"首先要了解什么是节点、节点与节点之间的关系……在元素嵌套的情况下，它们就存在了一个父子关系，还有兄弟关系。这个是比较重要的，大家需要掌握。因为只有你知道了它们之间的这种关系以后，才能对网页元素进行操作。"**

| # | 做什么 | 老师的原话 |
|---|---|---|
| ① | 认识节点、认节点之间的关系 | "首先要了解什么是节点" |
| ② | 看清页面的树形结构 | "我们得非常清楚一个页面结构分为哪几个部分" |
| ③ | **获取元素** | "我们需要先选中这个页面上的这张图片——选取某一个元素，这是我们要学习的：要获取元素" |
| ④ | **注册事件** | "要给这个元素去注册事件" |
| ⑤ | 在事件里改内容 / 属性 / 样式 | "注册完了事件之后，在这个事件里面去操作元素" |

把 ④⑤ 串起来就是一条完整的交互链，老师举的是购物网站：

| 步骤 | 发生什么 |
|---|---|
| ① | 页面上有一排缩略图 |
| ② | 鼠标移到某张缩略图上——**鼠标事件** |
| ③ | 在事件里把这张图放大 |
| ④ | 鼠标移开，恢复原样 |

> ★ 老师的话：**"通过掌握这些方法，我们就可以对页面上的元素进行动态的改变了，并且呢和用户的操作进行绑定。"**——**绑定**这个词是本节和下一段路的分界。

## 二、DOM 树：一个页面就是一棵树

### 2.1 HTML 本来就是一棵树

> ★ 老师的话：**"之前学习 HTML 的时候……它这是一个树形结构，树根在上面。"**

本节后面所有例子都用这个页面（老师当堂搭的也是这个结构：一个大标题、一个超链接、一个盒子里放图片和文字，再加一个列表）：

```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>DOM 示例页</title>
</head>
<body>
    <h1 id="title">我的第一个页面</h1>
    <a href="#">一个超链接</a>
    <div id="box" class="box">
        <img src="pic.jpg" alt="一张图片">
        <p>盒子里的一段文字</p>
    </div>
    <ul id="nav">
        <li class="item">小花</li>
        <li class="item">小红</li>
        <li class="item">小强</li>
    </ul>
</body>
</html>
```

把它画成树：

```text
document（文档节点）
└── html（根节点，元素节点）
    ├── head（元素节点）
    │   ├── meta（元素节点）
    │   ├── meta（元素节点）
    │   └── title（元素节点）
    │       └── "DOM 示例页"（文本节点）
    └── body（元素节点）
        ├── h1（元素节点）
        │   └── "我的第一个页面"（文本节点）
        ├── a（元素节点）
        │   └── "一个超链接"（文本节点）
        ├── div（元素节点）
        │   ├── img（元素节点）
        │   └── p（元素节点）
        │       └── "盒子里的一段文字"（文本节点）
        └── ul（元素节点）
            ├── li（元素节点）→ "小花"
            ├── li（元素节点）→ "小红"
            └── li（元素节点）→ "小强"
```

> ★ 老师的话：**"他们是像一棵树一样……但是它是一棵树，根在最上面。"**

### 2.2 根节点：`html`

> ★ 老师的话：**"html 它是所有节点的上级，它是根节点。"** 并追了一句：**"它没有任何的父节点。"**

> ★ 老师的话：**"他们的亲儿子是谁呢？……有两个亲儿子，一个是 head，一个是 body。"**

| 位置 | 是谁 | 说明 |
|---|---|---|
| 最外层 | `document` | 整个文档（对象） |
| **根节点** | `html` | 页面里最大的那个标签，**没有父节点** |
| 第二层 | `head`、`body` | `html` 的**两个亲儿子**，互为兄弟 |

> ★ 老师的话：**"我们整个页面上所有的元素都是在 html 里面。"**——页面上加的盒子、图片、列表，一个都跑不出 `html`。

### 2.3 `head` 里的三个节点，和 `body` 里的元素

老师带着大家数 `head`：第一个是编码格式 `<meta charset="UTF-8">`，第二个是 `<meta name="viewport" …>`，第三个是 `<title>`。

> ★ 老师的话：**"三个节点都是属于 head 节点里面的内容，也可以说是它的儿子。"**

`body` 同理：页面上看得见的东西全在 `body` 里；`body` 里只放了一个 `div`，那这个 `div` 就是 `body` 的子节点。

### 2.4 为什么非得会看这棵树

> ★ 老师的话：**"你一到网页，就要（知道）里面元素的结构，谁是谁的（节点），一定要清楚，特别是出现元素嵌套的这种情况下。"**

> ★ 老师的话：**"这个图是每次学习这个（部分）都要求大家会画的。"**——画图不是形式，是为了**在脑子里先把关系摆平**，再去写代码。

> 💡 **记忆点**：画树三步——先找**根**（`html`）→ 再找它的**亲儿子**（`head`、`body`）→ 最后顺着嵌套一层层往下挂。**挂在谁下面，就是谁的儿子。**

## 三、节点是有类型的：元素节点、文本节点、文档节点

### 3.1 三种常见节点

> ★ 老师的话：**"这个元素里面呢，它的节点是有分类的。"** 本节要认清的是三类：

| 节点类型 | 指什么 | 例子 |
|---|---|---|
| **元素节点** | 页面里**所有的标签**，不管双标签还是单标签，只要是用尖括号括起来的 | `div`、`img`、`p`、`h1`~`h6`、`a`、`ul`、`li` |
| **文本节点** | 标签**里面**的那些文字 | `h1` 里的标题字、`p` 里的段落字、`div` 里的文字 |
| **文档节点** | `<!DOCTYPE html>` 代表的这个文档本身 | `<!DOCTYPE html>` |

> ★ 老师的话：**"元素节点指的是页面中所有的标签。"** 并举例：盒子（`div`）、图片（`img`）、段落（`p`）、`h1` 到 `h6`，"所有这些都是标签……都叫元素节点"。

> ★ 老师的话：**"这里面全都是文字……这个叫文本节点。"**——新闻网站的正文，一行一行看上去是文字，在 DOM 里是文本节点。

> ★ 老师讲文档节点的话：**"我的这个代码是用（HTML）语言写的，你就这样给我解析就行了……这就代表了咱们这个文档。"**

> 💡 **记忆点**：**标签是元素节点，标签里的字是文本节点，`<!DOCTYPE html>` 是文档节点。**一句话：**皮是元素，馅是文本，整张饼是文档。**

### 3.2 `nodeType`：用数字查类型

> ★ 老师的话：**"如果你不清楚这个节点的类型是什么，你可以用 nodeType 去获取一下，打印到控制台看一看。"**

| 节点类型 | `nodeType` 的值 |
|---|---|
| 元素节点 | `1` |
| 文本节点 | `3` |
| 文档节点 | `9` |

```js
// 接着 2.1 的 demo.html
var box = document.getElementById("box");
console.log(box.nodeType);   // 1  → 元素节点
```

> ★ 老师的话：**"如果你去获取到文本节点，它表示出来的这个结果是 3，它是用数字表示的。"**

> ⚠️ **易错点**：`nodeType` 是**属性**，后面不加小括号；它给的是**数字**（`1` / `3` / `9`），不是 `"div"` 这样的字符串。想要名字，用下面 3.3 的 `nodeName`。

### 3.3 `nodeName`：节点的名字

> ★ 老师的话：**"这个内容就是节点的名称，可以获取（节点的）名称。"**

```js
var box = document.getElementById("box");
console.log(box.nodeName);   // DIV
```

| 属性 | 给什么 | 例 |
|---|---|---|
| `nodeType` | 一个**数字** | `1` |
| `nodeName` | 节点的**名字**（元素节点给的是大写的标签名） | `DIV`、`P`、`IMG` |

> 💡 **记忆点**：`nodeType` 回答"**它是什么类**"，`nodeName` 回答"**它叫什么**"。

## 四、节点之间的关系：父子、兄弟、祖先与后代

### 4.1 三种关系一览

> ★ 老师的话：**"还有一种关系，叫做祖先和后代的关系……就是除了（直接的）父子关系以外，还有爷爷（和孙子）……或者更（远）一些。"**

| 关系 | 定义 | 在 2.1 的页面里 |
|---|---|---|
| **父子** | 直接上下两层 | `html` ↔ `head`；`div` ↔ `img`；`ul` ↔ `li` |
| **兄弟** | **同一个父节点**下的两个子节点 | `head` ↔ `body`；`h1` ↔ `a` ↔ `div` ↔ `ul`；三个 `li` 之间 |
| **祖先与后代** | 隔了一层或好几层 | `html` 是 `p` 的祖先，`p` 是 `html` 的后代 |

### 4.2 父子：谁是谁的爹

> ★ 老师的话：**"父节点指的是某一节点的上级节点，相对来说，子节点就是某一节点的下级节点。"**

| 说法 | 意思 |
|---|---|
| 父节点 | 包着我的那一层 |
| 子节点 | 我包着的那一层 |

### 4.3 兄弟：同一个爹

> ★ 老师的话：**"兄弟关系就是同一个父节点的两个子节点。"**

老师当堂连着问了几句"这几个是不是兄弟"，答案整理成表：

| 这几个元素 | 同一个父节点吗 | 是不是兄弟 |
|---|---|---|
| `head`、`body` | 都是 `html` 的儿子 | **是** |
| 两个 `meta`、`title` | 都是 `head` 的儿子 | **是** |
| `h1`、`a`、`div`、`ul` | 都是 `body` 的儿子 | **是** |
| 三个 `li` | 都是 `ul` 的儿子 | **是** |
| `h1` 和 `img` | 一个在 `body` 下、一个在 `div` 下 | **不是**（是祖先与后代） |

> ⚠️ **易错点**：兄弟看的是**同一个父节点**，不是"打印出来挨着"。`h1` 和 `img` 在页面上离得近，但它们的父节点不同，所以不是兄弟。

### 4.4 祖先与后代：和 CSS 两种选择器对得上

> ★ 老师的话：**"我们之前在学习选择器的时候……有子代选择器，有后代选择器……子代选择器只能选择亲儿子，而后代选择器（能选所有后代）。"**

| CSS 选择器 | 选谁 | 对应本节的关系 |
|---|---|---|
| `div > p`（子代选择器） | 只选 `div` 的**亲儿子** `p` | 父子 |
| `div p`（后代选择器） | 选 `div` 里**所有层级**的 `p` | 祖先与后代 |

> ★ 老师的话：**"所以在这里我就要明白他们之间的这个层级关系。"**

> 💡 **记忆点**：问"`html` 和 `p` 什么关系"，**不能**答父子——它们中间隔着 `body`、`div`，答案是**祖先与后代**。

### 4.5 嵌套列表：关系一下就变复杂

老师在 `ul` 例子上又加了一层：某个 `li` 里再嵌一个 `ul`。

```html
<ul id="nav2">
    <li>首页</li>
    <li>课程
        <ul>
            <li>HTML</li>
            <li>CSS</li>
            <li>JavaScript</li>
        </ul>
    </li>
    <li>关于</li>
</ul>
```

```text
ul#nav2
├── li（首页）
├── li（课程）
│   └── ul
│       ├── li（HTML）
│       ├── li（CSS）
│       └── li（JavaScript）
└── li（关于）
```

| 问 | 答 |
|---|---|
| "首页""课程""关于"三个 `li` 什么关系 | 兄弟（同一个 `ul` 的儿子） |
| 里层 HTML / CSS / JavaScript 三个 `li` 什么关系 | 兄弟（同一个里层 `ul` 的儿子） |
| 里层的 `li` 和"首页"什么关系 | **不是兄弟**，是后代与祖先 |
| 里层的 `li` 和"课程"那个 `li` 什么关系 | 父子（中间只隔一个 `ul`） |

> ★ 老师的话：**"后代啊，就不是直接连的了，是后代和祖先的关系。像这种稍微复杂一点的嵌套元素……"**

老师顺势说了这件事的实战意义：要改"某个 `ul` 里某个 `li`"的内容，得**先拿到那个 `ul`，再往下找它的后代**。

> ★ 老师的话：**"我需要在（id 等于 nav 的）这个元素里面去寻找它的后代……需要通过（一层一层）先找到它（父亲），再去找。"**

> 💡 **记忆点**：判断两个节点的关系，只看**离它们最近的共同父节点**——是同一个，就是兄弟；不是同一个，就往上看，看谁是谁的祖先。

## 五、获取元素（一）：按 id 取——`getElementById`

### 5.1 先得有个名字：`id` 是唯一标识

> ★ 老师的话：**"元素的 id 属性是元素的唯一标识。所以说我用它来获取元素的话，（只能）选中一个（目标）。"**

联系前面学过的 CSS：样式表里用 `#id名` 给这个元素设样式，就是靠这个唯一标识认人的。

| 属性 | 能不能重复 | 用来干什么 |
|---|---|---|
| `id` | **不能**，页面里唯一 | 精确锁定**一个**元素 |
| `class` | 可以，多个元素共用 | 一次锁定**一组**元素（见第七节） |

### 5.2 语法

```js
var nav = document.getElementById("nav");
console.log(nav);        // <ul id="nav">…</ul>
```

| 部分 | 写什么 | 注意 |
|---|---|---|
| `document` | 对象（当前文档） | 每次都要从它出发 |
| `.` | 点 | 访问成员 |
| `getElementById` | 方法名 | **Element 是单数**，中间没有 s |
| `("nav")` | 括号里是 id 的**值** | 只写 id 的值，**不加 `#`** |

> ★ 老师的话：**"这个名字类似于（给元素起的）名字……我们第一步还是要先（给元素）命名。"**——`id` 是在 HTML 里先写好的，JS 只是拿这个名字去认人。

> ★ 老师还提醒过一句：不用把方法名的每个字母都背下来，"在（`document.`）里面只要打出来，它就有各种方法"——编辑器会给提示。

### 5.3 打出来验证一下

> ★ 老师的话：**"（打印）看看我们是不是成功地获取到了这个 ul。"**

```js
var nav = document.getElementById("nav");
console.log(nav);   // 能展开看到里面的三个 li，说明抓到了
```

### 5.4 返回的是"一个"元素

| 方法 | 返回 | 能不能直接操作 |
|---|---|---|
| `getElementById("nav")` | **一个**元素 | 能，它本身就是元素 |

> ★ 老师要求学生随时分得清的一件事：**"获取过来的元素是单一的还是多的集合。"**

> ⚠️ **易错点**：① 参数里加了 `#`（写成 `getElementById("#nav")`）取不到东西；② 页面里给两个元素写同一个 `id`，`getElementById` 只认第一个——**id 不能当类名用**。

## 六、获取元素（二）：按标签名取——`getElementsByTagName`

### 6.1 语法

```js
var lis = document.getElementsByTagName("li");
console.log(lis);          // HTMLCollection(3) [li, li, li]
console.log(lis.length);   // 3
```

| 部分 | 写什么 | 注意 |
|---|---|---|
| `getElementsByTagName` | 方法名 | **Elements 有 s**——一次可能拿回好几个 |
| `("li")` | 标签名 | **不加尖括号**，也不加点 |

> ★ 老师的话：**"（标签名）指的就是我们网页上这几个标签，它的名字，比如 ul。"**

### 6.2 返回的是"集合"，不是一个元素

> ★ 老师的话：**"按标签名获取元素的这种方法，获取过来的元素是多个的。"**

页面上有几个 `li`、几个 `a`、几个 `div`，这个方法就给你几个——所以结果不能直接当元素用，得先从里面取（第八节）。

### 6.3 只有一个元素，返回的仍然是集合（★）

> ★ 老师的话：**"即使页面上只有一个（li）元素，用这个方法返回的仍然是一个集合，只不过它里面只有一个元素。这个页面里面（如果）没有这个元素，那么它将（返回）一个空的集合。"**

| 页面上有几个 `li` | 返回什么 | `lis.length` | `lis[0]` |
|---|---|---|---|
| 3 个 | 3 个元素的集合 | `3` | 第一个 `li` |
| 1 个 | **只有 1 个元素的集合** | `1` | 那一个 `li` |
| 0 个 | **空集合** | `0` | `undefined` |

> ⚠️ **易错点**：页面上只有一个 `li` 时，`lis` 依然是**集合**，不能直接当元素用——照样要写 `lis[0]`。

> 💡 **记忆点**：`getElementById` 是**单数**，回一个；`getElementsByTagName` / `getElementsByClassName` 是**复数**，回一堆。**方法名里的 s 就是"是不是集合"的提示。**

## 七、获取元素（三）：按类名取——`getElementsByClassName`

### 7.1 类名不是唯一的

> ★ 老师的话：**"（类名）它不是唯一的……这个类名可以这个盒子用，也可以另外一个盒子用。这个（就是）很多个盒子同用一个名字。"**

这和 5.1 的 `id` 正好相反：`id` 是身份证，`class` 是"队服"——一队人都能穿。

### 7.2 语法：参数只写类名，不加点（★）

```js
var items = document.getElementsByClassName("item");
console.log(items.length);   // 3（2.1 页面里三个 li 都带 class="item"）
console.log(items[0]);       // 第一个 li
```

> ★ 老师的话：（这个方法的参数）"里面是（类）属性的属性值。"

> ⚠️ **易错点**：把 CSS 里的写法搬过来，写成 `getElementsByClassName(".item")`——那个点要去掉，加了点就变成"找一个类名叫 `.item` 的元素"，一个都找不到。

### 7.3 一组选项一起取：表单里的复选框

> ★ 老师的话：**"表单元素里面有很多的表单元素，比如说单选框啊、多选框……它们具有相同的（类名），主要也是为了方便我们去选取，可以一次性地把这一组选项全部获取过来。"**

在 2.1 的 `demo.html` 的 `body` 里再加这一段：

```html
<p>请选择你最喜欢的水果：</p>
<input type="checkbox" class="fruit" value="草莓"> 草莓
<input type="checkbox" class="fruit" value="雪梨"> 雪梨
<input type="checkbox" class="fruit" value="芒果"> 芒果
```

```js
var fruits = document.getElementsByClassName("fruit");
console.log(fruits.length);   // 3
console.log(fruits[0]);       // 第一个复选框（草莓）
console.log(fruits[2]);       // 第三个复选框（芒果）
```

> ★ 老师当堂提醒：下标还是**从 0 开始**数的，所以第三个是 `[2]`。

| 写法 | 拿到什么 |
|---|---|
| `fruits` | 三个复选框组成的集合 |
| `fruits[0]` | 草莓那个 |
| `fruits[2]` | 芒果那个 |
| `fruits.length` | `3` |

## 八、集合怎么用：按下标访问（HTMLCollection）

### 8.1 打印出来长什么样

> ★ 老师的话：**"（打印出来）显示出来的是什么结果？……而且是有（下标）的 0、1、2。"**

```js
var lis = document.getElementsByTagName("li");
console.log(lis);        // HTMLCollection(3) [li, li, li]
console.log(lis[0]);     // 第一个 li
console.log(lis[1]);     // 第二个 li
```

控制台里它长得很像数组：前面有集合的类型和个数，里面按下标排着。

### 8.2 按下标取：和数组一个写法

> ★ 老师的话：**"可以通过像数组一样，通过索引号去访问集合里面的元素，就是可以通过 0、1、2、3、4 这种索引号去访问返回集合里面的内容。"**

> ★ 老师的话：**"如果想要访问第一个 li，就在（方法调用的）后面加上方括号 0，来表示第一个。"**

```js
var lis = document.getElementsByTagName("li");

console.log(lis[0]);            // 直接取

var first = lis[0];             // 也可以先存到变量里
console.log(first);             // 和上面是同一个 li
```

| 写法 | 结果 |
|---|---|
| `document.getElementsByTagName("li")[0]` | 第一个 `li` |
| `var lis = …; lis[0]` | 第一个 `li`（推荐，别每次都重取） |
| `lis[9]` | `undefined`（没有第 10 个） |

### 8.3 只能按下标，不能当数组用（★）

> ★ 老师的话：**"不能够（用）数组的方法……比如说数组的截取呀、数组的排序呀、数组的反转呀等等，这些方法（是）用不了的。访问啊，就只能通过索引号……（这种）叫类数组对象。"**

| 想做的事 | 数组 | 集合（HTMLCollection） |
|---|---|---|
| 取第 1 个 | `arr[0]` | `list[0]` ✅ |
| 知道有几个 | `arr.length` | `list.length` ✅ |
| 排序 | `arr.sort()` | ❌ 没有这个方法 |
| 反转 | `arr.reverse()` | ❌ |
| 截一段 | `arr.slice(1, 3)` | ❌ |

> ⚠️ **易错点**：集合"打印像数组、能 `[0]`、有 `length`"，看着就是数组——**它不是**。老师当堂判断过这件事，结论是"**类数组对象**"：长得像，方法没有。看到它就想成"**只认下标的盒子**"。

### 8.4 集合是"活的"

> ★ 老师的话：**"我在这个网页上又加了一个 li……集合它会动态地改变。"**

```js
var lis = document.getElementsByTagName("li");
console.log(lis.length);   // 3

// 在页面里再加一个 <li> 之后，同一个 lis 再打印：
console.log(lis.length);   // 4
```

> 💡 **记忆点**：集合不是"拍照"，是"**直播**"——页面结构一变，它里面的内容跟着变。

### 8.5 一张表：三个"老"方法

| 方法 | 参数怎么写 | 返回 | 最多拿到几个 |
|---|---|---|---|
| `getElementById("id值")` | id 值，**不加 `#`** | 一个元素 | 1 |
| `getElementsByTagName("标签名")` | 标签名，**不加 `<>`** | 集合 | 0 ~ 多个 |
| `getElementsByClassName("类名")` | 类名，**不加 `.`** | 集合 | 0 ~ 多个 |

## 九、获取元素（四）：用 CSS 选择器取——`querySelector` / `querySelectorAll`

### 9.1 为什么还要多这两个方法

> ★ 老师的话：**"（设置样式的时候）我们是通过选择器去（选）某一个元素，或者是某几个元素的集合。"**

选择器在 CSS 里已经用熟了，DOM 干脆**借过来直接用**：把选择器写成字符串传进去。

### 9.2 两个方法的分工

| 方法 | 返回 | 什么时候用 |
|---|---|---|
| `document.querySelector("选择器")` | 满足条件的**第一个**元素 | 只要一个 |
| `document.querySelectorAll("选择器")` | **所有**满足条件的元素（集合） | 要一整组 |

> ★ 老师的话：**"如果说你只需要获取第一个元素，用 querySelector；如果想要获取所有元素的集合，那就用（querySelectorAll）。"**

### 9.3 参数必须写成选择器的样子（★本节最容易错）

> ★ 老师的话：**"重点在这里：我们需要写进去的参数，是选择器的形式——类名的话，在类名前面加点；id 的话，在 id 前面加井号。"**

> ★ 老师的话：**"这个方法需要把 CSS 选择器的名字写到参数里，所以说就需要（和）我们样式表里面的写法（一样）。"**

| 想选谁 | 前三个方法的写法 | `querySelector` 的写法 |
|---|---|---|
| class 是 `box` 的 | `getElementsByClassName("box")` | `querySelector(".box")` ← **有点** |
| id 是 `nav` 的 | `getElementById("nav")` | `querySelector("#nav")` ← **有井号** |
| 所有 `li` | `getElementsByTagName("li")` | `querySelectorAll("li")` ← 直接写标签名 |
| `div` 里的 `p` | 得一层层往下找 | `querySelectorAll("div p")` ← 后代选择器 |

> ⚠️ **易错点**：`querySelector("box")` 少了点，会被当成**标签名** `box` 去找，页面上没有这个标签，返回 `null`；而 `getElementsByClassName("box")` 又**不能**加点。**同一个类名，两个方法的参数差一个点**——这是本节最常错的地方。

### 9.4 演示：四个一模一样的盒子

在 `demo.html` 的 `body` 里，把那个带图片的盒子再复制三份，凑成四个 `class="box"` 的盒子：

```html
<div class="box">盒子二</div>
<div class="box">盒子三</div>
<div class="box">盒子四</div>
```

```js
var one = document.querySelector(".box");     // 只拿第一个
var all = document.querySelectorAll(".box");  // 拿全部

console.log(one);         // 只有第一个盒子
console.log(all.length);  // 4
console.log(all[3]);      // 第四个盒子
```

> ★ 老师的话：**"第一个方法选取的是第一个盒子，而第二个方法选取的是四个盒子。"**

### 9.5 四个方法怎么挑

| 场景 | 用哪个 |
|---|---|
| 页面上只有一个、而且给了 `id` | `getElementById` |
| 要某一类标签的全部 | `getElementsByTagName` |
| 要某一类类名的全部 | `getElementsByClassName` |
| 只要第一个，或者条件比较复杂 | `querySelector` |
| 要全部，而且条件比较复杂 | `querySelectorAll` |

> ★ 老师的话：**"如果你觉得用这个方法比较方便，那你用这个方法。"**——四套方法各管一段，没有谁必须替代谁。

## 十、把镜头拉到整个文档：`document` 身上的几个成员

### 10.1 为什么要直接拿 `html` / `body`

> ★ 老师的话：**"有的时候我们还需要去获取到 body……对整个页面做一些设置，比如说在页面上添加一个鼠标事件，单击页面某一个地方。"**

也就是说：要给"整张页面"绑定动作，先得把整张页面（`html` 或 `body`）拿到手。

### 10.2 `documentElement` 与 `body`

| 写法 | 拿到 | 老师的说法 |
|---|---|---|
| `document.documentElement` | `html` 元素 | **"这个方法获取到的是 html 元素。"** |
| `document.body` | `body` 元素 | **"如果你想要获取 body 元素的话，用 document.body。"** |

```js
console.log(document.documentElement);   // 整个 <html>…</html>
console.log(document.body);              // 只有 <body>…</body>
```

> ★ 老师的话：**"（两个打印出来的）内容是不一样的……第一个获取过来的是 html 部分，就是从 html 开头到（html）结尾之间的内容。"**

| | `document.documentElement` | `document.body` |
|---|---|---|
| 是谁 | `html` 元素 | `body` 元素 |
| 范围 | `head` + `body` 全都在里面 | 只有页面上看得见的那部分 |
| 谁包含谁 | 装着 `body` | 被 `html` 装着 |

> ⚠️ **易错点**：`body`、`documentElement` 都是**属性**，后面**不加小括号**；写成 `document.body()` 会报"不是一个函数"。

### 10.3 `document.images`：一次拿到所有图片

```js
console.log(document.images);          // 页面里所有的 img，打印出来是一个集合
console.log(document.images.length);   // 有几张图
```

> ★ 老师的话：**"document.images 这个（属性）是获取所有……图片元素。"**

| 写法 | 拿到 |
|---|---|
| `document.images` | 所有 `img` 组成的集合 |
| `document.images[0]` | 第一张图 |
| `document.images.length` | 一共几张 |

> 💡 **记忆点**：`document` 身上有两种东西——**结构**（`documentElement`、`body`）和**成批的元素**（`images`）。名字是复数，拿到的就是集合。

### 10.4 `document.title`：读和写（★）

> ★ 老师的话：**"用 document.title 获取当前的标题……如果想要修改的话，可以用 `document.title = 新标题` 来赋值。"**

```js
console.log(document.title);    // DOM 示例页

document.title = "新标题";
console.log(document.title);    // 新标题
```

> ★ 老师的话：**"我们现在看到的这个网页的标题（浏览器标签页）部分，显示的就是新标题这几个字了。"**

| 操作 | 写法 | 结果 |
|---|---|---|
| **读** | `var t = document.title;` | 拿到当前标题（一个字符串） |
| **写** | `document.title = "新标题";` | 浏览器标签页上的字立刻变 |

> ⚠️ **易错点**：`document.title()` 是错的——`title` 是**属性**，不是方法。**改属性用等号，调方法才加括号。**

> 💡 **记忆点**：本节唯一一个"能读又能写"的成员就是 `title`：**读它不给值，写它用等号。** 其余几个（`body`、`documentElement`、`images`）本节只讲"取"，没讲"改"。

## 十一、易错点速查

| # | 错误写法 / 错误理解 | 后果 | 正确写法 |
|---|---|---|---|
| 1 | `document.getElementByTagName("li")` | 少个 s，方法不存在 | `getElementsByTagName` |
| 2 | `document.getElementsById("nav")` | 按 id 取的是单数，多了 s 就没这个方法 | `getElementById` |
| 3 | `getElementById("#nav")` | 参数里带了 `#`，取不到 | `getElementById("nav")` |
| 4 | `getElementsByClassName(".box")` | 参数里带了点，一个都取不到 | `getElementsByClassName("box")` |
| 5 | `querySelector("box")` | 少了点，被当成标签名 | `querySelector(".box")` |
| 6 | 用 `querySelector` 想拿全部 | 只拿到第一个 | 改 `querySelectorAll` |
| 7 | 把集合直接当元素用 | 改不到东西 | 先 `[0]` 取出来 |
| 8 | 对集合用 `sort()` / `reverse()` / `slice()` | 报错，它不是数组 | 只能按下标访问 |
| 9 | 以为只有一个元素时返回的就是元素 | 其实还是集合 | 照样 `[0]` |
| 10 | 页面里给两个元素写同一个 `id` | `getElementById` 只认第一个 | `id` 必须唯一，分组用 `class` |
| 11 | `document.title()` | `title` 是属性不是方法 | `document.title` |
| 12 | `document.body()` / `document.images()` | 都是属性 | 不加小括号 |
| 13 | `nodeType` 拿来和字符串比（`=== "1"`） | 永远不成立 | 它是数字：`1` / `3` / `9` |
| 14 | 把"祖先与后代"当成"父子" | 关系判断错，树就画错 | 隔了层就是祖先与后代 |
