# 网页前端设计与开发 课堂笔记（第 41—42 节）——事件绑定：让页面"动"起来的第一步

> 上一节把**元素**抓到了手里——`getElementById`、`getElementsByTagName`、`getElementsByClassName`、`querySelector`……可抓到手里只是"拿到了"，页面还是死的：你不刷新，它一动不动。这一节补上另一半：**事件**。整节的因果链是：页面要"响应"人 → 人的动作（单击、划过、双击、按下与抬起、键盘……）必须能被程序**监测到** → 这种"可以被 JS 监测到的行为"就叫**事件** → 一件事要说清，靠**三要素**：**事件源**（谁身上发生的）、**事件类型**（单击还是划过）、**事件驱动程序**（发生后做什么）→ 于是写交互就固定成三步：**先确定事件源并取到元素 → 再确定事件类型并注册 → 最后分析交互效果、写驱动程序** → 注册的语法只有一行：`元素.onclick = function () { … }`，左边是"元素 + 点 + `on` + 事件类型"，右边是一个**匿名函数** → 也可以把 `onclick` 直接写进 HTML 标签，但代码长、碍阅读、违背"结构、样式、行为相分离"，不推荐 → 驱动程序里能做的事，从最简单的 `alert()` 弹窗，一路走到真正有用的：用 **`innerHTML` / `innerText` / `textContent`** 改元素**里面的内容** → 于是不必改动 HTML 结构，页面也能变。
>
> 文中代码按浏览器里能直接运行的写法补全，只使用本节讲过的 API；示例页面统一用 6.1 的 `demo.html` 配 6.2 的 `demo.js`，后面的案例都在这张页面上加东西。

## 一、先把地基再夯一遍：节点关系与取元素（复习）

### 1.1 页面是一棵树

上一节把整个页面看成**一棵树**，树上的每一个点叫**节点**。本节所有"取元素"的动作，都是在这棵树上找点。

| 节点类型 | 是什么 | 例子 |
|---|---|---|
| **元素节点** | 页面上所有的标签 | `html`、`head`、`body`、`h1`、`ul`、`li`、`table`、`tr`、`td` |
| **文本节点** | 标签与标签之间的那些文字 | `<li>西游记</li>` 里的"西游记"三个字 |
| **文档节点** | `<!DOCTYPE html>` 这一句 | 它代表整份文档，在页面上**看不到** |

树上的点之间只有三种关系：

| 关系 | 判断标准 | 例子 |
|---|---|---|
| **父子** | 直接包着它的那个是父节点，被它直接包住的才是子节点 | `html` 是根节点，`head` 和 `body` 是它的两个子节点；`tr` 的父是 `table` |
| **兄弟** | 有**同一个父节点** | `head` 与 `body`；`ul` 里四个 `li` 彼此都是兄弟 |
| **祖先与后代** | 隔了几层也算，一路往上都是祖先 | `html` 是 `h1` 的祖先，`h1` 是 `html` 的后代 |

> 💡 **记忆点**：做交互时找元素，脑子里要能"看见"这棵树——先抓一个，再顺着父子或兄弟往下走，比乱试方法快得多。

### 1.2 取元素的方法清单（上一节学过，本节天天用）

| 方法 | 参数写什么 | 拿到什么 | 什么时候用 |
|---|---|---|---|
| `document.getElementById("id名")` | 元素的 `id` 值 | **一个**元素 | `id` 在页面里唯一，最直接 |
| `document.getElementsByTagName("标签名")` | 标签名，如 `"li"` | **集合** | 一类标签要一起处理 |
| `document.getElementsByName("name值")` | 元素 `name` 属性的值 | **集合** | 表单里的一组多选框，`name` 相同，一次全取到 |
| `document.getElementsByClassName("类名")` | 类名 | **集合** | 类名可以共用，一组元素能分两批取（前两个、后两个） |
| `document.querySelector("选择器")` | CSS 选择器：类名加点、`id` 加井号 | **第一个** | 条件复杂时，一句选择器定位 |
| `document.querySelectorAll("选择器")` | CSS 选择器 | **全部**（集合） | 条件复杂又要全拿 |

老师复习时的态度很松：**只要能把这个元素取过来，用哪个方法都可以**，具体看页面的情况——"如果它有 `id`，那你就用 `id`"；也可以先用标签名取到一批，再从中取某一个。

### 1.3 "集合不是元素"——这条规矩本节还会踩

- 按标签名、按 `name`、按类名、`querySelectorAll`，拿回来的都是**集合**，不是元素；
- 集合像数组：用**下标** `[0]`、`[1]`、`[2]` 访问，从 **0** 开始数；
- **页面上只有一个这样的元素，它照样是集合；一个都没有，就是空集合**；
- 直接对集合操作（比如 `…getElementsByTagName("li").onclick = …`）拿不到东西，会出错。

> ⚠️ **易错点**：`document.getElementsByTagName("li")` 后面**不能**直接接 `.innerHTML` 或 `.onclick`。它是一批，不是一个；先写 `[0]` 再说。

> 💡 **记忆点**：取了集合，先想下标，再想属性。

### 1.4 复习到这里，缺的正是"反应"

元素能抓到、能改，但页面只在你刷新的时候变。要让它在你**点一下**、**划一下**的时候变，就得让元素"听见"你的动作——这就是事件。

## 二、事件：能被 JS 监测到的行为

### 2.1 一句话定义

> ★ 老师的话：**"事件是指可以被 JS 监测到的行为。"**

拆开看，这句话里有三个要点：

| 要点 | 意思 |
|---|---|
| **行为** | 事情是"做"出来的：单击、划过、双击、按下、抬起、敲键盘 |
| **被 JS 监测到** | 这个行为发生在页面上，程序能察觉，不是发生在别处 |
| **事件 → 反应** | 监测到之后要执行我们写的代码 |

> ★ 老师的话：**"网页会根据你的这个事件做出反应，那这个反应是用代码去实现的。"**

所以"事件"本身不是效果，它只是**一次可以被程序接住的时机**；效果是我们自己在事件里写出来的。

### 2.2 老师当堂点过的事件

| 行为 | 老师当堂说的页面反应 | 说明 |
|---|---|---|
| **单击** | 点页面上的按钮、点一个标题，页面做出响应 | 本节的**主角**，写法就是 `onclick` |
| **鼠标指针划过** | 鼠标划过两个盒子，两个盒子的**背景色由白色变成浅黄色** | "一个鼠标划过的行为，它也是一个事件" |
| **双击** | —— | 与单击是两个不同的事件 |
| **鼠标按下 / 抬起** | —— | 按下、抬起是**两个动作**，也是两个事件 |
| **点击之前 / 点击之后** | —— | 这两个时机都可以**单独设置** |
| **键盘按键** | —— | "还有很多其他的键盘等等，都可以去进行操作" |

> ★ 老师的话：**"单击页面、鼠标指针划过，这都叫事件。"**

> ★ 老师的话：**"这两个盒子的背景色在我们鼠标划过的时候，由白色变成了浅黄色。"**——这是他当堂演示"划过有效果"的例子：效果不是天生的，是有人给这两个盒子写了事件。

### 2.3 事件名"顾名思义"：`on` + 事件类型

> ★ 老师的话：**"这些事件的类型，它都是顾名思义的。"**

> ★ 老师的话：**"以这个单击事件为例，`on` 这个单词加上事件类型来进行注册。"**

于是"单击"这件事，在代码里就写成：

```text
on + click  →  onclick
```

| 想监听的行为 | 事件属性怎么来的 |
|---|---|
| 单击 | `on` + 单击对应的英文词 = `onclick` |
| 双击、划过、按下、抬起…… | 同一个办法：`on` 加上那个动作对应的英文词 |

> 💡 **记忆点**：事件属性一律以 **`on`** 开头。少写这个 `on`，它就不是事件属性了，绑了也不会响。

### 2.4 事件要"绑"在某个元素上

> ★ 老师的话：**"不同的行为对应的是不同的事件，我们通过这个事件给某一个元素去进行绑定。"**

老师举的例子很朴素：页面上写一个标题，给这个标题绑定一个**鼠标单击**事件，那么点这个标题的时候，页面就跳转到另一个页面——"这个效果就有了"。

| 环节 | 谁的事 |
|---|---|
| 行为发生在谁身上 | 那个**元素**（标题、按钮、`li`） |
| 是什么行为 | **事件类型**（单击、双击、划过） |
| 发生后干什么 | 我们写的**代码** |

## 三、事件的三要素

> ★ 老师的话：**"他有三个要素。"**

### 3.1 事件源

> ★ 老师的话：**"事件源就是这个事件产生的元素对象，也就是我点击的那个标题。"**

- 事件源是"**事情发生在谁身上**"；
- 它是一个**元素对象**，不是标签名、不是字符串；
- 所以确定事件源之后，紧接着的动作就是"用上一节的方法把它**取过来**"。

### 3.2 事件类型

单击、双击、鼠标划过……老师说得很直白：

> ★ 老师的话：**"要确定是单击还是双击，还是鼠标划过，确定这个事件类型。"**

事件类型决定了你写 `onclick` 还是写别的——换事件类型，就是换 `on` 后面那个词。

### 3.3 事件驱动程序

> ★ 老师的话：**"事件的驱动程序是什么呢？就是这个事件发生以后，网页产生的效果——这个效果是要用代码去实现的。"**

老师在不同地方也叫它**事件处理函数**、事件处理程序：

> ★ 老师的话：**"后面这一部分是事件处理函数……写到这个大括号里面。"**

一句话：**事件发生以后要执行的那段代码**，就是驱动程序。它最终落成一个函数，塞在 `=` 的右边。

### 3.4 三要素在代码里各落在哪

| 三要素 | 回答的问题 | 在代码里的位置 |
|---|---|---|
| **事件源** | 事情发生在**谁**身上？ | `document.getElementById("btn")` 取到的那个元素（存进变量） |
| **事件类型** | 发生了**什么**动作？ | `.onclick` 里 `on` 后面的部分 |
| **事件驱动程序** | 发生之后**做什么**？ | `function () { … }` 大括号里的代码 |

> 💡 **记忆点**：三要素 = **谁、什么动作、之后干什么**。写不出来的时候，先把这三句用中文说一遍，代码就跟着出来了。

## 四、写交互的固定三步

### 4.1 第一步：确定事件源，把元素取过来

> ★ 老师的话：**"首先要先确定事件源，然后获取这个元素……你首先得确定我要单击谁。"**

"单击谁"这个问题必须先有答案：是标题、是按钮、还是某一本书的名字。想清楚了，再用上一节的六种方法之一把它取到变量里。

### 4.2 第二步：确定事件类型，注册

> ★ 老师的话：**"获取过来以后，确定事件类型，也就是说你要先确定是单击还是双击，还是鼠标划过。"**

"确定事件类型"在代码里的动作叫**注册**：

> ★ 老师的话：**"怎么去确定这个事件类型呢？就是我们需要对这个事件进行注册。"**

### 4.3 第三步：分析交互效果，写驱动程序

> ★ 老师的话：**"然后再分析，我们要分析这个事件实现的网页交互效果、哪些逻辑——它到底是有一个什么效果。"**

老师用"标题单击跳转"走了一遍：效果是**跳转到另一个页面 / 打开一个新的页面**，那驱动程序就围着这个效果写。

### 4.4 三步对照表

| 步骤 | 要做的事 | 对应要素 | 代码长什么样 |
|---|---|---|---|
| ① | 想清楚"我要点谁"，再把元素取过来 | 事件源 | `var btn = document.getElementById("btn");` |
| ② | 想清楚"是单击还是双击还是划过" | 事件类型 | `btn.onclick` |
| ③ | 想清楚"点完要发生什么"，写成函数 | 事件驱动程序 | `function () { alert("…"); }` |

> ★ 老师的话：**"确定事件源 → 获取元素 → 注册事件绑定 → 写事件驱动程序。"**——他当堂把这条流程又复述了一遍。

## 五、注册事件的语法：`元素.onclick = function () { … }`

### 5.1 把这一行拆开

```js
btn.onclick = function () {
    alert("你单击了按钮");
};
```

| 部分 | 写法 | 意思 |
|---|---|---|
| **左边** | `btn` `.` `onclick` | 给 `btn` 这个元素**注册单击事件**：元素 + 点 + `on` + 事件类型 |
| **等号** | `=` | 把右边的函数**交给**这个事件；事件一发生，就执行它 |
| **右边** | `function () { … }` | 事件发生时执行的代码（事件驱动程序） |

> ★ 老师的话：**"给这个元素后面加上点，再写事件属性，这样就给他绑定了一个单击事件。"**

> ★ 老师的话：**"用等号把前面的事件和后面的函数连起来，事件一发生就执行后面这个函数。"**

> 💡 **记忆点**：这一行就是"**谁** `.` **什么事件** `=` **要干什么**"，从左往右读，正好是三要素的顺序。

### 5.2 右边那个函数：匿名函数

> ★ 老师的话：**"右边写什么呢？写事件的驱动程序，也就是一个匿名函数……这个函数里面不需要任何参数，它只是一个弹窗的操作，所以说它没有函数名，也没有参数，小括号里面是空的，但是小括号不能省，在大括号里面写你的驱动程序。"**

| 问题 | 答案 |
|---|---|
| 有函数名吗？ | **没有**——它只用这一次，不需要名字 |
| 有参数吗？ | **没有**，小括号 `()` 里是空的 |
| 小括号能省吗？ | **不能**，`function { … }` 是语法错误 |
| 代码写在哪？ | 大括号 `{ }` 里面，一行一行写"要做什么" |

> ★ 老师的话：**"就是弹窗，用等号……执行后面的这个函数。"**

### 5.3 语法骨架（假设已经取到了 `btn`）

```js
// ① 事件源：元素已经取到，存在 btn 里
// ② 事件类型：单击 → onclick
btn.onclick = function () {        // ③ 驱动程序：匿名函数，事件发生后执行
    // 这里写"单击之后要做什么"
};
```

> ⚠️ **易错点**：等号右边要给的是一个**函数**，不是函数执行的结果。写成 `btn.onclick = alert("你单击了按钮");`，弹窗会在**页面一加载时**就弹出来，之后你再怎么点都不会再弹。

### 5.4 另一种写法：把事件写进 HTML 标签里

```html
<button id="btn" onclick="alert('你单击了按钮');">单击</button>
```

> ★ 老师的话：**"第一种比较简单的方式，在标签里面对元素的事件进行注册。他用的非常的少。"**

写法上要注意：因为 `onclick` 的值本身用双引号包着，里面的字符串就得换成**单引号**。

### 5.5 为什么不推荐这种写法

> ★ 老师的话：**"如果写到标签里面的话，这个代码会很长，它会影响你对这个元素的代码的阅读，而且违背了结构与样式行为相分离的原则。"**

> ★ 老师的话：**"网页结构、样式以及行为是要分离的。我们为什么要把 JS 文件写到外面去呢？"**

| 对比项 | 写在标签里 | 用 JS 注册 |
|---|---|---|
| 代码位置 | 全挤在标签上，和结构混在一起 | 单独写在 `.js` 文件里 |
| 代码长度 | 长，一个标签上挂一大串 | 事件处理器多长都不影响结构 |
| 可读性 | 影响对结构代码的阅读 | 结构一眼看清，行为另找一处 |
| 与课程原则 | 违背"结构、样式、行为相分离" | 符合 |
| 老师的评价 | 最简单，但用得很少，**不推荐** | 本节要用的写法 |

> ⚠️ **易错点**：写在标签里"也能实现"，但它不是本节推荐的做法。别因为短就到处写——一个元素写一段，页面一复杂就没法读了。

### 5.6 两句话记住这一节

> 💡 **记忆点**：**取元素 → 点事件 → 给函数**。三步走完，一个交互就成了。

> 💡 **记忆点**：网页的三层分工——`html` 管结构、CSS 管样式、JS 管行为。事件属于"行为"，所以它该待在 JS 里。

## 六、案例一：一个按钮，点一下弹个窗

### 6.1 页面 `demo.html`

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>事件示例</title>
</head>
<body>
    <h1 id="title">第 41—42 节：事件示例</h1>

    <!-- 页面上生成一个按钮，标签之间写着"单击"两个字 -->
    <button id="btn">单击</button>

    <!-- 行为写到外面单独的文件里，结构与行为分离 -->
    <script src="demo.js"></script>
</body>
</html>
```

老师特意讲了按钮是怎么来的：`<button>` 标签在页面上**生成一个按钮**，"这个按钮里面有两个文本——单击"，这两个字写在**标签之间**。为了方便，给它起了一个 `id` 名：

> ★ 老师的话：**"为了方便给它起了一个 `id` 名，那这样我们就可以通过 `id` 名去选中这个按钮了。"**

### 6.2 脚本 `demo.js`

```js
// ① 确定事件源：页面上只有一个按钮，用 id 直接取
var btn = document.getElementById("btn");

// ② 确定事件类型 + ③ 写驱动程序：单击 → onclick，右边是匿名函数
btn.onclick = function () {
    alert("你单击了按钮");
};
```

### 6.3 逐句读一遍

| 代码 | 干了什么 | 第几步 |
|---|---|---|
| `document.getElementById("btn")` | 按 `id` 把按钮取到 | ① 取元素 |
| `var btn = …` | 存进变量，后面直接写 `btn` | ① |
| `btn.onclick` | 给这个按钮注册单击事件 | ② 注册 |
| `function () { … }` | 匿名函数：单击之后执行什么 | ③ 驱动程序 |
| `alert("你单击了按钮")` | 弹出一个提示框 | ③ |

老师说，确定元素这一步这里特别好办：

> ★ 老师的话：**"确定哪个元素？页面上就只有一个（按钮），所以说你就直接获取这个元素就行了。"**

### 6.4 老师给这段代码的评价

> ★ 老师的话：**"这是我们这学期学习的内容的一个里程碑式的代码。"**

> ★ 老师的话：**"都是这样做的，只不过这是最简单的一种。"**

意思是：这段代码短得不起眼，但它第一次把"页面上的元素"和"用户的一个动作"接上了。后面再复杂的交互，骨架还是这三步。

### 6.5 顺带一句：能点的元素，要长得像能点的

老师在这段里还提醒了一个**设计层面**的细节：能点击的元素需要有"能点的样子"——**下划线、颜色的变化**，让人一眼看出它可以点（他当堂对比了页面上的超链接，"你看它就是一个很有点击的状态"）。

> 💡 **记忆点**：功能上"能点"是 `onclick` 给的；体验上"看得出能点"是样式给的。两件事分开做，但都得做。

## 七、案例二：四本书，四个单击事件

### 7.1 需求

页面上有四本书的名字。老师的要求是：

> ★ 老师的话：**"给四本书分别绑定一个单击事件。要求什么？点击书名的时候，能够弹出他们的作者。"**

### 7.2 先想清楚"事件源有几个"

- 事件源**不是** `ul`，而是四本书各自的 `li`；
- 四个 `li` 每个都要挂一个单击事件，就是**四个**事件；
- 所以先用上一节的办法把这一组 `li` **整批取过来**，再按下标一个个绑。

### 7.3 加进 `demo.html` 的页面结构

```html
<ul id="books">
    <li>西游记</li>
    <li>红楼梦</li>
    <li>三国演义</li>
    <li>水浒传</li>
</ul>
```

### 7.4 加进 `demo.js` 的脚本

```js
// ① 事件源：一组 li，按标签名整批取，得到的是集合
var books = document.getElementsByTagName("li");

// ② + ③ 给第 1 本书绑定单击事件，驱动程序是弹窗
books[0].onclick = function () {
    alert("《西游记》的作者是吴承恩");
};

books[1].onclick = function () {
    alert("《红楼梦》的作者是曹雪芹");
};

books[2].onclick = function () {
    alert("《三国演义》的作者是罗贯中");
};

books[3].onclick = function () {
    alert("《水浒传》的作者是施耐庵");
};
```

> ★ 老师的话：**"按照索引号，分别用索引 0 到 3 去进行访问，方便给他绑定鼠标单击事件。"**

| 元素 | 下标 | 单击之后弹出的内容 |
|---|---|---|
| 第一本 `li`（西游记） | `books[0]` | 《西游记》的作者是吴承恩 |
| 第二本 `li`（红楼梦） | `books[1]` | 《红楼梦》的作者是曹雪芹 |
| 第三本 `li`（三国演义） | `books[2]` | 《三国演义》的作者是罗贯中 |
| 第四本 `li`（水浒传） | `books[3]` | 《水浒传》的作者是施耐庵 |

### 7.5 为什么"代码一样，弹出来的不一样"

四行代码除了下标和那句话，长得一模一样。老师点破了原因：

> ★ 老师的话：**"都写不一样的内容，代码是一样的，取出来就不一样。"**

| 相同的部分 | 不同的部分 |
|---|---|
| `onclick = function () { alert(…); }` 这个骨架 | `books[0]` / `books[1]` / … 取到的是**不同的元素** |
| 匿名函数的写法 | `alert` 里那句**字符串**不一样 |

每个 `li` 身上挂的是**自己那个**函数，函数里写着**自己那句**话——所以点哪本弹哪本。

### 7.6 只想给两本书绑定怎么办

集合的好处是"要几个取几个"：只给前两本绑，就写 `books[0]`、`books[1]`；只给后两本绑，就写 `books[2]`、`books[3]`。老师上一节复习"前两个 / 后两个"的取法，就是为了这种时候。

> ⚠️ **易错点**：`books[4]` 取不到第五本——四个 `li` 的下标只到 **3**。越界拿到的是 `undefined`，再对它写 `.onclick` 就会报错。

## 八、事件里能做的事（一）：改元素的内容

按钮弹窗只是"证明事件通了"。真正让页面变化，是**在事件里改元素里面的东西**。老师这一节讲了三个属性，都是**元素对象的属性**（用点访问，**不加括号**）。

### 8.1 三个属性一览

| 属性 | 取到的是什么 | 带不带标签 | 能不能赋值改内容 |
|---|---|---|---|
| **`innerHTML`** | 元素**内部**的全部内容 | **带**（子标签原样带出来） | 能，赋进去的标签会被**解析**成真标签 |
| **`innerText`** | 只有文字 | **不带** | 能 |
| **`textContent`** | 只有文字（源码里的换行、空格**保留**） | **不带** | 能 |

### 8.2 `innerHTML`：带标签

> ★ 老师的话：**"第一个属性是包含标签的，返回的结果是包含标签的，也就是说它会把元素里面的标签一起交给你。"**

> ★ 老师的话：**"标签之内所有的内容都可以获取回来，也可以进行修改。"**

所以元素里如果套着 `<a>`、`<span>`，`innerHTML` 会把它们**连标签一起**取回来；反过来，往 `innerHTML` 里赋一段带标签的字符串，标签会被当成真标签渲染出来。

### 8.3 `innerText` 与 `textContent`：只有文本

> ★ 老师的话：**"这两个（属性）只获取文本，用它们获取过来的只有'西游记'这三个字，它只有文本，不包含前面的标签。"**

同一个元素，一个带标签、两个不带——这就是三个属性最要紧的区别。

### 8.4 后两个的细微差别：空格与换行

> ★ 老师的话：**"它会去掉空格、换行……如果你有空格或者换行标记的话。"**

> ★ 老师的话：**"有换行啊等等这些格式，就是他俩这个区别。"**

| 属性 | 对空白的态度 | 适合拿它干什么 |
|---|---|---|
| `innerText` | 更接近"**页面上看到的**"：多余的空格、换行会被吃掉 | 取一句人话去显示、去比较 |
| `textContent` | 更接近"**源码里写的**"：换行、缩进原样保留 | 要保留原来的排版格式时 |

> ⚠️ **易错点**：用 `textContent` 取回来的文字，可能因为源码里的换行、缩进而**多出空白**。拿它去和 `"西游记"` 做相等判断，容易对不上——这种时候先 `console.log` 看一眼，或者改用 `innerText`。

### 8.5 取和改是同一个属性

三个属性既能**读**，也能**写**。读的时候写在等号右边，改的时候写在等号左边：

```js
// 读：把元素里面的内容取出来看
console.log(book.innerHTML);

// 写：把元素里面的内容换掉
book.innerHTML = '正在读：《<a href="#">三国演义</a>》';
```

> ★ 老师的话：**"也可以进行修改。"**

### 8.6 演示：同一个元素，三种取法

在 `demo.html` 里加一段（`<a>` 只是让"带不带标签"看得更明显）：

```html
<p id="book">正在读：《<a href="#">西游记</a>》</p>
```

```js
var book = document.getElementById("book");

console.log(book.innerHTML);    // 正在读：《<a href="#">西游记</a>》
console.log(book.innerText);    // 正在读：《西游记》
console.log(book.textContent);  // 正在读：《西游记》
```

| 属性 | 控制台里的结果 | 看出来的事 |
|---|---|---|
| `innerHTML` | `正在读：《<a href="#">西游记</a>》` | 标签跟着回来了 |
| `innerText` | `正在读：《西游记》` | 只剩文字 |
| `textContent` | `正在读：《西游记》` | 只剩文字 |

### 8.7 什么时候用哪个

| 想要的效果 | 用哪个 |
|---|---|
| 把里面的小标签一起取出来 / 塞一段带标签的内容进去 | `innerHTML` |
| 只要文字，不要标签 | `innerText` |
| 要文字，而且要保留原来的换行、空格 | `textContent` |

> 💡 **记忆点**：三个属性里，只有 `innerHTML` 那个名字里带 **HTML**——带 HTML 的那个，就带标签。

## 九、案例三：表格里的商品状态要更新

### 9.1 需求

> ★ 老师的话：**"对于过季款、当前热销和春季新品这三款商品，它的状态是需要实时更新的。"**

要改的只是**表格里某几个单元格里的字**，表格的结构一行都不用动。

### 9.2 加进 `demo.html` 的页面结构

```html
<table id="goods">
    <tr>
        <th>商品</th>
        <th>状态</th>
    </tr>
    <tr>
        <td>过季款</td>
        <td id="state1">已下架</td>
    </tr>
    <tr>
        <td>当前热销</td>
        <td id="state2">已下架</td>
    </tr>
    <tr>
        <td>春季新品</td>
        <td id="state3">已下架</td>
    </tr>
</table>
```

### 9.3 加进 `demo.js` 的脚本

```js
// 三个状态单元格都用 id 取：这些元素身上正好有 id
var s1 = document.getElementById("state1");
var s2 = document.getElementById("state2");
var s3 = document.getElementById("state3");

// 三个属性都能改内容，这里各用一次
s1.innerHTML = "已上架";
s2.innerText = "已上架";
s3.textContent = "已上架";
```

这段代码在页面一加载时就会执行，所以一进页面三个状态就已经是"已上架"了——它演示的不是"什么时候改"，而是"**内容确实能被属性改掉**"。

> ★ 老师的话：**"这里用的是 `id`，因为这个元素它有 `id` 属性。"**

> ★ 老师的话：**"设置成了已上架。"**

页面一刷新，三个状态就从"已下架"变成"已上架"。老师把这件事的意义说了出来：

> ★ 老师的话：**"我们可以不用更改网页结构，就可以去修改页面，让我们的页面变化。"**

> ★ 老师的话：**"去修改更多的东西。"**

### 9.4 顺带复习：表格的骨架

老师用这个案例顺手把表格的标签过了一遍：

| 标签 | 作用 |
|---|---|
| `<table>` | 整个表格 |
| `<tr>` | 一行（table row） |
| `<td>` | 一个单元格 |
| `<th>` | 表头单元格，字**默认加粗** |

- 一行里有几个 `td`，这一行就有几列；
- 每个单元格里的内容，都可以用本节那三个属性去读、去改。

> ★ 老师的话：**"像这种加粗的单元格，会用 `th`。"**

老师还指出了一个"能写但不推荐"的地方：单元格的一些属性可以直接写在标签里，效果也生效，但**不推荐**——

> ★ 老师的话：**"我们有一些属性，可以不用写到 CSS 样式表里面，也可以写到这里，但是不推荐这里。"**

这和第 5.5 节是同一个道理：**样式的事归样式表，结构里只留结构**。

### 9.5 顺带复习：`div` 与 `span`

| 标签 | 老师怎么形容 | 特点 |
|---|---|---|
| `<div>` | **大盒子** | 独占一整块空间，一个 `div` 占一行 |
| `<span>` | **小盒子**（小盒子容器） | 可以在一行里放很多个 |

> ★ 老师的话：**"`div` 是大盒子，独占一整块空间；`span` 是小盒子，它可以在一行内放很多个。"**

`span` 的典型用场：一段文字里**只有某几个字**要不一样（要在一行里显示，但样式不同），就把这几个字用 `span` 包起来。

> ★ 老师的话：**"需要在一行里显示，但是样式不一样。"**

于是三个属性在这里又分出高下：

> ★ 老师的话：**"这种情况下，我们用 `innerHTML` 去获取里面的内容的时候，就会把 `span` 这个标签一起获取过来。"**

| 取法 | 拿到的东西 |
|---|---|
| `innerHTML` | `《<span>西游记</span>》`——标签也在里面 |
| `innerText` / `textContent` | `《西游记》`——只有文字 |

> 💡 **记忆点**：**只要文字就用后两个，要连标签一起动就用 `innerHTML`**。判断方法很简单：看结果里要不要出现尖括号。

## 十、易错点速查

| # | 错误写法 / 错误理解 | 后果 | 正确写法 |
|---|---|---|---|
| 1 | `document.getElementsByTagName("li").onclick = …` | 对集合操作，取不到元素，报错 | `…getElementsByTagName("li")[0].onclick = …` |
| 2 | 以为"页面上只有一个 `li`，取回来就是元素" | 它仍是集合，写 `.innerHTML` 无效 | 一个也要按下标：`[0]` |
| 3 | `btn.click = function () { … }` | 少了 `on`，绑的不是事件属性，点了没反应 | `btn.onclick = function () { … }` |
| 4 | `btn.onclick = alert("你单击了按钮");` | 弹窗在页面加载时就弹了，之后点不再弹 | 右边给**函数**：`function () { alert(…); }` |
| 5 | `function { … }`（漏了小括号） | 语法错误，整段脚本不执行 | `function () { … }`，小括号不能省 |
| 6 | 把事件写进标签：`<div onclick="…">` | 代码长、碍阅读，破坏结构/样式/行为分离 | 在 JS 里用 `元素.onclick = …` 注册 |
| 7 | 用 `innerHTML` 取文字去做比较 | 结果里带着 `<a>`、`<span>` 等标签 | 只要文字就用 `innerText` / `textContent` |
| 8 | 写成 `book.innerText()` | 属性被当成方法调用，报错 | 属性不加括号：`book.innerText` |
| 9 | `books[4]` 取第五本书 | 越界，得到 `undefined`，`.onclick` 报错 | 四个 `li` 的下标是 `0`—`3` |
| 10 | 把 `<!DOCTYPE html>` 当成元素节点 | 类型判断错，DOM 关系讲不通 | 它是**文档节点**，代表整份文档 |
| 11 | 以为"元素在页面上，点一下自然有反应" | 没注册事件，点了什么也不发生 | 必须 `元素.onclick = function () { … }` |
| 12 | 往 `innerText` 里塞 `<a href="#">…</a>` | 标签被当文字原样显示 | 要让标签生效，用 `innerHTML` |
| 13 | 改了内容却盯着 HTML 源码看 | 以为没生效 | 属性改的是**页面上的实际内容**，刷新前就生效 |
