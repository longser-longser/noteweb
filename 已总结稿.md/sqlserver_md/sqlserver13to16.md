# SQL Server 数据库 课堂笔记（第 13—16 节）——数据表、字段与约束

> **本节主线**：上一批把"库"建起来了，这一批开始往库里**装东西**——所有数据最终都装在**数据表**里。
> 建一张表只定三件事：**字段名、数据类型、约束**。全节的重心落在**约束**上：主键、非空、默认值、检查、标识列、外键。

---

## 一、从建库到建表

### 1.1 先把上一批的账结清

| 环节 | 做法 | 关键点 |
|---|---|---|
| 建库 | SSMS 右键"新建数据库"；也可以在属性里改 | 图形界面和 SQL 语句两条路 |
| 扩展 | 自动扩展 / 手动扩展 | 库不够用了就长大 |
| 收缩 | 自动收缩 / 手动收缩 | 把空闲空间收回来 |
| 移动 | 先**分离**，再**附加** | 文件换个地方放 |
| 删除 | 右键删除 | 不要了就删掉 |

**分离**和**删除**最容易混，一定要分清：

| 操作 | 结果 | 文件 |
|---|---|---|
| 分离 | 数据库从当前实例的列表里消失，实例不再管它 | **文件仍留在原来的位置**，可以复制、移动，再附加回来 |
| 删除 | 数据库连同文件一起被删掉 | **不可逆转**，删了就没了 |

### 1.2 一个数据库至少两个文件

| 文件 | 扩展名 | 是否必需 |
|---|---|---|
| 主数据文件 | `.mdf` | 必需 |
| 日志文件 | `.ldf` | 必需 |
| 辅助（次要）数据文件 | — | 按需要再添加 |

> 💡 一个数据库**最少两个文件**：一个主数据文件 + 一个日志文件。数据文件可以不止一个，需要时再加辅助数据文件；日志文件也是必需的。

### 1.3 数据库命名的规矩

| 规则 | 具体要求 |
|---|---|
| 可用字符 | 汉字、字母、数字、下划线 |
| 开头 | 不能以数字开头，也不能以特殊符号开头 |
| 禁用字符 | 不能有空格、星号、斜杠这类非法字符 |
| 保留字 | 不能使用系统的保留字（关键字） |
| 长度 | 最多 128 个字符 |
| 重名 | 同一个服务器（实例）下不能有同名数据库，否则提示"数据库已存在" |
| 大小写 | 不区分大小写；教材里写成大写，只是为了把关键字标出来 |
| 中文 | 允许用中文，但**不提倡**——后面写程序、做后台维护都麻烦 |

> ⚠️ 数据库名里带空格、星号、斜杠，或者拿数字开头，都属于**不符合命名规则**，建库时直接过不去。

### 1.4 数据库只分两类

| 分类 | 说明 |
|---|---|
| 系统数据库 | 安装时由系统**自动生成**，一共 **4 个**；不能附加、不能分离、不能删除 |
| 用户数据库 | 自己建的库，包括课上演示建的那些 |

> ⚠️ 分类里**没有"临时数据库"这一类**，别自己加。
> 系统数据库是实例自己的家底，一旦被破坏，实例就起不来，所以不能附加、不能分离，更不能删除。

## 二、数据表：数据库里真正存数据的地方

### 2.1 表是最重要的数据库对象

数据库建好只是有了一个"仓库"，真正装货的是**表**。

| 数据库对象 | 说明 |
|---|---|
| 数据表 | 真正存放数据的对象，是数据库里**最重要**的对象 |
| 视图、存储过程、触发器、索引 | 同样是数据库对象，但它们的数据核心都**来源于表** |

> 💡 记住一句话：**数据都在表里**。别的对象再花哨，底下还是表。

### 2.2 四个术语：表、字段、记录、实体

| 术语 | 也叫 | 含义 |
|---|---|---|
| 表 | 二维表 | 由行和列组成的表格 |
| 字段 | 列、列名 | 表头那一行，规定这一类数据是什么，如学号、姓名、性别 |
| 记录 | 行 | 表里的一行数据 |
| 实体 | — | 实实在在存在的一个对象 |

一行 = 一条记录 = 一个实体。

课上举的例子：一个学生就是一条记录、一个实体；全班 44 个人，学生信息表里就是 44 条记录。

### 2.3 字段名要"见名知意"

- 字段名一看就知道这一列存的是什么：`学号`、`姓名`、`出生日期`。
- 不要起那种看半天也不知道存了啥的名字，自己过两天都认不出来。

## 三、建表：字段名、数据类型、约束

### 3.1 建表的两种方式

| 方式 | 怎么做 | 说明 |
|---|---|---|
| 图形界面（SSMS 表设计器） | 展开数据库 → 右键"表" → "新建表"，一列一列填 | 边看边改，约束也能在界面上点出来 |
| SQL 语句 | `CREATE TABLE` | 一次把字段、类型、约束写清楚 |

> 💡 两种都要会：**用工具建表、用工具建约束**要会，**用语句建表**也要会，这两个是重点。

### 3.2 数据类型与长度

| 类型 | 含义 |
|---|---|
| `CHAR(n)` | 定长字符，长度固定 |
| `VARCHAR(n)` | 变长字符，`v` 就是可变（variable）的意思；括号里的数字是**最大长度** |
| 日期类型 | 出生日期这类数据用 |
| 数值类型 | 成绩这类数据用 |

长度和字节的关系：

| 项目 | 占用 |
|---|---|
| 一个英文字母 | 1 个字节 = 8 位 |
| 一个汉字 | 2 个字节 = 16 位 |
| 长度写 20 | 最多存 20，超了就存不下 |

> ⚠️ 长度定小了，数据存不进去就报错；定得太大又浪费空间。课上的例子：明明只显示一个姓名，却占了整整一行。

### 3.3 课上建的三张表

| 表 | 字段 | 主键 |
|---|---|---|
| 学生信息表 | 学号、姓名、年龄、性别、专业、出生日期、家庭地址、邮箱 | 学号 |
| 课程信息表 | 课程编号、课程名称、开课学期、学时、学分 | 课程编号 |
| 成绩表 | 学号、课程编号、成绩 | （学号, 课程编号） |

> 💡 成绩表是夹在中间的"关系表"：它用**学号**连学生信息表，用**课程编号**连课程信息表。
> 学生信息表、课程信息表是**主表**，成绩表是**子表（从表）**。

## 四、约束（本节重点）

约束就是对数据的**限制**——数据库只收符合规矩的数据，不合规矩的直接拒绝。

课上打的比方：现实生活里到处是限制，有法律法规，有道德规范；注册账号时带星号的必填项，也是一种限制。

| 约束 | SQL 关键字 | 管什么 | 课上的例子 |
|---|---|---|---|
| 主键约束 | `PRIMARY KEY` | 唯一标识一行，不许重复、不许为空 | 学号 |
| 非空约束 | `NOT NULL` | 这一列必须有值 | 姓名 |
| 默认值约束 | `DEFAULT` | 不填的时候自动带一个值 | 性别默认 `'男'` |
| 检查约束 | `CHECK` | 值必须满足给定的表达式 | 成绩 0—100；邮箱必须有 `@` |
| 外键约束 | `FOREIGN KEY` | 值必须在另一张表的主键里真实存在 | 成绩表.学号 → 学生信息表.学号 |
| （标识列） | `IDENTITY` | 系统自动编号 | 编号列自动生成 1、2、3… |

### 4.1 主键约束 PRIMARY KEY

| 要点 | 说明 |
|---|---|
| 作用 | 唯一标识表中的每一行 |
| 特点 | 不允许重复，不允许为空 |
| 是否必需 | **不是必须有**，但一般都设 |
| 图形界面 | 选中列 → 右键"设置主键"，列名前出现一个**金色钥匙**图标 |
| SQL 写法 | `学号 VARCHAR(20) PRIMARY KEY` |

什么样的列能当主键：

- ✅ 学号：每个学生一个，不会重复。
- ✅ 身份证号：每个人都不一样，也不会重复。
- ❌ 性别：只有男、女两种，一个表里大半都是重复的，标识不了任何一行。

> ⚠️ 主键选错，表的"唯一标识"就没了。凡是一列里会出现大量重复值的，都不能做主键。

### 4.2 非空约束 NOT NULL

- 这一列必须填，不许空着。
- 图形界面：选中列，把"**允许 Null 值**"的勾取消掉。
- 课上例子：**姓名**不能空着——一个人连名字都没有，这条记录就没意义。

### 4.3 默认值约束 DEFAULT

- 不填的时候，系统自动填上事先定好的值。
- 图形界面：在"**默认值或绑定**"一栏里填。
- 课上例子：**性别**默认 `'男'`，录入时没改，就自动是"男"。

```sql
性别 CHAR(2) DEFAULT '男'
```

> 💡 默认值是"你不填我才填"，不是"每次都必须填这个值"。填了别的，以填的为准。

### 4.4 检查约束 CHECK

- 限定这一列的取值范围或格式，不满足就报错。
- 图形界面：右键表 → "**CHECK 约束**" → 添加 → 在"表达式"里写条件。

课上写了两个：

```sql
-- 邮箱必须带 @，@ 前面后面是什么都行
CHECK (邮箱 LIKE '%@%')

-- 成绩只能在 0 到 100 之间
CHECK (成绩 >= 0 AND 成绩 <= 100)
```

`LIKE '%@%'` 里的 `%` 表示"任意多个字符"，所以这条的意思是：`@` 前面任意、后面任意，只要中间有个 `@` 就算合格。

> ⚠️ 检查约束要把**两头都写全**。只写"成绩 <= 100"，那 -50 分也能录进去。

### 4.5 标识列 IDENTITY（不是约束，是列属性）

| 要点 | 说明 |
|---|---|
| 是什么 | 列的属性，不是约束 |
| 作用 | 由系统自动生成、有规律地编号，不用自己填 |
| 要设两个值 | **种子**（从哪个数开始）和**增量**（每行加多少） |
| 图形界面 | 选中列，在"**标识规范**"里设 |

```sql
列名 INT IDENTITY(1, 1)   -- 种子 1，增量 1：1、2、3、4 …
列名 INT IDENTITY(1, 2)   -- 种子 1，增量 2：1、3、5、7 …
```

> 💡 标识列一般用在整数类型的编号列上：录一条自动给一个号，不会重，也不用自己算。这个点是考点。

### 4.6 外键约束 FOREIGN KEY

外键就是"我这一列的值，必须是另一张表里真实存在的"。

| 概念 | 说明 |
|---|---|
| 外键 | 一个表里引用另一张表主键的那一列 |
| 主表 | 被引用的表（学生信息表、课程信息表） |
| 子表（从表） | 放外键的表（成绩表） |
| 作用 | 保证录入成绩时，学号在学生信息表里真有这个人，课程编号在课程信息表里真有这门课 |

课上讲得很直白：录一条成绩，学号写了个"咱班没这个人"的号，数据库不许你录；课程编号写了个不存在的课，也不许录。

建外键的两条路：

| 方式 | 操作 |
|---|---|
| 图形界面 | 右键表 → 设计 → 点"**关系**" → 添加 → 在"**表和列规范**"里选主表、主表列和子表列 |
| SQL 语句 | `FOREIGN KEY (子表列) REFERENCES 主表(主表列)` |

```sql
FOREIGN KEY (学号) REFERENCES 学生信息表(学号)
FOREIGN KEY (课程编号) REFERENCES 课程信息表(课程编号)
```

> ⚠️ 顺序不能反：**先有主表，才能加外键**。课上就是先把学生信息表、课程信息表建好，最后建成绩表，再挂上两个外键。

### 4.7 表与表不是孤立的

- 表之间靠**主键—外键**连起来，形成关系。
- 一个表如果跟任何表都没有关系，那这个表就是**多余**的。

> 💡 三张表的骨架：学生信息表（学号是主键）← 成绩表 → 课程信息表（课程编号是主键）。成绩表两头都是外键，正好把两张主表连起来。

## 五、在 SSMS 里把表建出来

### 5.1 建表与加约束的操作路径

| 要做的 | 点哪里 |
|---|---|
| 新建表 | 展开数据库 → 右键"表" → "新建表" |
| 加字段 | 在表设计器里一行一行填：列名、数据类型、允许 Null 值 |
| 设主键 | 选中列 → 右键"设置主键"（列名前出现金色钥匙） |
| 设非空 | 取消该列"允许 Null 值"的勾 |
| 设默认值 | 在该列"默认值或绑定"里填，如 `'男'` |
| 设标识列 | 选中列 → 在"标识规范"里填种子和增量 |
| 设检查约束 | 右键表 → "CHECK 约束" → 添加 → 编辑表达式 |
| 设外键 | 右键表 → 设计 → "关系" → 添加 → "表和列规范" |
| 保存 | 保存后输入表名 |

### 5.2 建表的顺序

1. 先建**学生信息表**：设学号为主键，姓名非空，性别给默认值 `'男'`，邮箱加检查约束。
2. 再建**课程信息表**：课程编号为主键，其余字段按上表填。
3. 最后建**成绩表**：学号、课程编号、成绩三列，成绩加非空和 0—100 的检查约束，再加两个外键分别指向两张主表。

## 六、用 SQL 语句建这三张表

### 6.1 学生信息表

```sql
CREATE TABLE 学生信息表
(
    学号     VARCHAR(20)  NOT NULL PRIMARY KEY,
    姓名     VARCHAR(20)  NOT NULL,
    年龄     INT,
    性别     CHAR(2)      DEFAULT '男',
    专业     VARCHAR(30),
    出生日期 DATE,
    家庭地址 VARCHAR(50),
    邮箱     VARCHAR(50)  CHECK (邮箱 LIKE '%@%')
);
```

### 6.2 课程信息表

```sql
CREATE TABLE 课程信息表
(
    课程编号 VARCHAR(10) NOT NULL PRIMARY KEY,
    课程名称 VARCHAR(30) NOT NULL,
    开课学期 VARCHAR(20),
    学时     INT,
    学分     INT
);
```

### 6.3 成绩表

```sql
CREATE TABLE 成绩表
(
    学号     VARCHAR(20)  NOT NULL,
    课程编号 VARCHAR(10)  NOT NULL,
    成绩     DECIMAL(5,2) NOT NULL CHECK (成绩 >= 0 AND 成绩 <= 100),
    PRIMARY KEY (学号, 课程编号),
    FOREIGN KEY (学号)     REFERENCES 学生信息表(学号),
    FOREIGN KEY (课程编号) REFERENCES 课程信息表(课程编号)
);
```

> 💡 成绩表用（学号, 课程编号）**两列一起做主键**：一个人一门课只该有一条成绩。这两列同时又是外键，分别指向两张主表——一个字段身兼两职，这在关系表里很常见。

### 6.4 建表语句的写法要点

| 要点 | 说明 |
|---|---|
| 字段之间用逗号隔开 | 最后一列后面不加逗号 |
| 列级约束 | 直接写在字段后面，如 `NOT NULL`、`DEFAULT '男'`、`CHECK (...)` |
| 表级约束 | 单独写成一行，如 `PRIMARY KEY (学号, 课程编号)`、`FOREIGN KEY (...) REFERENCES ...` |
| 多列主键 | 必须写成表级约束 |
| 语句统一大写 | `CREATE TABLE`、`PRIMARY KEY`、`FOREIGN KEY`、`CHECK`、`DEFAULT` |

## 七、为什么"建表要先设计"

建表之前，先想清楚这张表到底要存什么数据、要哪些字段。

老师拿建桥打比方：桥是先有图纸再施工的，图纸错了，桥都建好了再返工，代价就大了。表也一样——**表建好、数据也录进去了，才发现字段设计错了，再改就很麻烦**。

> ⚠️ 最常见的翻车：表里已经存了几十条数据，才想起少一个字段、或者某个字段长度不够。所以顺序永远是：**先设计，后建表**。

> 💡 判断设计好没好，看两点：字段是不是"见名知意"；表和表之间有没有用主键—外键连起来。

## 易错点清单

| # | 易错点 | 正确做法 |
|---|---|---|
| 1 | 以为每张表都必须有主键 | 主键可以没有，但一般都要设 |
| 2 | 拿性别这类重复值多的列做主键 | 主键必须能唯一区分每一行，用学号、身份证号 |
| 3 | 以为设了默认值就每次都得填这个值 | 默认值只在你没填的时候生效 |
| 4 | 检查约束只写上限 | 上下限都写：`成绩 >= 0 AND 成绩 <= 100` |
| 5 | 邮箱检查写成 `LIKE '@'` | 前后都要加 `%`：`LIKE '%@%'` |
| 6 | 先建子表再建主表 | 先建主表，最后建子表并加外键 |
| 7 | 把标识列当成一种约束 | 标识列是列属性，在"标识规范"里设 |
| 8 | 字段长度定得太小 | 按实际需要的最长长度定，一个汉字占 2 字节 |
| 9 | 把"分离"当成"删除" | 分离只是移出实例，文件仍在原处 |
| 10 | 数据库名带空格、数字开头、用保留字 | 按命名规则来，否则建不出来 |
| 11 | 表建好、数据录进去才发现字段设计错了 | 先设计后建表 |
| 12 | 建一张跟谁都没关系的表 | 表要靠主键—外键连起来，孤立的表是多余的 |

## 自测题（合上笔记再答）

### 第一组：库与文件

1. 分离数据库和删除数据库，结果有什么不同？（见 1.1）
2. 一个数据库最少要有几个文件？分别是什么扩展名？（见 1.2）
3. 数据库名能不能用中文？能不能以数字开头？最长多少个字符？（见 1.3）
