## 一、数据库的文件构成与逻辑名称

### 1.1 一个数据库至少要有哪些文件

老师在讲创建数据库时反复强调文件数量：

| 要点 | 说明 |
|---|---|
| **文件数量下限** | 一个数据库**至少要有两个文件**：<br>① **主数据文件**（`.mdf`）② **日志文件**（`.ldf`） |
| 可以更多 | 数据文件可以有多个（主数据文件 + 若干**次要数据文件** `.ndf`）；日志文件也可以有多个 |
| 创建时写几个 | 创建语句里**至少定义一个数据文件和一个日志文件**，「文件都是两个文件」这是最低要求 |

### 1.2 创建语句里的文件定义顺序

老师带着大家看书上的示例，并逐段讲解「**这一段在整个语句里是干什么的**」：

```sql
CREATE DATABASE 数据库名
ON PRIMARY
( NAME = ..., FILENAME = ..., SIZE = ..., MAXSIZE = ..., FILEGROWTH = ... ),   -- 主数据文件
( NAME = ..., ... ),                                                            -- 次要数据文件（可选）
LOG ON
( NAME = ..., FILENAME = ..., SIZE = ..., MAXSIZE = ..., FILEGROWTH = ... ),   -- 日志文件
( NAME = ..., ... );                                                            -- 第二个日志文件（可选）
```

**老师强调的三个语法细节**（这些是「细节题」的常见出题点）：

1. **一个括号 = 一个文件**。要加第二个文件，就**再写一对括号再定义一次**：
   > 「如果我想（加）第二个（数据）文件咋办？再（写）一个逗号，再定一点。」
2. **括号之间用逗号分隔**。转写里老师专门指着屏幕说「你看后面多一个逗号」。
3. **最后一个定义后面不能再加逗号**。最后一项写完后语句就结束（分号），
   > 「最后这个地方他那个我就不能再加了。」

> ⚠️ **易错点**：老师问「**关键是你谁放前谁放后**」——
> 也就是说 **`ON PRIMARY` 这一段（数据文件）在前、`LOG ON` 这一段（日志文件）在后**，
> 文件定义的书写顺序不能颠倒。老师让同学「按这个顺序」去思考。

### 1.3 逻辑名称（NAME）与物理文件（FILENAME）

| 概念 | 说明 |
|---|---|
| **逻辑名称** | 前面 `NAME = ...` 写的是**逻辑名**，是数据库内部使用的名字 |
| **物理文件名** | 后面 `FILENAME = ...` 写的是**实际存在磁盘上的文件** |
| 老师的追问 | 「**你的名字你都存到哪个位置？名字是啥东西？**」——即要分清**逻辑名**和**物理文件名**是两件事 |

> 💡 复习提示：老师用 `NAME` / `FILENAME` 这一对参数来考「逻辑名 vs 物理文件」，这个对比要记牢。

## 二、数据库的自动增长与手动增长

老师明确说「**本来有两种方式**」，并把它列为本节第一个知识点：

| 方式 | 做法 | 老师演示的要点 |
|---|---|---|
| **自动增长** | 在**数据库属性**里把「自动增长 / 自动**数据**增长」打开，就 OK 了 | 转写为「在数据库属性里面把这个自动数据（增长）稍微（设）一下就 OK 了」 |
| **手动增长** | 手动指定增量，例如原来是 **60 MB**，改成一个新的值 | 需要自己算出要加多少 |

**手动增长时老师提到的两个参数**：

1. **每次增长的增量**：转写里出现「原来是 60 兆」以及「一千」「一千五」这类数值——
   说明**手动模式下要自己填写增量数字**（具体单位是 MB，具体数值因演示库而异）。
2. **增长的上限**：辅助参数是有限的，不能无限制地长下去。
   > 老师顺带举了个生活化的例子说明「上限」这个概念：**同一个数据库扩展的时候，
   > 可以按 500（MB）、300（MB）这样一档一档往上加，但不能超过你设的上限。**
   > （原话碎片：「一个数据库扩展的时候……然后（设）五百（MB）……三百（MB）的。」）

> ⚠️ 转写里「自动货站」「自动手术」「自动手（势）」指的都是**自动增长**；
> 「手动分」「手术也有两种」指的是**手动增长**，见附录 A。

## 三、数据库属性配置（重点演示）

老师在 `[00:15:20] — [00:16:35]` 完整演示了一遍「数据库属性」对话框。

### 3.1 进入路径

1. 在 SSMS 的**对象资源管理器**里展开「数据库」节点；
2. **选中**你要配置的那个数据库（**先选中，才会弹出该数据库的属性**）；

### 3.2 属性对话框里要会看的几项

| 属性项 | 老师演示/强调的内容 | 备注 |
|---|---|---|
| **恢复模式** | 老师演示时点过这一项（转写有「三种方式」的字样） | 标准恢复模式为：**完整 / 大容量日志 / 简单** 三种（**此项老师只带过一句，未展开，请以教材为准**） |
| **限制访问** | 「这个限制（访问）还有三种方式嘛」——**单用户 / 多用户 / 受限用户** | 转写为「马奥克优势个单用户多用户还只能只能用户」，订正见附录 A |
| **自动关闭** | 「自动关闭」选项，老师说要**把它去掉（取消勾选）** | 转写同时出现「自动收缩」，两个自动选项要分清 |
| **自动收缩** | 同上，属于「自动」类选项 | 与第四章的「收缩数据库」是同一组概念 |
| **权限** | 「你看这个权限」——数据库属性里可以看/改权限 | 与「访问不了」的权限话题对应 |

> ⚠️ **待确认**：转写为「自动搜锁」，从上下文看应是**自动收缩**；
> 但老师在同一句里也提到了「自动关闭」，因此这一处无法百分百区分（见附录 B）。

### 3.3 关于「自动关闭」的一个实操后果（老师讲了原理）

老师在演示「删除数据库失败」时解释了原因：

> 「这不是刚才的时候，还是写在文件夹里面，然后第一次见他的属于文件（被占用）……」
> 「**这样正在使用啊，正在使用**。」

**结论（重要）**：

| 现象 | 原因 | 处理 |
|---|---|---|
| 数据库文件在资源管理器里**删不掉**、**复制不动** | 文件正被 **SQL Server 服务（实例）占用** | 先**分离**数据库，再对文件做复制 / 移动 / 删除 |
| SSMS 里删除数据库报错「**无法删除正在使用的数据库**」 | 该数据库还有**活动连接** | 先断开连接（或先分离），再删除 |

> 这两条是同一条原理的两种表现，老师把它们当成一个「坑」反复讲。

## 四、数据库的收缩（自动收缩 / 手动收缩）

老师在 `[00:24:43] — [00:26:35]` 讲完自动增长后紧接着讲收缩。

### 4.1 两种收缩方式

| 方式 | 说明 |
|---|---|
| **自动收缩** | 在数据库属性（或选项）里把「自动收缩」打开，数据库会自己回收空闲空间 |
| **手动收缩** | 通过 **任务** 菜单手动执行一次收缩 |

### 4.2 手动收缩的操作步骤（老师演示路径）

1. 在对象资源管理器中选中目标数据库；
2. 右键 → **任务**；
3. 在「任务」子菜单里找到 **收缩** → **数据库**（也可以收缩**文件**）；
4. 在对话框里选择**要收缩到多大**：
   > 「收缩（到）最大可能空间多少，**你自己需要**（自己决定）。」
   > 转写里出现的具体数字为演示时的数值，不是固定要求。
5. 确认后执行。

> 💡 老师原话里的「收缩（数据）库、收缩（文件）」「收缩到最大可用空间多少，你自己需要」，
> 说的就是**收缩目标大小由操作者自己指定**，不是系统固定值。

## 五、数据表与数据库管理系统的实际应用

这一段老师从「数据库里到底存什么」讲到了身边真实在用的系统，是理解**为什么学数据库**的好材料。

### 5.1 数据库里存的是「表」，表里存的是「行」

老师当场新建了一个表来演示：

| 概念 | 老师的讲法 |
|---|---|
| **数据库** | 数据的「仓库」（原话碎片：「建数据库……数据的仓库」） |
| **表（数据表）** | 数据最终存在**表**里；「都在数据库……都在数据表」 |
| **列（字段）** | 建表时要定好有哪些列，例如 **学号、姓名、性别、年龄** 等 |
| **行（记录）** | 「**这一行是不是代表一个人（的）信息啊？**」——**一行 = 一条记录 = 一个对象** |

> ⚠️ 老师明确指出后面要重点做的方向：「**后面咱们要重点（讲）……加条件，都要（按）标准（规范）管理维护**」，
> 也就是后面会进入**数据的增删改查与条件筛选**。这一段是**铺垫**，本节没有展开写 SQL。

### 5.2 学校里的真实系统举例（老师逐个数）

| 系统 | 管的是什么 | 老师原话要点 |
|---|---|---|
| **教务管理系统** | 教学相关事务 | 「一个教务的教务管理系统」 |
| **学生管理系统（学籍）** | 管学生 | 与「学籍管理系统」是同一类 |
| **人事管理系统** | 管老师 | 「一个人事、管老师的**人事管理系统**」 |
| **财务 / 人力系统** | 财务、人力信息 | 「人力（资源）、（还有）财务，**肯定信息都不一样**」 |

**老师的核心观点**：

> 「这些数据都在学校（信息）中心，就在对面楼……都在那（个）里。」
> 「现在都实现数字化了，但是呢**数据（量）很高**。」
> 「你这个信息在（教务）处有了，在人事处也有了，**调出来（就能用）**——
> 要不然**再采集一遍**、需要的时候**再采集一遍**，反复再进行采集。」

**换句话说**：**数据库的最大价值就是「一次采集、多系统共享」，避免重复采集。** 这是老师这段闲聊里唯一的技术落点。

### 5.3 数据安全与隐私的顺带提醒（非考点，但老师强调过）

| 提醒 | 内容 |
|---|---|
| 权限 | 「你要（有）权限……**你没有权限，那就访问不了**」 |
| 可见性 | 「哪些信息……**有些人不用看，有些不能公开看**」 |
| 个人隐私 | 老师提醒同学：**不要把个人照片、隐私资料随意放在网上/公共空间** |
| 现状评述 | 老师认为国内对个人数据的保护「现在这个数据保护得不太够」，「每个人都有啥都是透明的」 |

## 六、数据库的分离与附加（★ 考试重点）

> 老师在 `[00:34:32]` 明确说过：「（以前）考试的时候……**考你哪两点？**」
> 结合上下文，这两点就是 **分离** 与 **附加**。这是本节最该背熟的一节。

### 6.1 为什么需要分离

**背景**：数据库文件（`.mdf` / `.ldf`）在**被 SQL Server 实例使用**时，是**不允许**被随便复制、移动、删除的。

> 老师原话（转写）：「这个数据我问你，你是复制也好，（删）掉也好，**想拿重新干的个是不允许的**。」
> 「你单独复制了，你（想）干啥子（就干啥子，那不行）……」

**老师补了一个版本差异的重要提示**：

> 「**那么在原来这个（SQL Server）2022 版本……在（SQL Server）12 点（？）之前的版本里面**，
> 那么这个数据，你是复制也好……**都是不允许的**。」
> 「（但是）这个**高版本的它允许了一下**，就不允许了。」（转写语义有粘连，见附录 B）

| 版本情况 | 能否直接复制数据库文件 |
|---|---|
| **旧版本**（老师提到 2012 / 2014 之类及更早） | **不允许**，文件被占用，复制/移动/删除都做不了 |
| **较高版本**（老师提到 2022 等 / 本次演示环境） | **由于版本升级、功能改变，情况有变化**——老师现场演示了「直接复制也能复制得到」的情形 |

> ⚠️ **这一段转写质量最差，但结论要记住**：
> **不能依赖「直接复制文件」这种野路子**，正确做法永远是「**先分离，再复制/移动，最后附加**」。
> 版本之间的差异老师自己也说「他版本升级功能强了……（别）买太（较）真了」，
> 也就是说**以老师演示的当前版本为准**。

### 6.2 分离数据库（Detach）——操作步骤

**操作路径**（老师一步步演示）：

1. 在 SSMS 的**对象资源管理器**中，**选中**要分离的数据库；
2. 右键 → **任务**；
3. 在任务子菜单里找到 → **分离**；
4. 弹出「分离数据库」对话框，**确认**后执行；
5. 分离成功后，该数据库**从 SSMS 的数据库列表中消失**，但 **`.mdf` / `.ldf` 文件仍然留在磁盘上**。

**分离的关键理解（老师原话）**：

> 「你要理解这**分离**啥意思？就是**第一个你要分离**，你要（把）数据库**选中的，从任务菜单里面选**的。
> 这里有一个大家（都）选（的）**分离数据库**，这样的方式嘛。」

**分离前必须做的检查**：

| 检查项 | 说明 |
|---|---|
| **有没有活动连接** | 有连接时分离会失败，需先断开（老师演示时遇到过类似提示） |
| **要不要先备份** | 老师提醒：**分离之前先考虑要不要备份**（原话碎片：「要不你要（先）备份」） |

### 6.3 分离之后就自由了

> 老师原话：「**分离出来了以后**……你就可以想对他**复制、删除，想干啥干啥**。」

| 分离前 | 分离后 |
|---|---|
| 文件被占用，删不掉、移不动（「你看他不让删，他们都删不了的呀」） | **可以随意复制、移动到别的文件夹、U 盘、别的硬盘** |
| 只能停留在原来的目录 | 可以**放到其他位置**，也可以**给别人用**（老师原话：「或者让别人用的」） |

### 6.4 附加数据库（Attach）——操作步骤

**使用场景**（老师讲了两种情况）：

1. **自己的数据库搬家**：把分离出来的文件复制到新位置后，要**重新让它出现在 SQL Server 里**；
2. **拿到别人的数据库**：同学/同事给你的 `.mdf` + `.ldf`，你**必须附加到自己的数据库管理系统里才能用**。

**操作路径**：

1. 在对象资源管理器中**右键「数据库」节点**（不是某一个具体数据库）→ **附加**；
2. 在弹出的「附加数据库」对话框里点 **添加**；
3. 在文件浏览里**找到并选中主数据文件（`.mdf`）**；
4. 系统会**自动带出对应的日志文件（`.ldf`）**——因为主数据文件里记录了日志文件的对应关系；
5. 确认 → 确定，附加完成后数据库**重新出现在数据库列表里**，即可正常使用。

**老师关于「附加时显示什么文件」的重要提示**：

> 「**你看主（数据文件）只显示 `.mdf`，这个日志（文件 `ldf`）……（列表里）都不显示。**」
> 「那么我要把这个（附加）的话，**首先你要（选对）**，你再来使用。」

> ⚠️ 这是常见失分点：**附加对话框里你需要手动选的是 `.mdf`（主数据文件），`.ldf` 由系统自动匹配**，
> 不要以为要一个一个把文件都手动加进去。

### 6.5 分离 / 附加 全流程速记

```
【搬家 / 给别人用】
  ① 备份（需要的话）
  ② 右键数据库 → 任务 → 分离
  ③ 到文件夹里，把 .mdf + .ldf 复制 / 移动到目标位置
  ④ 目标机器上：右键「数据库」→ 附加 → 添加 → 选中 .mdf
  ⑤ 确定，数据库回来了
```

| 关键点 | 一句话记住 |
|---|---|

## 七、数据库的删除（★ 永久删除，务必慎用）

### 7.1 操作路径

老师演示了两种删除方式：

| 方式 | 操作 |
|---|---|
| **图形界面（快捷菜单）** | 在对象资源管理器中**右键数据库 → 删除** |
| **命令方式** | 老师明确说：「**第二（种）还可以用命令来进行（删除）。**」<br>对应的 T-SQL 是 `DROP DATABASE`（**老师课上只提到「用命令」，未板书完整语句，此处为通用写法，请以教材为准**） |

### 7.2 两个必须记住的注意点

> **老师的原话（一定要背）**：

1. **「在数据库里面，你给它删除了以后，它就永久删除，大家一定要记住。」**
   —— **数据库的删除是永久的，不进回收站、不能撤销。**
2. **「大家也要注意，尤其里面的（数据）一定要慎用，一定要确认、再确认。」**
   —— 点击「确定」之前，**必须反复确认**。

> 老师还补了一句：「**一旦（删）出了，我（就）差不多（回不来了）**。」
> 也就是 **删了就没了**，所以「**备份**」这件事在下面被专门提出来。

### 7.3 删除失败与「正在使用」提示

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示「**无法删除正在使用的数据库**」 | 有活动连接 | 先断开连接（可先分离），再删 |
| 提示与之前演示的「无法（操作）」**一模一样** | 同一类「正在使用」保护 | 同上 |

> 老师在 `[00:48:16] — [00:48:41]` 特意做了对比：
> 「**这里面这个提示……跟我们刚才说（的）没有这个提示是一样的，就是（提示）是一模一样的。**」
> —— 也就是说，**凡是「文件/数据库正在被使用」的报错，处理思路都是同一条**。

### 7.4 备份意识（老师顺带强调，为后面章节埋伏笔）

> 「（你要）**备份**……后面（课）都还讲。」
> 「（你要不）备份，（那就）无所谓（了，反正删了就没了）。」

**要点**：

- **备份（Backup）/ 还原（Restore）是后面章节的内容**，本节只是「点一下」；
- 但老师用它来解释**为什么删除要慎之又慎**：**没有备份，删了就是永久损失。**

> 💡 **易错点总结（本节最实用的一条）**：
> **删除数据库 = 永久删除 + 无法撤销 → 删之前一定先备份、先确认、先断开连接。**

## 易错点清单

| # | 易错点 | 正确做法 |
|---|---|---|
| 1 | 以为「一个数据库一个文件就够」 | **至少两个**：数据文件 + 日志文件 |
| 2 | 多文件定义时**逗号写错**（漏写 / 多写） | 括号之间加逗号，**最后一项后面不加** |
| 3 | `ON PRIMARY` 与 `LOG ON` 顺序颠倒 | **数据在前、日志在后**，按教材顺序写 |
| 4 | 把**逻辑名**当**物理文件名** | `NAME` 是逻辑名，`FILENAME` 才是磁盘文件 |
| 5 | 直接在资源管理器里删 / 移数据库文件 | 删不掉、移不动——**先分离** |
| 6 | 附加时手动去加 `.ldf` 或加错文件 | **只选 `.mdf`**，日志文件由系统自动匹配 |
| 7 | 以为「分离 = 删除」 | **分离不删文件**，只是从管理系统摘出；**删除**才是永久删除 |
| 8 | 删除数据库时没看有没有连接 | 先断开连接 / 先分离，再删 |
| 9 | 认为删错了可以恢复 | **永久删除，不可恢复**，删前先备份、确认再确认 |
| 10 | 直接把数据库文件拷给别人 / 交作业 | 必须**先分离**再复制文件 |
| 11 | 网上抄代码直接交 | **数据库名不同**，要按自己的库名改 |
| 12 | 把「自动关闭」和「自动收缩」搞混 | 两个都在属性里，**自动关闭一般要取消勾选**；自动收缩是回收空间 |
