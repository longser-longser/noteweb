## 一、约束的第二种建法：用语句写

约束有两种建法，前面用的是第一种（在表设计器里点出来的）：

| 建法 | 怎么做 | 要求 |
|---|---|---|
| **图形界面** | 在表设计器里点钥匙（主键）、勾 / 取消「允许 Null 值」、填「默认值或绑定」、写检查表达式 | **必须会** |
| **语句** | 写在 `CREATE TABLE` 的列定义后面 | 老师只简单解释了一遍，**明确说「不要求」**，会看即可 |

一条列定义的三个组成部分，落到语句上就是这个样子：

```sql
CREATE TABLE 表名
(
    字段名   数据类型   约束,      -- 第 1 列：名字 + 类型 + 约束
    字段名   数据类型   约束       -- 最后一列后面不加逗号
);
```

> 💡 **记忆点**：一条列定义 = **字段名 + 数据类型 + 约束**。三样缺一样，这个字段就定义不完整。

## 二、数据类型与标识列

### 2.1 数据类型要会查表

数据类型不用背，但要会查教材第 73 页那张表，并且看懂三件事：

| 看什么 | 为什么 |
|---|---|
| **占几个字节 / 几位** | 决定存储空间，也决定能存多大的数 |
| **能表示的范围** | 超出范围就存不进去（例如整数类型存不了小数） |
| **能不能存小数、能存几个字符** | 决定这个字段该选整数型还是字符型、长度定多少 |

### 2.2 整数类型：位数越多，范围越大

教材上的整数类型从小到大：

| 类型 | 位数 | 说明 |
|---|---|---|
| `TINYINT` | 8 位 | 最小的整数类型 |
| `SMALLINT` | 16 位 | 比 `TINYINT` 大一级 |
| `INT` | 32 位 | 最常用的整数类型 |
| `BIGINT` | 64 位 | 范围最大，最大能到 **2 的 63 次方减 1** |

> 💡 **记忆点**：位数翻一倍，能表示的范围不是翻一倍，而是**翻很多倍**——所以选类型时宁可先看清楚范围，别拿 `TINYINT` 去装学号、身份证号这种大数。

### 2.3 标识列：自动编号的那一列

标识列 **不是约束**，是列的一种属性，作用是让系统自动往这一列里填编号。

| 项目 | 说明 |
|---|---|
| **两个参数** | **种子**（第一条记录填几）、**增量**（每往后一条加多少） |
| **写法** | `IDENTITY(种子, 增量)` |
| **效果** | `IDENTITY(1,1)` → 1、2、3、4…… 一条一条往下排 |
| **特点** | 值由系统自动填，**手输不进去**，也不用你管 |

```sql
CREATE TABLE 成绩表
(
    编号   INT   IDENTITY(1,1),      -- 标识列：种子 1、增量 1，自动编号
    ...
);
```

课上成绩表的「编号」列就是标识列：种子是 1、增量是 1，所以前面是 1，下一条在 1 的基础上加 1，变成 2、3、4……

## 三、数据完整性：三类，三种约束

### 3.1 什么叫数据完整性

**完整性 = 存进去的数据要「对」、要「准」**——每一条数据都合法、都符合业务上的要求，不能想填什么就填什么。

实现完整性的办法就是**约束**：每存一条数据，系统先检查它合不合法，不合法就不让进。

> 💡 **最重要的一句**：数据完整性出问题，**多半是设计表的时候没设计好**。所以设计表这一步非常关键——设计的时候就要想方设法保证以后存进来的数据都是对的。

老师举的几个例子，说明「类型没选对、长度没定对」会出什么事：

| 现象 | 问题出在哪 | 怎么防 |
|---|---|---|
| 成绩列写成字符型，"张三"也能存进去 | 类型选错 | 成绩要用数值类型 |
| 年龄填成 26.1 岁 | 成年人的年龄是整数 | 用整数类型 |
| 身份证号位数不对 | 长度没定好 | 定长、把位数定准 |
| 性别填了标准以外的值 | 超出允许的取值 | 用检查约束限定 |

### 3.2 实体完整性——靠主键

**一句话：每一行必须是唯一的一个实体，不能重复、不能被认错。**

| 要点 | 说明 |
|---|---|
| 谁保证 | **主键** |
| 主键的两条硬规矩 | **不允许重复**、**不允许为空** |
| 课上例子 | 学号唯一、身份证号唯一——一个人只能有一条记录 |
| 界面上怎么看 | 主键那一列前面有一把**金色的钥匙** |

### 3.3 域完整性——靠取值范围

**「域」就是取值范围**：这个字段只许填这个范围里的值。

| 字段 | 域（取值范围） | 靠什么约束 |
|---|---|---|
| 成绩 | **0—100**，超了就不对 | 检查约束 |
| 邮箱 | 前后可以任意，但**必须含 `@`** | 检查约束 |
| 性别 | 只能是标准里的那两种写法，不能乱填 | 检查约束 + 默认值 |
| 姓名 | 不能空着 | 非空 |

所以域完整性靠的是**数据类型 + 检查约束 + 默认值 + 非空**这一组，一起把单个字段的值管住。

### 3.4 参照完整性——靠外键

**一句话：保持表与表之间已经定义好的关系。**

- 学生的基本信息在学生信息表里，成绩存在成绩表里，两张表靠**学号**关联；
- 课程信息在课程信息表里，成绩表靠**课程编号**关联；
- 所以：**成绩表里出现的学号，必须先在学生信息表里存在；出现的课程编号，必须先在课程信息表里存在。**

如果成绩表里冒出一个学生信息表里根本没有的学号，这条成绩就没人认——这就是破坏参照完整性，系统不允许。

参照完整性（也叫引用完整性）靠**外键**实现：在成绩表上给学号建一个外键指向学生信息表，给课程编号建一个外键指向课程信息表。

### 3.5 三类完整性对照表（背这张表）

| 完整性 | 管什么 | 靠什么实现 | 课上例子 |
|---|---|---|---|
| **实体完整性** | 每一行唯一、能区分开 | **主键** | 学号不能重复 |
| **域完整性** | 单个字段的取值范围 | 数据类型、检查约束、默认值、非空 | 成绩 0—100；邮箱必须带 `@` |
| **参照完整性** | 表与表之间的关系 | **外键** | 成绩表的学号和课程编号必须先在两张主表里存在 |

> 💡 **记忆口诀**：**实体看主键、域看范围、参照看外键**。

## 四、维护表结构：加列、改列、删列

### 4.1 为什么强调「建表时一次定好」

表一旦建好、数据一旦录进去，再回头改结构，代价就大了。老师打的比方：

> 图纸已经定好了，楼都盖了两三层，才发现图纸上少了东西——只能拆了重来。

所以规矩是：**在还没有数据的时候把表结构维护好；数据录进去以后，就尽量别再动结构。**

### 4.2 进表设计器

对象资源管理器 → 展开数据库 → 展开「表」→ **右键要改的表 → 设计**，就打开了表设计器。

表结构的维护就三件事：**添加（列）、修改（列）、删除（列）**。

### 4.3 添加列

在表设计器里加一行：

1. 写上**列名**（例如 `备注`）；
2. 选**数据类型**（例如 `VARCHAR`，并按需要定长度）；
3. 决定**「允许 Null 值」**勾不勾；
4. 保存。

两个位置上的细节：

| 情况 | 新列出现在哪 |
|---|---|
| 直接在最后一行往下加 | 排在**所有列的后面** |
| 先**选中某一列**再插入新列 | 排在**选中那一列的上边** |

> ⚠️ 想好了再定位置：列加错地方，后面还得再挪。

### 4.4 修改列

在表设计器里直接改，能改三样：

| 改什么 | 例子 |
|---|---|
| **数据类型 / 长度** | 把性别列的长度改大 |
| **是否允许为空** | 把「允许 Null 值」的勾去掉，这一列就变成非空 |
| 列名 | 必要时改名 |

改完保存。

### 4.5 删除列

选中要删的那一列 → **右键 → 删除** → 保存。删掉的列连同里面的数据一起没了。

### 4.6 保存时的坑：提示「要求删除并重新创建表」

> ⚠️ **现象**：在表设计器里改完，一点保存就弹提示——**「你所做的更改要求删除并重新创建以下表」**，保存不了，改动等于白做。
>
> **原因**：SSMS 默认勾了一个选项，凡是「改动需要把表删了重建」的操作，一律拦住不让保存。
>
> **解决**：
> 1. 菜单 **工具 → 选项**；
> 2. 左边找到 **设计器 → 表设计器和数据库设计器**；
> 3. 把 **「阻止保存要求重新创建表的更改」** 前面的勾**去掉**；
> 4. 确定，再回来保存，就能存上了。
>
> 保存完**刷新一下表**（刷新对象资源管理器里的表节点），改动的列才会显示出来。

> 💡 **记忆点**：**工具 → 选项 → 设计器**。选项对话框里分类很多（环境、项目、设计器……），这个开关就藏在「设计器」那一类下面，找不到就往「设计器」里翻。

## 五、删除表

在对象资源管理器里选中要删的表 → **右键 → 删除** → 弹出确认对话框 → 确定。

- 表删掉以后，**表里的数据也一起没了**；
- 删之前先确认：这张表里的数据是不是还要用——**表一删，里面的记录全跟着没**。

## 六、数据更新（一）：往表里插入记录

### 6.1 数据更新有哪三种操作

| 操作 | 干什么 | 语句 |
|---|---|---|
| **插入** | 往表里加新记录 | `INSERT` |
| **修改** | 改已有记录的值 | `UPDATE` |
| **删除** | 把记录整行拿掉 | `DELETE` |

本节用**图形界面**做，语句写法对照着看。

### 6.2 图形界面录入：编辑前 200 行

1. 对象资源管理器里**右键目标表**；
2. 选 **「编辑前 200 行」**；
3. 在网格里一行一行往下填，填完把光标移开，数据就存进去了。

录的时候能直接看出前面设的约束在起作用：

| 看到的 | 说明 |
|---|---|
| 主键列前面有**金色的钥匙** | 这一列是主键 |
| 性别一列**自动填好了** | 设了默认值，不填就取默认值 |
| 成绩表的编号一列**灰的、点不进去** | 标识列，系统自动填，手输不进去 |

### 6.3 用语句插入（对照）

```sql
INSERT INTO 学生信息表 (学号, 姓名, 性别)
VALUES ('20250101', '张三丰', '男');       -- 邮箱不填也能进：只设了"必须含 @"的检查，没设非空
```

### 6.4 逐条验证约束：故意输错，看系统拦不拦

录数据的过程，其实就是把前面设的约束**一条一条验证一遍**。老师是故意输错来验证的：

| 验证哪条约束 | 怎么试的 | 结果 |
|---|---|---|
| **主键（实体完整性）** | 学号 20250101 已经录过张三丰，再插一条同学号的记录 | 报错：「**不能在对象 … 中插入重复键**」，违反 PRIMARY KEY 约束，插不进去；把学号改掉才能插 |
| **检查约束（邮箱）** | 邮箱里不写 `@` | 不让进，违反了检查约束 |
| **检查约束（邮箱）** | 邮箱写成「前面任意 + `@` + 后面任意」 | 通过——检查的就是**必须含 `@`**，前后是什么不管 |
| **非空** | 邮箱这一格**空着不填** | 能进去——邮箱只设了检查（必须含 `@`），**没设非空** |
| **默认值** | 性别不填 | 自动填上默认值 |
| **标识列** | 想手动往编号列里输值 | 输不进去，系统自动生成 |
| **检查约束（成绩）** | 成绩输 **120**（域是 0—100） | 报错，超出范围；改成 **40** 才通过 |
| **外键（学号）** | 成绩表里输学号 **20251008**，学生信息表里没有这个人 | 违反外键约束，插不进去 |
| **外键（课程编号）** | 成绩表里输课程编号 **8**，课程信息表里没有这门课 | 违反外键约束，插不进去 |

> 💡 报错对话框的标题里带着数据库名（课上这个库叫**数据库学习管理系统**），从标题就能看出自己是在哪个库、哪张表上出的错。

### 6.5 标识列的坑：号用掉了就作废，不会回头补

> ⚠️ **现象**：成绩表的编号本来是 7，这一条输错了（或者被删掉了），再插一条新记录，编号直接变成 **8**——**7 就空在那里，永远补不回来**。

三条要记住：

| 情况 | 标识列会怎么样 |
|---|---|
| 一条记录**插入失败**（比如违反了别的约束） | 那个号**已经被用掉了**，下一条接着往后排 |
| 一条记录**被删除** | 号**不回收**，后一条继续往后加 |
| 把记录改回来、重新输一次 | 号**不会退回**原来的值 |

所以：**标识列只保证「自动、不重复」，不保证「连续」**。中间空几个号是正常现象，别当成错误去修。

## 七、数据更新（二）：删除记录，以及外键带来的顺序问题

### 7.1 图形界面删记录

1. 在「编辑前 200 行」的网格里**选中要删的那一行**（例如最后一条记录）；
2. **右键 → 删除**；
3. 弹出确认对话框，提示**删除以后无法撤销**；
4. 确定。

> ⚠️ **删了就删了，恢复不了**。删错了只能把数据重新输一遍，所以点「确定」之前先看清楚选中的是哪一行。

### 7.2 删主表记录被外键拦住

课上删的是学生信息表里**小张**那条记录：小张的学号在成绩表里**还有成绩**。

| 现象 | 原因 |
|---|---|
| 删除时报「发生冲突」，删不掉 | 成绩表里还有引用这个学号的记录，**违反参照完整性** |

道理很直白：**如果把小张删了，成绩表里他的成绩就没有对应的人了**——这些成绩成了没人认的数据，参照完整性被破坏，所以系统不让删。

### 7.3 正确顺序：先删子表，再删主表

要删学生信息表里的某个人，必须**先把他名下的成绩删干净**：

```sql
-- 以学号 20250101 的张三丰为例
-- 第一步：先在子表（成绩表）里删掉这个学号的所有成绩
DELETE FROM 成绩表
WHERE 学号 = '20250101';

-- 第二步：再回主表（学生信息表）删这个人
DELETE FROM 学生信息表
WHERE 学号 = '20250101';
```

顺序反过来就删不动。表与表之间有外键的时候，**永远先动子表，再动主表**：

| 想做的操作 | 会被拦吗 | 正确做法 |
|---|---|---|
| 往成绩表插一条「学号不存在」的成绩 | 拦 | 先到学生信息表把这个人建出来 |
| 删学生信息表里**有成绩**的学生 | 拦 | 先在成绩表删掉他的成绩，再删人 |
| 删学生信息表里**没有成绩**的学生 | 不拦 | 直接删 |

## 八、数据库关系图：把三张表的关系画出来

外键建好了，光看列名不直观。SSMS 里有现成的**数据库关系图**，能把表与表的关系画成一张图。

### 8.1 建图的操作路径

| 步骤 | 操作 |
|---|---|
| 1 | 对象资源管理器 → 展开数据库 → 展开**数据库关系图** |
| 2 | **右键 → 新建数据库关系图** |
| 3 | 弹出「添加表」对话框，把**三张表都选上**（按住 Ctrl 多选），点**添加** |
| 4 | 自动生成关系图；布局不好看可以拖动调整 |
| 5 | **保存**，下次打开还在 |

### 8.2 图怎么看

| 图上的东西 | 含义 |
|---|---|
| 一个方框 | 一张表，框里列出它的列 |
| 两个框之间的连线 | 一条**外键**关系 |
| **钥匙指向的那一端** | **主表（目标表）**——被引用的那一张 |
| 另一端 | **子表**——引用别人的那一张 |

课上这三张表画出来的关系就是两条线：

| 关系 | 靠哪一列 | 谁引用谁 |
|---|---|---|
| 学生信息表 ↔ 成绩表 | **学号** | 成绩表引用学生信息表 |
| 课程信息表 ↔ 成绩表 | **课程编号** | 成绩表引用课程信息表 |

> 💡 **用处**：关系图是检查外键建对没有的最快办法——三张表应该是「学生信息表、课程信息表在两头，成绩表在中间，被两条线连着」；少一条线，就说明有一个外键漏了。

## 九、查询的入口：比较运算符与 `_` 通配符

### 9.1 比较运算符

查询要写条件，条件里用的就是比较运算符（教材第 128 页有表）：

| 运算符 | 含义 |
|---|---|
| `=` | 等于 |
| `>` | 大于 |
| `>=` | 大于等于 |
| `<` | 小于 |
| `<=` | 小于等于 |
| `<>` | 不等于 |
| `!=` | 不等于（另一种写法） |

> 💡 **记**：**不等于有两种写法——`<>` 和 `!=`，意思完全一样**；等于只有 `=` 一种写法（不是 `==`）。

### 9.2 通配符 `_`：正好占一个字符

`LIKE` 里可以用通配符，前面已经用过 `%`（任意多个字符）。本节重点补另一个：**下划线 `_`**。

| 通配符 | 代表什么 |
|---|---|
| `%` | **任意多个**字符（0 个、1 个、很多个都行） |
| `_` | **正好一个**字符（一个位置只占一个字，写几个 `_` 就占几个位置） |

```sql
-- 姓张、两个字的名字：第一个字固定是"张"，第二个字任意
SELECT * FROM 学生信息表
WHERE 姓名 LIKE '张_';
```

这条条件的意思拆开看：**第一个字符固定是「张」，第二个字符任意**——所以它管的是**两个字**的张姓名字。

> ⚠️ 「张三丰」这种三个字的名字，用 `'张_'` 是查不出来的：`_` 只占**一个**位置，三个字就差一个位置，得写两个 `_`。

## 复习要点

| 序号 | 要点 | 所在章节 |
|---|---|---|
| 1 | 一条列定义 = **字段名 + 数据类型 + 约束** | 一 |
| 2 | 约束有图形界面和语句两种建法，**语句建约束不要求掌握** | 一 |
| 3 | 数据类型要会查教材第 73 页的表：**位数、范围、能否存小数** | 2.1 |
| 4 | 整数类型从小到大：`TINYINT` → `SMALLINT` → `INT` → `BIGINT`；`BIGINT` 到 **2 的 63 次方减 1** | 2.2 |
| 5 | **标识列 = `IDENTITY(种子, 增量)`**，是列属性、不是约束，值不能手输 | 2.3 |
| 6 | **数据完整性 = 数据要对、要准**，靠约束实现；出问题多半是设计表没设计好 | 3.1 |
| 7 | **实体完整性 → 主键**（不重复、不为空） | 3.2 |
| 8 | **域完整性 → 取值范围**（数据类型、检查、默认值、非空）：成绩 0—100、邮箱带 `@` | 3.3 |
| 9 | **参照完整性 → 外键**：成绩表的学号、课程编号必须先在两张主表里存在 | 3.4 |
| 10 | 表结构维护三件事：**加列、改列、删列**；路径是**右键表 → 设计** | 4.2—4.5 |
| 11 | 新列默认排在最后；**先选中某列再插入，新列排在选中列的上边** | 4.3 |

| 13 | 数据更新三种操作：**插入、修改、删除**；图形界面用 **「编辑前 200 行」** | 6.1 / 6.2 |
| 14 | 主键重复 → 「**不能在对象 … 中插入重复键**」 | 6.4 |

## 易错点清单

| # | 易错点 | 正确做法 |
|---|---|---|
| 1 | 把**标识列**当成一种约束 | 标识列是**列的属性**，写法 `IDENTITY(种子, 增量)` |
| 2 | 以为标识列的号一定连续 | 只保证自动、不重复；**插失败、删除都会跳号**，不回收 |
| 3 | 认为「完整性」是抽象概念，跟建表无关 | 三类完整性**全靠约束堆出来**，设计表时就要想好 |
| 4 | 混淆三类完整性 | **主键管实体、范围管域、外键管参照** |
| 5 | 以为外键只防「插错」，不管删除 | 删除主表记录时**也会被外键拦住** |
| 6 | 删学生前不删成绩，删不动还找不到原因 | **先删子表（成绩表），再删主表（学生信息表）** |
| 7 | 改完表结构直接点保存，被提示「要求删除并重新创建表」 | 先到 **工具 → 选项 → 设计器** 去掉那个勾，再保存 |
| 8 | 以为新加的列会自动排在你想要的位置 | 默认排在最后；要换位置**先选中目标列再插入** |
| 9 | 以为邮箱是必填（因为设了检查） | 检查约束只管「**必须含 `@`**」，**没设非空**，空着能进 |
| 10 | 写成 `==` 当「等于」，或者只记住一种「不等于」 | 等于只有 `=`；不等于 **`<>` 或 `!=`** |
| 11 | 把 `_` 当成「任意多个字符」 | `_` 只占**一个**字符，任意多个是 `%` |
| 12 | 删记录时不看选中的是哪一行 | 删除**不可撤销**，删错了只能重录 |
