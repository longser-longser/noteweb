# SQL Server 数据库 课堂笔记（第 21—24 节）——用语句往表里放数据：`INSERT` 的填空格式、约束的一次次拦截与跨表批量插入

## 一、数据库建好之后：数据处理的四件事

### 1.1 从「结构」转到「数据」

前面十来节的功夫几乎都花在**结构**上：建库、建表、定字段和数据类型、加主键非空默认值检查外键（第 9—20 节）。等到表里已经有了一行行数据，重点就换成**数据本身**怎么动。老师把它拆成四块，顺序是固定的：

| 顺序 | 做什么 | 对应语句 | 前面做过没有 |
|---|---|---|---|
| 1 | 添加数据（插入） | `INSERT` | 第 17—20 节插过一行三列 |
| 2 | 修改数据 | `UPDATE` | 只提到「后面再讲」 |
| 3 | 删除数据 | `DELETE` | 第 17—20 节删过记录 |
| 4 | 查询数据 | `SELECT` | 本节只开了个头 |

老师原话的意思是：数据库建完、表建完，往下就是「对数据进行处理」，而这四块是处理数据的全部内容，也是这门课的重点。

### 1.2 同一件事，两条路

| 做法 | 怎么操作 | 本节的位置 |
|---|---|---|
| **图形界面** | 右键表 →「编辑前 200 行」，在网格里直接敲、直接删 | 第 17—20 节已经做过，本节不再重复 |
| **SQL 语句** | 在查询编辑器里写 `INSERT …`，分析、执行 | **本节的主线** |

两条路看起来一个点鼠标、一个敲键盘，但**底层守的规矩完全一样**——这一点在第六节会被约束一条一条证明。

### 1.3 为什么「查询」排第四，却是最要紧的一条

四块里查询排在最后，老师却反复强调它最重要。他给了两个例子：

- **搜索引擎**：百度、必应这些，本质就是「在海量数据里把你要的那几条找出来」。数据库的查询是同一件事，只不过数据在自己机器上、量小些。
- **SQL 注入**：有人想进别人的系统，第一步干什么？先进数据库，**先查一下你的表里到底有没有数据**——有数据才值得往下破解，没数据扭头就走。而他用到的第一条语句就是查询语句。

> 💡 一句话记：**数据库里最常用的语句，第一条就是查询。** 本节先把「往里放」讲清楚，是因为没有数据就没得查。

## 二、写语句的地方：查询编辑器

### 2.1 从「新建查询」进去

工具栏上有一个**新建查询**按钮，单击它，右边就打开一个**查询编辑器**（一片空白的编辑区）。语句就写在这里面，写完执行。

### 2.2 第一件事：确认自己在哪个数据库里

写语句之前要先想清楚一件事：**这张表在哪个数据库里**。老师说这就像在资源管理器里新建文件夹——你总得先打开那个文件夹，才能在里面动东西。

- 打开「数据库学习管理系统」，把里面的表展开，能看见 学生信息表、课程信息表、成绩表；
- 也可以在编辑器上方的**数据库下拉框**里切过去，切完再写语句。

位置选错了，语句里的表名就找不到——这一步是「先定位、再动手」。

### 2.3 关键字是蓝色的，写完先「分析」

编辑器里有一眼就能看出来的区别：`INSERT`、`INTO`、`VALUES` 这些**关键字显示成蓝色**，而表名、列名、自己填的值是黑的。老师说：**蓝色的都是固定的，黑的才是你要填的。**

写完不要急着执行，先点**分析**（检查语法），没问题再**执行**。这个习惯在第四节的报错现场会救你好几次。

## 三、`INSERT` 的格式：一道填空题

### 3.1 骨架

教材第 91 页给了完整语法，老师把它简化成一句话：**关键字固定，其余全是填空**。

```sql
INSERT [INTO] 表名 [(列1, 列2, …)]
VALUES (值1, 值2, …);
```

### 3.2 三段各填什么

| 位置 | 填什么 | 说明 |
|---|---|---|
| `INSERT` | 不动 | 关键字，蓝色 |
| `[INTO]` | 可写可不写 | 带上更清楚，不带也执行得通 |
| 表名 | 你要往哪张表里插 | 学生信息表 / 课程信息表 / 成绩表 |
| `(列1, 列2, …)` | 你打算给**哪几列**赋值 | 列名之间用英文逗号；整段可以省略（见 3.4） |
| `VALUES (…)` | 每列对应的值 | 值的**个数、顺序、类型**都要和前面列的一一对应 |

一句话概括这条语句在干什么：**「往哪张表的哪几列，按顺序填这几个值。」**

### 3.3 `INTO` 写不写都行

老师特意点了一句：`INTO` 是可有可无的，写上是习惯，不写照样跑。所以看到别人代码里没有 `INTO`，不要以为写错了。

### 3.4 全部列 与 部分列

| 写法 | 列名要不要写 | 值的个数 | 适用场合 |
|---|---|---|---|
| **全部列** | 可以整段省略，也可以全写出来 | 必须等于表的**列总数** | 一行数据齐齐全全地录进去 |
| **部分列** | **必须写**，写你要给值的那几列 | 等于你写了几列 | 有些列先不给值，让它空着或取默认值 |

> ⚠️ **易错点**：省略列名段（`INSERT INTO 表名 VALUES (…)`）时，值的顺序必须**和表设计器里列的顺序一模一样**，一个都不能少。少给一列、多给一列都会报错，所以老师演示时宁可把列名全写出来——写清楚了，值对着列名走，不容易错位。

### 3.5 标点一律英文

这是本节被反复强调的一条：**逗号、括号、单引号，全部用英文半角**。中文逗号「，」长得像英文逗号「,」，混进去以后语句在分析阶段就过不去。另外逗号只用在**两项之间**：最后一个值后面不加逗号，整条语句以一个分号结束。

```sql
-- 对的
VALUES ('2025011', '周之若', '女')

-- 错的：中间那个是中文逗号
VALUES ('2025011'，'周之若', '女')
```

## 四、现场演示（一）：把一名学生的整行信息插进去

### 4.1 要做什么

往**学生信息表**里插一行完整的记录。学生信息表一共八列：

| 列名 | 类型 | 这一行给什么值 |
|---|---|---|
| 学号 | `VARCHAR(20)` | `'2025011'` |
| 姓名 | `VARCHAR(20)` | `'周之若'` |
| 年龄 | `INT` | `16` |
| 性别 | `CHAR(2)` | `'女'` |
| 专业 | `VARCHAR(30)` | `'计算机应用'` |
| 出生日期 | `DATE` | `'2009-09-09'` |
| 家庭地址 | `VARCHAR(50)` | `'河南省郑州市'` |
| 邮箱 | `VARCHAR(50)` | `'zzr@163.com'` |

**为什么这八个值要这么写**：学号、姓名、性别、专业、家庭地址、邮箱是字符型，值要拿**单引号**包起来；年龄是整数，直接写数字；出生日期是日期型，写成 `'年-月-日'` 的字符串形式，系统自己转成日期。

### 4.2 写什么语句

```sql
INSERT INTO 学生信息表 (学号, 姓名, 年龄, 性别, 专业, 出生日期, 家庭地址, 邮箱)
VALUES ('2025011', '周之若', 16, '女', '计算机应用', '2009-09-09', '河南省郑州市', 'zzr@163.com');
```

八列对八个值，位置一一对应：第 1 个值给学号，第 2 个值给姓名……第 8 个值给邮箱。

### 4.3 第一版：报「值的数目不对」

第一次执行，语句被拦下来了，报错的大意是：**列的数目小于 `VALUES` 里指定的值的数目**。老师当场数了一遍——列是八个，值是九个，**多了一个**。删掉多的那一个，数目对上了。

> ⚠️ **易错点**：`INSERT` 最常见的错就是「数不对」。写完先自己数一遍：左边括号里几个列名，右边括号里就必须几个值。多敲一个逗号，值那边就会多出一个空位，同样是数目不符。

### 4.4 第二版：报「日期转换失败」

数目对了，下一版又被拦：**从字符串转换日期和/或时间时，转换失败**。问题出在出生日期这一格——日期型列的字符串写法有固定形状，写歪了就转不过去。改成 `'2009-09-09'` 这种「年-月-日」之后才通。

| 报错信息 | 指向哪里 | 怎么改 |
|---|---|---|
| 列的数目小于 `VALUES` 中指定的值的数目 | 列的个数 ≠ 值的个数 | 数一遍，补齐或删掉多余的 |
| 从字符串转换日期和/或时间时，转换失败 | 日期列的值写不成日期 | 改成 `'2009-09-09'` 这样的写法，并加单引号 |

### 4.5 第三版：逗号是中文的

再改一版，分析就报**语法错误**，位置指在逗号附近。原因还是标点：某两个值之间用的是中文逗号。改回英文逗号，语句才通过分析。

老师的顺序是：**先分析，后执行**。分析只检查语法，几分钟就能把「括号、逗号、引号」这类毛病挑出来，比执行到一半再猜错在哪快得多。

### 4.6 成了以后怎么验证

执行成功，消息区只告诉你「一行受影响」，看不到数据长什么样。要看结果，还得回到熟悉的那个入口：右键**学生信息表** →「编辑前 200 行」，刷新，刚才那一行就在里面了——学号 2025011、姓名周之若、性别女，一列一列都对得上。

> 💡 「一行受影响」这句话是**结果的样子**：它只报条数，不报内容。想确认内容，永远去「编辑前 200 行」里看。

## 五、现场演示（二）：只插一部分列

### 5.1 哪几列可以省

学生信息表的八列里，有两列是**必须给值**的：

| 列 | 为什么不能省 |
|---|---|
| 学号 | 主键，不允许为空 |
| 姓名 | 建表时标了 `NOT NULL` |

其余六列（年龄、性别、专业、出生日期、家庭地址、邮箱）都可以不给值——不给就是 `NULL`（性别给了默认值 `'男'`，不给值时取默认值）。

### 5.2 语句与结果

```sql
INSERT INTO 学生信息表 (学号, 姓名, 性别)
VALUES ('2025012', '李小雨', '女');
```

执行成功。回到「编辑前 200 行」看这一行：学号和姓名、性别有值，**其余六列空着**（显示成 `NULL`）。这就是「部分列插入」的样子——列名段写了几列，就只给这几列赋值。

> ⚠️ **易错点**：省略列名段（`INSERT INTO 表名 VALUES (…)`）**不能**用来做部分列插入。一旦省了列名，系统就认为你要按整张表的列顺序给全部列赋值，少给一个都不行。部分列插入必须把列名写出来。

### 5.3 只想执行其中一句：先选中

查询编辑器里常常堆了好几条语句。老师演示时把光标放在某一条上，先说了一句很实用的话：**要单独执行某一部分，就先把那一段选中，再分析、再执行**。不选中的话，编辑器会把它上面的语句一起送出去，前面那条一报错，后面的就跟着不执行。

## 六、约束会一条一条把你拦住

语句插得顺了，老师开始故意插错——**每插错一次，就有一条约束跳出来拦**。这一段是本节的核心：它证明「用语句插」和「用界面插」守的是同一套规矩。

### 6.1 主键重复：实体完整性

把已经插过的学号 `'2025011'` 再插一次：

```sql
INSERT INTO 学生信息表 (学号, 姓名)
VALUES ('2025011', '另一个人');
```

报错：**违反了 PRIMARY KEY 约束，不能在对象 'dbo.学生信息表' 中插入重复键**。

**为什么**：学号是主键，主键的值在整张表里**唯一、不能重复**——这正是**实体完整性**。想插进去，只能换一个没用过的学号。

### 6.2 姓名不给值：非空约束

```sql
INSERT INTO 学生信息表 (学号, 年龄)
VALUES ('2025013', 17);
```

报错：**不能将值 NULL 插入列 '姓名'，表 'dbo.学生信息表'；列不允许有 Null 值。INSERT 失败。**

**为什么**：姓名列建表时标了 `NOT NULL`。你没写这一列，系统就按 `NULL` 去插，`NULL` 撞上非空约束，插不进去。

### 6.3 邮箱里没有 @：检查约束

```sql
INSERT INTO 学生信息表 (学号, 姓名, 邮箱)
VALUES ('2025013', '王一鸣', 'wangyiming163.com');
```

报错：**INSERT 语句与 CHECK 约束冲突。冲突发生在数据库 "数据库学习管理系统"、表 "dbo.学生信息表"、列 '邮箱'。**

**为什么**：邮箱列当年加过检查约束 `CHECK (邮箱 LIKE '%@%')`——值里必须含 `@`。`'wangyiming163.com'` 里没有 `@`，被拦；补上 `@`（比如 `'wangyiming@163.com'`）就进去了。

### 6.4 一张表看完这几次拦截

| 故意插错的地方 | 报什么错 | 被哪条约束拦住 | 属于哪类完整性 |
|---|---|---|---|
| 学号 `'2025011'` 再插一次 | 违反了 PRIMARY KEY 约束，不能在对象中插入重复键 | 主键 | 实体完整性 |
| 姓名这一列不给值 | 不能将值 NULL 插入列 '姓名' | 非空 | 域完整性 |
| 邮箱 `'wangyiming163.com'`（无 `@`） | INSERT 语句与 CHECK 约束冲突…列 '邮箱' | 检查约束 | 域完整性 |

### 6.5 结论：语句不是后门

老师把这几次演示收到一句话上：**用语句往表里插数据，和用图形界面在网格里敲数据，要求完全一样**——你设计表时定了哪些约束，语句就得满足哪些约束，违反了照样报错、照样插不进去。

> ⚠️ **易错点**：不要把报错当成「语句写错了」。报错分两种：**语法错**（逗号、括号、关键字拼错，分析阶段就拦）和**约束错**（语句能跑，但数据不合规矩，执行阶段才拦）。看错误信息里有没有出现约束名、列名，就能分清是哪一种。

## 七、一次插多行；把一个表的数据搬进另一个表

### 7.1 一条语句插多行

一行一行插太慢。`VALUES` 后面可以接**多组括号**，中间用英文逗号隔开，一条语句插多行：

```sql
INSERT INTO 学生信息表 (学号, 姓名, 性别)
VALUES ('2025014', '赵晨', '女'),
       ('2025015', '孙浩', '男');
```

执行后「一行受影响」变成「两行受影响」，表里同时多出两条记录。格式还是那个格式，只是括号写了两次。

### 7.2 新表必须先建好（教材第 92 页）

接下来要讲的用法是：**把一张表里已有的数据，整批插到另一张表里**。老师翻了教材第 92 页的提示，说了两条前提：

| 前提 | 意思 |
|---|---|
| **目标表必须先建好** | `INSERT` 只负责往里放数据，不会替你建表。要往哪张表里搬，先把那张表建出来 |
| **列的顺序、数据类型必须对得上** | 搬过去的每一列，要和目标表的列一一对应；类型不一致，数据搬不过去 |

### 7.3 演示：建一张「通讯录」，把学生的学号姓名邮箱搬过去

**第一步：建表**。新建一张三列的表（先叫「信息表」，后来改名成「通讯录」）：

```sql
CREATE TABLE 通讯录
(
    学号 VARCHAR(20) NOT NULL PRIMARY KEY,
    姓名 VARCHAR(20) NOT NULL,
    邮箱 VARCHAR(50)
);
```

**第二步：搬数据**。用 `INSERT` 加一条 `SELECT`：

```sql
INSERT INTO 通讯录 (学号, 姓名, 邮箱)
SELECT 学号, 姓名, 邮箱
FROM 学生信息表;
```

**结果长什么样**：执行后刷新「通讯录」，学生信息表里的学号、姓名、邮箱被整列搬了过来，通讯录里出现了 3 行——**源表里有几条记录，这里就搬过来几行**，一行都不用自己写。

**为什么这么写**：

- `INSERT INTO 通讯录 (学号, 姓名, 邮箱)` 这一段和前面的插入一模一样，说的是「往哪张表的哪几列放」；
- 后面不是 `VALUES`，而是一条 `SELECT`——**查询出来的结果就是一批值**，直接喂给 `INSERT`；
- `SELECT` 里列的顺序要和 `INSERT` 后面列的顺序**严格一致**：学号对学号、姓名对姓名、邮箱对邮箱。顺序一换，姓名就跑到学号那一列去了。

> 💡 这条语句的结构可以记成：**`INSERT INTO 目标表 (列…) SELECT 列… FROM 源表;`** ——前半句管「放哪儿」，后半句管「从哪儿取」。

### 7.4 顺带一句：给列起别名

讲这段时老师提到了「别名」：查询时可以在列名后面用 `AS` 起个别名，结果集的列标题就跟着变。

```sql
SELECT 学号 AS SID, 姓名, 邮箱
FROM 学生信息表;
```

执行后结果集的第一列标题显示成 `SID`，数据本身不变。别名只是**给列换个显示的名字**，不影响表里的列。

### 7.5 `INSERT … SELECT` 与「多行 `VALUES`」的区别

| 用法 | 值从哪来 | 什么时候用 |
|---|---|---|
| `INSERT INTO 表 (列…) VALUES (…), (…)` | 自己一条条写出来的值 | 手工补几条记录 |
| `INSERT INTO 表 (列…) SELECT 列… FROM 源表` | 另一张表里查出来的数据 | 成批搬数据、给表留备份 |

## 八、课程信息表：字符加引号，数字不加

### 8.1 两行课程数据

最后拿**课程信息表**再走一遍同样的格式。这张表五列：课程编号、课程名称、开课学期、学时、学分。

```sql
INSERT INTO 课程信息表 (课程编号, 课程名称, 开课学期, 学时, 学分)
VALUES ('225', '程序设计', '第二学期', 60, 2);
```

这一段里最值得记的是**引号**：

| 列 | 类型 | 写法 |
|---|---|---|
| 课程编号 / 课程名称 / 开课学期 | 字符型 | 值必须加**单引号** |
| 学时 / 学分 | 数字型 | **不加引号**，直接写数字 |

老师用同样的语句接着插了第二门课，只改编号、学期、学时学分——**格式不变，换值重填**。这就是本节反复强调的那句话：`INSERT` 是一道填空题。

> ⚠️ **易错点**：字符列的值忘了加单引号，它会被当成列名或关键字，语句直接报错；数字列的值加了引号，等于把一个字符串交给数字列，多绕一道转换。老师的要求很干脆：**字符加引号，数字不加**。

### 8.2 本节停在哪里

本节的四件事只做完了第一件（插入），而且只做到「会用语句插、知道约束会拦」。**查询**只是被摆到了台面上：老师说它有「几种格式」，和插入一样是**填空**——表名填哪张、列填哪些、条件写什么，格式固定，往里填就行。

## 易错点清单

| # | 容易犯的错 | 正确做法 |
|---|---|---|
| 1 | 列的个数和值的个数不一致 | 写完数一遍：左边几列、右边几值，必须相等 |
| 2 | 日期写成 `2009年9月9日` 或漏单引号 | 写 `'2009-09-09'`，加单引号 |
| 3 | 用了中文逗号、中文括号 | 全部切到英文半角；报「语法错误」先看标点 |
| 4 | 只想跑一条语句，结果全被送出去 | 先**选中**要执行的那一段，再分析、执行 |
| 5 | 以为给了默认值的列也必须写 | 默认值列不给值时会自动填默认值 |
| 6 | 省掉列名段做部分列插入 | 省列名 = 按整表列顺序给全部列赋值；部分列必须写列名 |
| 7 | 把约束报错当成语句写错 | 看报错里有没有约束名、列名：有就是数据不合规矩 |
| 8 | 以为用语句能绕过约束 | 语句和界面守同一套约束，违反照拦 |
| 9 | `INSERT … SELECT` 里两边的列顺序写反 | 目标列与查询列**一一对应**，顺序不能换 |
| 10 | 往还不存在的表里搬数据 | 目标表先 `CREATE TABLE` 建好，再 `INSERT … SELECT` |
| 11 | 数字列习惯性加引号、字符列忘了加引号 | 字符日期加引号，数字不加 |
